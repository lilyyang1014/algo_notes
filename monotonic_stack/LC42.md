**①的根因**：while condition 只在**进入这一轮时**验过栈非空，`pop()` 把那个保证消耗掉了，`peek()` 是在一个已经变了的栈上调用的。栈空意味着 mid 左边没有更高的柱子，这一格接不住水。**更深一层：口述机制时我说 while「一直弹到当前元素不再比栈顶高」——只说了出口一，出口二（栈空）根本不在模型里**，所以 pop 之后自然想不到要再查一次。不是手滑，是模型少了一支。

**②的根因**：`height[left]` 是**绝对高度**（从地面量），`height[i] - height[mid]` 是**相对高度**（右墙高出凹槽底多少）。**两个参考系不同的量塞进同一个 min 里比大小，比出来的真假没有意义。** 正确顺序是先在绝对高度上取 min 选出较矮的墙，再统一减掉凹槽底。`[3,1,4]` → 我的写法 `min(3, 4-1) = 3`，正确 `min(3,4)-1 = 2`。**静默且极易蒙混**：两式只有 `height[mid] == 0` 时才相等，而 42 的样例里 0 特别多，前几个 case 很容易过。

> **自检信号**：一个表达式里出现减法和 min/max 时，先问「参与比较的两个量，是不是从同一个基准量起的」。基准不同就一定要先统一再比。

**自测点**：`pop()` 之后的新栈顶，凭什么一定是 mid 左边**第一个**比它高的柱子？（不是随便某个更高的柱子）

**归族**：「变量角色抓错名字」族，与 LC704 的 `nums[left]` 应为 `left` **互为镜像**（那次多套一层，这次少套一层）。

> **自检信号**：栈/队列里存 index 时，**凡是拿它参与数值比较的地方，都得先套一层原数组**。写完把所有出现 `peek()` / `pop()` 的行拉出来横着看一遍，问「这一行要的是位置，还是位置上的值」。

**当日口答（单调栈）**：「弹完之后的新栈顶凭什么是 mid 左边**第一个**比它高的柱子」——**两轮都停在「为什么它更高」这一层**（答「栈内有序」），接不上「第一个」。栈序只保证「留下来的都更高」；**「中间没留下的都更矮」要靠入栈出栈规则**：mid 与新栈顶之间那些 index 不在栈上，说明被更高的柱子弹掉了，顺着这条链收下去，执行者只能是 mid 自己。

**当日口答（双指针，同日补学）**：`preMax < sufMax` 时凭什么断定 `min` 就是 `preMax`——提示「未知区」之后接住了完整因果链。

**同日两处措辞已拧紧，是同一个动作的两次**：

- 「只有比栈顶小的时候才入栈」——`push(i)` 在 while **外面**，是**无条件入栈**（理由：任何柱子都可能是未来的左墙或凹槽底）。「push 时栈顶比它高」是 while 弹完之后的**结果**，不是入栈的**判据**

### 核心思路（一句话）

**第 i 列的水 = `min(它左边的最大高度, 它右边的最大高度) − height[i]`。** 三个解法都在算这同一件事，只是「怎么拿到那两个最大值」不同——数组存下来、两个 variable 边走边推、或者干脆换成横向分层。

### 解法一：前缀 / 后缀最大值数组（O(n) space，脚手架）

**把定义逐字翻译成代码，零推导。**

```java
class Solution {
    public int trap(int[] height) {
        int n = height.length;

        int[] preMax = new int[n];              // preMax[i] = height[0..i] 的最大值
        preMax[0] = height[0];
        for (int i = 1; i < n; i++) {
            preMax[i] = Math.max(preMax[i - 1], height[i]);
        }

        int[] sufMax = new int[n];              // sufMax[i] = height[i..n-1] 的最大值
        sufMax[n - 1] = height[n - 1];
        for (int i = n - 2; i >= 0; i--) {
            sufMax[i] = Math.max(sufMax[i + 1], height[i]);
        }

        int ans = 0;
        for (int i = 0; i < n; i++) {
            ans += Math.min(preMax[i], sufMax[i]) - height[i];
        }
        return ans;
    }
}
```

**两个数组都是闭区间、都包含 `height[i]` 自己**——所以当第 i 根是全场最高时，两个 max 都等于它，`min - height[i] = 0`。**这一版天然加不出负数，不需要任何特判。**

**Time O(n)**（三趟）/ **Space O(n)**（两个数组）。

### 解法二：双指针（O(1) space，最优解）

**同一个式子，把两个数组压成两个 variable。**

```java
class Solution {
    public int trap(int[] height) {
        int n = height.length;
        int ans = 0;
        int left = 0, right = n - 1;
        int preMax = 0, sufMax = 0;

        while (left <= right) {
            preMax = Math.max(preMax, height[left]);    // 结算之前先更新，保证减出来非负
            sufMax = Math.max(sufMax, height[right]);
            if (preMax < sufMax) {                      // 左边这堵墙更矮 → 左边这列能定死
                ans += preMax - height[left];
                left++;
            } else {
                ans += sufMax - height[right];
                right--;
            }
        }
        return ans;
    }
}
```

**Time O(n) / Space O(1)。面试首选。**

#### 为什么两个 variable 就够（这一层必须能讲出来）

手上的三段：

- `preMax` = `height[0..left]` 的最大值 —— 左侧已扫完，**真值**
- `sufMax` = `height[right..n-1]` 的最大值 —— 右侧已扫完，**真值**
- `(left, right)` 之间 —— **未知区**，谁都没扫过

`left` 这一列需要「右边的最大值」，而手上只有 `sufMax`，缺了未知区。但**不确定性只有一个方向**：

```
右边真正的最大值 = max(未知区, sufMax) ≥ sufMax
```

**只会更大，绝不会更小。** 所以当 `preMax < sufMax` 时：

```
preMax < sufMax ≤ 右边真正的最大值
⟹ min(preMax, 右边真正的最大值) = preMax
```

**未知区里长什么样，已经影响不到这一列的答案了** —— 当场结清，`left++`。`else` 完全对称。

> **一句话**：每轮只结算「墙更矮的那一侧」，因为**矮的那侧不确定性影响不到它**。挪走的正是刚刚结清的那一格，一路挑下来正好覆盖每一列。

#### 边界为什么是 `left <= right`

**判据是「相遇那一格算没算过」。** 本版每轮先更新两个 max、再结算、最后才挪指针，所以 `left == right` 那一轮**这一格还没被结算过，必须算**。

- `[4,2,0,3,2,5]`：相遇在 index 5，它自己是全场最高，`preMax` 被刷成 5，加 **0** —— 看起来像「多跑一轮无害」
- `[3,1,3]`：相遇在 index 1，`preMax = sufMax = 3`，加 **2** —— **这一格真的接了水，写 `<` 就漏了**

**别把「恰好加 0」当成通例。** 同理，「在端点所以加 0」也是错的说法——加 0 的真实条件是「这一格自己就是当前那堵矮墙」，`[1,5,1]` 的正中间照样加 0。

#### dry run：`[4,2,0,3,2,5]`（答案 9）

| 轮  | left | right | preMax | sufMax | preMax<sufMax? | 结算                 | ans   |
| --- | ---- | ----- | ------ | ------ | -------------- | -------------------- | ----- |
| 1   | 0    | 5     | **4**  | **5**  | ✓              | 4−4 = 0 → left=1     | 0     |
| 2   | 1    | 5     | 4      | 5      | ✓              | 4−2 = **2** → left=2 | 2     |
| 3   | 2    | 5     | 4      | 5      | ✓              | 4−0 = **4** → left=3 | 6     |
| 4   | 3    | 5     | 4      | 5      | ✓              | 4−3 = **1** → left=4 | 7     |
| 5   | 4    | 5     | 4      | 5      | ✓              | 4−2 = **2** → left=5 | 9     |
| 6   | 5    | 5     | **5**  | 5      | ✗              | 5−5 = 0 → right=4    | **9** |

**`right` 一次都没动**：右墙 5 是全场最高，所以整条路上水面恒为左墙 4，右边具体长什么样无关。

镜像的 `[4,2,0,3,2,0]`（答案 4）则是 **`left` 一次都没动**，`right` 从 5 一路收到 0，水面跟着 `sufMax` 走（index 3 那堵 3 决定了 index 1、2 的水面）。**两个例子合起来就是这个 `if` 的全部行为。**

### 解法三：单调栈（换坐标，横向分层）

```java
class Solution {
    public int trap(int[] height) {
        Deque<Integer> stack = new ArrayDeque<>();   // 存 index，栈底→栈顶高度递减
        int res = 0;

        for (int i = 0; i < height.length; i++) {
            while (!stack.isEmpty() && height[i] > height[stack.peek()]) {
                int mid = stack.pop();               // 凹槽底
                if (stack.isEmpty()) break;          // 左边没墙 → 接不住，这个 i 收工
                int left = stack.peek();             // 左墙（弹完之后的新栈顶）
                int h = Math.min(height[left], height[i]) - height[mid];
                int w = i - left - 1;                // 两墙之间的开区间
                res += h * w;
            }
            stack.push(i);                           // 无条件入栈：任何柱子都可能是
        }                                            // 未来的左墙或凹槽底
        return res;
    }
}
```

**Time O(n)**：每个 index 进栈恰好一次、出栈至多一次。**Space O(n)**：严格递减数组（如 `[5,4,3,2,1]`）时全部 index 压在栈上。

#### 一层水是怎么切的

**前两版按列结算，这一版按层结算**——这是它和前两版的根本区别：

- **前两版**：固定 index i，`min(preMax, sufMax) - height[i]` 求出**第 i 列**的水，宽度恒为 1，一列一次结清
- **单调栈**：每次 pop 结算一个**横向矩形**——从 `height[mid]` 这条水平线往上切一片，宽 `w = i - left - 1`（可能横跨好几列），高 `h = min(左墙, 右墙) - height[mid]`

`height = [4,2,0,3,2,5]`（答案 9），四次结算：

```
index:    0  1  2  3  4  5
height:   4  2  0  3  2  5

i=3 弹 mid=2: left=1, h=min(2,3)-0=2, w=1 → +2   底 0→面 2, 覆盖 index 2
i=3 弹 mid=1: left=0, h=min(4,3)-2=1, w=2 → +2   底 2→面 3, 覆盖 index 1~2
i=5 弹 mid=4: left=3, h=min(3,5)-2=1, w=1 → +1   底 2→面 3, 覆盖 index 4
i=5 弹 mid=3: left=0, h=min(4,5)-3=1, w=4 → +4   底 3→面 4, 覆盖 index 1~4
i=5 弹 mid=0: 栈空 → break
                                            res = 9
```

**index 2 那一列总共接了 4 格水，是在三个不同轮次里被算完的**（第 1 块拿 0→2 两格、第 2 块拿 2→3 一格、第 4 块拿 3→4 一格）。**同一个输入，双指针版第 3 轮一次就把这 4 格结清了**——两个坐标的差别一眼可见。

**这也解释了为什么 42 不需要首尾补 0**（84 需要）：遍历完栈里剩的柱子都没找到右墙，它们头顶那些层压根不存在水，直接丢掉就对。84 剩的柱子面积还没算，必须靠末尾的 0 强制弹出。

### 三版对比

|               | Time | Space    | 讲清正确性要几步推导                |
| ------------- | ---- | -------- | ----------------------------------- |
| 前缀/后缀数组 | O(n) | O(n)     | **0 步**，定义即代码                |
| 双指针        | O(n) | **O(1)** | 1 步（未知区只会把对面的 max 变大） |
| 单调栈        | O(n) | O(n)     | 换坐标，最难讲                      |

对比 brute force O(n²)（每一列各向左右扫一遍求两个 max）：三版都把「找左右边界」摊进了常数趟遍历。

**面试按「数组版 → 双指针」的顺序讲**：数组版先把「为什么是 min 减自己」说穿，正确性已经落地；再说「这两个数组可以降成两个 variable」上双指针。**数组版是双指针的脚手架，不是竞争关系**——直接甩双指针，容易被追问未知区那一步接不上。单调栈作为另一个角度值得会，但不占优。

### 沉淀

- **两个各自成立的陈述，不等于它们之间存在因果**。一刷时我说「等高还是入栈，因为等高接不到水」——两句都对，但接不到水**不是**入栈的理由（比栈顶矮的柱子这轮同样接不到水，入栈理由却完全不同）。**②是同一个动作的另一次发作**——两个各自有意义的量，被放进一个并不成立的比较关系里
- **栈里存的是 index，那就自始至终是 index**。要值就套 `height[...]`，要位置就直接用。**condition 那一行最容易漏**，因为它离 `pop()` 最远、且漏了也不报错（二刷）
- **可推论的结果不要说成入口条件**，**条件最常出现的场景也不是条件本身**（二刷同日两次：「比栈顶小才入栈」、「在端点所以加 0」）。判据要落在量的关系上，不落在位置上
- **min / max 遇上减法，先统一基准再比**（见上方自检信号）
- **while condition 有几个操作数，就有几个出口**。`pop()` 之后要重新验一遍被消耗掉的那个前提
- **一次结算三个角色，「弹出的」和「左墙」是两根不同的柱子**：`mid = pop()` 是凹槽底（水面之下），`left = peek()` 是弹完之后的新栈顶
- **循环边界 `<` 还是 `<=`，判据永远是「最后那一格算没算过」**，不是背模板。跟推进方式配套，**不能从别的题抄一半过来**（同 LC45 换收尾写法的老毛病）
- **收尾写法定一版就别再改**：`if (stack.isEmpty()) break;` 与把结算整个包进 `if (!stack.isEmpty()) { ... }` 完全等价（后者的退出由 while condition 的 `!isEmpty()` 接走）。break 版把「栈空就没戏了」写死在出错那一行旁边，读代码不用回头看 while 头，选它。**不要发明第三种**

### 引申：单调栈的 condition 写 `>` 还是 `>=`

**都对**，因为两根等高的柱子之间夹不住水——水面高度就是它们自己的高度，`h` 恒为 0。区别只在什么时候算这个 0：`>` 版等高不弹、留到后面某一轮；`>=` 版当场弹出、白算一轮 `h = 0`。

**推荐 `>`**：少跑一轮无效结算，且栈内维持「非严格递减」，等高的柱子全部保留、每根都有机会当左墙。

**`>=` 有个隐藏耦合**：它让栈空这条路径触发得频繁得多（`[1,1]` 在 `>` 版下一次都不弹，`>=` 版 i=1 就把栈弹空）。**缺 ① 那个 guard 时，`>=` 版会在更小更常见的输入上炸。**

**84 的同一选择性质不同**：那题等高弹出会算出偏窄的矩形，但同高柱子里最后一根会把完整宽度补回来，结果仍对。42 是「贡献恒为 0」，84 是「先算窄的、后面补回来」，两题别混着记。

### Interview pitch (练口述)

> "The water above column i is min of the max height to its left and to its right, minus its own height. The brute force scans both sides for every column — O(n²). The clean fix is to precompute two arrays, a prefix max and a suffix max, then sum the formula in one pass: O(n) time, O(n) space. From there I can drop to O(1) space with two pointers. I keep a running prefix max from the left and suffix max from the right. The key observation is that the unscanned middle can only make the opposite side's max larger, never smaller — so whichever running max is currently smaller is already the true min for that column, and I can settle it and advance that pointer. The monotonic stack is a different angle entirely: instead of summing column by column, it settles water in horizontal layers. I keep a stack of indices with decreasing heights; when the current bar is taller than the stack top, I've found a right wall, pop the top as the valley floor, and the new stack top is the left wall. Two edge cases there: after popping, the stack may be empty, meaning no left wall and no water; and each index is pushed once and popped at most once, so it stays O(n)."
