## 13. Roman to Integer

Date: 8/31/2026, 9/2/2026, 9/16/2026
Difficulty: Easy
Tags: Hash Table, String, Math

![Scanning "MCMXCIV" left to right: each numeral is compared with its right neighbour and subtracted when smaller, added otherwise](assets/13.png)

> **固定写法**：`Map<Character, Integer>` 存七个单字符；每轮只结算当前字符，比右邻小就减，否则就加。

### 一刷 (8/31/2026) ❌ 三套方案各写一半

减法规则、六对组合和 map 中的值都知道，但双字符查表、手写 if-chain、逐字符累加拼在一起，互相抵消。

```java
Map<String, Integer> map = new HashMap<>();      // map 含 IV/IX/.../CM 六个双字符 key
map.put("I", 1); ... map.put("M", 1000);

int ans = -1;                                   // ❌④ 应为 0；i 从 1 起还漏掉首字符
for (int i = 1; i < s.length(); i++) {
    if (s.charAt(i) == "V" && s.charAt(i-1) == "I") {
        // ❌① char 与 String 不能这样比较，compile error
        ans = 4;                                // ❌⑤ 覆盖已有结果，后续还会重复加
    } else if (... 手写六对减法规则 ...) {
        ans = 1000;                             // ❌⑥ CM 应为 900，与 map 中的值不一致
    }
    if (maps.containsKey(s.charAt(i))) {         // ❌② maps 未定义
        ans = ans + map.get(s.charAt(i));        // ❌❌③ char 查 String key，分支恒不进入
    }
}
```

**③的根因**：`char` autobox 成 `Character`，不等于任何 String key → `containsKey` 恒 false，累加一次都不执行。

**三套方案拼接**：if-chain 覆盖 ans，逐字符累加又算一次，双字符 map 则没被正确使用。同 LC34：两套各自成立的方案拼在一起，整体不成立。

> **自检信号**：同一个信息存了两遍就停下检查。本题 CM 在 map 里是 900、if-chain 里是 1000，冗余已经产生冲突。

### 二刷 (9/2/2026) ❌❌ key 类型错复发；双字符结算与 for 步长冲突

```java
Map<String, Integer> map = new HashMap<>();       // ❌❌① key 仍是 String
...
int cur = map.get(s.charAt(i));                  // char 查 String key → null → 拆箱 NPE
for (int i = 0; i < s.length(); i++) {
    if (s.charAt(i+1) < s.length && ...) {        // ❌② length() 少括号
                                                 // ❌③ 应判 index；这里先取值，末位越界
        ans += map.get(s.charAt(i+1)) - cur;
        i += 2;                                  // ❌④ 与 for 的 i++ 叠加，一轮前进三格
    } else if (... && cur > map.get(s.charAt(i+1))) {
        ans += cur;                              // ❌⑤ 漏掉 == 和最后一格
    }
}
// ❌⑥ 原稿括号不配对，return ans 掉到 class 层
```

**①的根因**：与一刷同一个 key 类型错；这次 `get` 返回 null 后拆箱 NPE。一刷静默、二刷崩溃，只是调用的方法不同。

**③的根因**：guard 应先判断 `i + 1 < s.length()`，再读取右邻；不能先调用 `charAt(i+1)`，再检查是否越界。

**④⑤的根因**：`next - cur` 一次结算两格，却没有对应的前进方式；`else if (cur > next)` 又把相等和末位排除，造成静默漏加。

**修订时只改了一半**：if 的 guard 和 `ans -= cur` 已改对，else-if 仍保留旧 condition。同 LC380：对称操作只补了一半。

> **自检信号**：改完一支分支，再检查另一支是否仍与当前方案一致。

**自测点**：如果输入是 `IC`（有人拿它表示 99），代码会算出什么？为什么本题可以不处理这种输入？

### 三刷 (9/16/2026) ❌ key 类型未对应；ans 提前结算右邻，下一轮重复加

这次 guard、`s.length()`、else 和固定 `i++` 都写对了，剩下两处：

```java
Map<Integer, Integer> map = new HashMap<>();      // ❌① key 应为 Character
map.put('I', 1);                                 // char autobox 成 Character，不能传给 Integer key
...                                             // 其余六个字符同样如此

int ans = 0;
for (int i = 0; i < s.length(); i++) {
    if (i + 1 < s.length()
            && map.get(s.charAt(i)) < map.get(s.charAt(i + 1))) {
        ans += map.get(s.charAt(i + 1)) - map.get(s.charAt(i));
        // ❌❌② condition 正确，update 错：一次结算两格，下一轮却只前进一格
    } else {
        ans += map.get(s.charAt(i));
    }
}
```

**①的根因**：知道单引号是 char，但 map 的 key 没对应上。`char` autobox 成 `Character`，这里在 `put` 时就会出现 compile error。

**②的根因**：`next - cur` 已把右邻加进 ans，for 下一轮又处理右邻 → 重复计数。**比较右邻只为决定当前字符的正负，不代表这一轮要结算右邻。**

**Dry run（先修好 key 类型）**：`"IV"` → i=0 加 `5-1=4` → i=1 再加 `5` → 返回 `9`，应为 `4`。不会崩溃，是静默错误。

> **自检信号**：检查 ans 的 update 究竟结算几格，再对照 pointer 前进几格。每轮只前进一格，就只结算当前字符。

**自测点**：为什么最后一个字符可以直接加，不需要再检查它的左邻？口答待测。

### 核心思路（一句话）

**合法罗马数字中，当前值比右邻小就减当前值，否则加当前值；每轮只结算一个字符。**

### 正确写法

```java
class Solution {
    public int romanToInt(String s) {
        Map<Character, Integer> map = new HashMap<>();
        map.put('I', 1);
        map.put('V', 5);
        map.put('X', 10);
        map.put('L', 50);
        map.put('C', 100);
        map.put('D', 500);
        map.put('M', 1000);

        int ans = 0;
        for (int i = 0; i < s.length(); i++) {
            int cur = map.get(s.charAt(i));
            if (i + 1 < s.length()
                    && cur < map.get(s.charAt(i + 1))) {
                ans -= cur;  // 只结算当前字符，右邻留给下一轮
            } else {
                ans += cur;  // 相等和最后一格也归这一支
            }
        }
        return ans;
    }
}
```

### 复杂度分析

**Time: O(n)**：遍历 n 个字符，每轮固定次数的 map 查询。
**Space: O(1)**：map 固定七个 entry。

### 沉淀

- **每轮结算范围要与 pointer 的前进方式一致**：`next - cur` 结算两格，`i++` 只前进一格，会重复处理。固定逐字符方案，就只对 cur 做加减。
- **key 类型要贯穿声明、put、get**：`char → Character`。`put(K, V)` 有类型检查；`get` / `containsKey` / `remove` 接收 Object，传错类型可能编译通过，却查不到。
- **guard 先判 index，再取值**：靠 `&&` 的短路避免访问不存在的右邻；else 接住相等和末位，不能随意加 condition。
- **方案改完要检查整条路径**：从查表、ans update 到 pointer 前进保持一致，避免保留旧方案的一半。
