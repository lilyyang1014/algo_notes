### 一刷 (9/18/2026) ❌ 起点判断混淆 index 与数值，重复展开导致 TLE

**卡在哪**：能建立 HashSet，但不知道找到起点后怎么继续；看解后重写，修正遍历对象后通过。

```java
if (!set.contains(nums[i - 1])) {
    // ❌① 查的是前一个 index 的值；i = 0 时还会越界
}
```

**①的根因**：连续指的是数值相邻，不是原 array 中的位置相邻。应查 `nums[i] - 1`，判断当前数值有没有 predecessor。

修正后仍有问题：

```java
for (int i = 0; i < nums.length; i++) { // ❌② nums 中仍有 duplicates
    if (!set.contains(nums[i] - 1)) {
        int cur = nums[i];
        int length = 1;

        while (set.contains(cur + 1)) {
            cur++;
            length++;
        }

        ans = Math.max(ans, length);
    }
}
```

**②的根因**：set 去重了，但遍历对象 nums 没去重。重复的起点会反复扫描同一段，time 最坏退化为 O(n²)。

例如 `[1,1,1,2,3,4]`，每遇到一个 1，都会重新数到 4。第二个 loop 应遍历 set。

**自测点（当时）**：为什么只从没有 predecessor 的数开始，就不会漏掉最长 sequence？为什么外层 for 加内层 while，expected time 仍是 O(n)？

### 三刷 (10/10/2026) ❌ 起点判断写对，但 while 的 condition 没有推进

已写出 `!set.contains(nums[i] - 1)`，但把一次判断写成了 while：

```java
for (int i = 0; i < nums.length; i++) { // ❌① 仍应遍历 set，避免重复起点
    while (!set.contains(nums[i] - 1)) {
        length = 1; // ❌❌② 只改 length，condition 不变，遇到起点就 infinite loop
    }

    while (set.contains(nums[i] + 1)) {
        length++; // ❌③ 一直检查同一个数，没有 cur++ 推进
        ans = Math.max(ans, length);
        // ❌④ 更新放在 while 内，会漏掉 length 为 1 的 sequence
    }
}
```

**根因**：while 每轮重新检查 condition，但不会自动改变 variable。只修改 length，不会改变 nums[i] 或 set；卡在内层 while 时，也走不到外层的 i++。例如当前数为 1、set 没有 0，第一个 while 会一直重复“没有 0 → length = 1”。

讲解后能区分：enhanced for 依次取出每个 value；if 判断一次是否为起点；while 用 cur++ 检查下一个连续数字。能说明 predecessor 存在时跳过整个 if，由外层 for 取下一个 num。尚未展示修正后的独立代码。

> **自检信号**：写完 while，指出 body 中哪一行会改变下一次 condition 检查的内容；区分 cur“走到哪个数”和 length“数了几个数”。

**自测点**：同事把 ans 的更新放进计数 while，代码能正确处理 `[8]` 吗？说明执行过程。

### 核心思路（一句话）

**用 HashSet 去重；只有 num - 1 不存在时，才从 num 开始向右计数，最后取最大 length。**

### 正确写法

```java
class Solution {
    public int longestConsecutive(int[] nums) {
        Set<Integer> set = new HashSet<>();

        for (int num : nums) {
            set.add(num);
        }

        int ans = 0;

        for (int num : set) {
            if (!set.contains(num - 1)) {
                int cur = num;
                int length = 1; // 起点自己也算一个

                while (set.contains(cur + 1)) {
                    cur++;
                    length++;
                }

                ans = Math.max(ans, length);
            }
        }

        return ans;
    }
}
```

空 array 会自然返回 0。

### 为什么只从起点开始

每段 consecutive sequence 都有一个最小值，它没有 predecessor。从它开始查 `cur + 1`，就能找到整段；其他数不必重复扫描。

**起点是这一段的最小值，不一定是整个 array 的最小值。**

例如 `[100,4,200,1,3,2]`：

- 100 没有 predecessor 99，是起点，length 为 1。
- 200 同理，length 为 1。
- 1 没有 predecessor 0，向右找到 `1 → 2 → 3 → 4`，length 为 4。
- 2、3、4 都有 predecessor，不启动扫描。

HashSet 不保证遍历顺序，但不影响结果。即使先遇到 4，之后遇到 1 时仍能找到整段。

### For / if / while 的分工

- **Enhanced for**：每个 distinct value 都取出来看一次，不需要 index。
- **If**：对当前 num 判断一次，决定是否开始计数。
- **While**：只要下一个连续数字存在，就继续推进。

```text
对每个数，检查一次。
如果它是起点，就开始计数。
只要下一个数存在，就继续往后走。
```

**外层取下一个 element，由 for 负责；内层查下一个连续数字，由 cur++ 负责。**

Cur 和 length 的职责不同：

```text
cur    = 目前数到哪个数字
length = 到目前为止数了几个数字
```

只有 length++，不会让下一轮检查的数字发生变化。

### HashSet API 与 enhanced for

```java
Set<Integer> set = new HashSet<>();

set.add(3);       // 新增返回 true；已存在返回 false
set.contains(3);  // 存在返回 true，否则 false
set.remove(3);    // 删除成功返回 true；不存在返回 false
set.size();       // 返回 distinct elements 的数量
set.isEmpty();    // 为空返回 true
```

**Set 查 value 用 contains(value)；Map 查 key 用 containsKey(key)。**

HashSet 没有 index，也没有 get(i)。enhanced for 直接取出 element：

```java
for (int num : set) {
    // num 是本轮取出的 value，不是 index
}
```

**去重来自 HashSet，不来自 enhanced for。**

- `for (int num : nums)`：遍历原 array，仍会遇到 duplicates。
- `for (int num : set)`：每个 distinct value 只遍历一次。

### 复杂度分析

设 n = nums.length，m = number of distinct elements，m ≤ n。HashSet 的 add / contains 按 average O(1) 计。

| 遍历对象 | Time（包含建 set）                              | Extra space     |
| -------- | ----------------------------------------------- | --------------- |
| set      | expected O(n)                                   | O(m)，最坏 O(n) |
| array    | 最坏 O(n²)，即使 HashSet 操作按 average O(1) 计 | O(m)，最坏 O(n) |

**遍历 set：** 建 set 为 O(n)；外层检查 m 个 distinct values，内层只从起点扫描，各段互不重叠，总扫描量为 O(m)。因此总 time 为 O(n + m) = O(n)。

**遍历 array：** 重复的起点会反复扫描同一段。如果约 n/2 个 elements 都是 1，且连续 sequence 长度约为 n/2，就需要约 n/2 × n/2 次操作，退化为 O(n²)。没有 duplicates 时，expected time 也是 O(n)。

**两种写法都建立相同的 set，所以 extra space 相同。** cur、length、ans 只占 O(1)。

不能只看到 nested loops 就判 O(n²)，要看内层的总执行次数。

### 沉淀

- **数值相邻 ≠ index 相邻。** `nums[i] - 1` 查 predecessor，`nums[i - 1]` 取前一个位置。
- **去重后，检查实际遍历的是谁。** 遍历 set 避免重复起点；检查 predecessor 避免从中间重新扫描。
- **While 不会自动推进。** Body 必须改变与 condition 有关的状态，或通过 break 等方式退出。
- **判断一次用 if，连续计数用 while。** 先确认当前数是起点，再开始扫描。
- **Cur、length、ans 分工明确。** 当前数字、当前长度、最大长度不能混用；扫描结束后统一更新 ans，包含 length 为 1 的情况。

> "I put the numbers into a HashSet to remove duplicates and support fast lookups. I only expand from numbers whose predecessor is absent, so each consecutive sequence is counted once.
