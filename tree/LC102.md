### 二刷 (10/10/2026) ❌ 两侧推进放在 branches 外，跳过未检查的组合

已写出 sorting、固定 i、外层去重和 Arrays.asList。错误集中在内层 pointer update：

```java
if (sum == 0) {
    ans.add(Arrays.asList(nums[i], nums[left], nums[right]));
} else if (sum < 0) {
    left++;
} else {
    right--;
}

// ❌ 核心错误：无论进入哪个 branch，都会继续执行两侧推进
left++;
while (left < right && nums[left] == nums[left - 1]) left++;

right--;
while (left < right && nums[right] == nums[right + 1]) right--;
```

**根因**：sum < 0 / sum > 0 时，已经移动对应的一侧；退出 branch 后又无条件移动两侧，会跳过尚未检查的组合。例如 `[-3,0,1,2]`，sum = -1，left 从 0 移到 1 后又被推进，漏掉 `[-3,1,2]`。

> **自检信号**：分别走一遍 sum 小于、大于、等于 0 的路径；每个 branch 完成自己的 pointer update 后，应回到下一轮重新计算 sum。

**讲解后**：理解了 sum 不为 0 时，跳过重复 values 只是减少计算；sum 为 0 后去重，是为了避免重复加入答案。能主动解释：nums[i] > 0 时后面全部不可能有答案，用 break；固定值重复只跳过当前轮，用 continue。尚未展示修正后的独立代码。

**自测点**：找到一个 triplet 后，为什么可以同时放弃当前 left 和 right 的 values，不会漏掉新的 value 组合？

### 核心思路（一句话）

**Sorting 后固定一个数，在它右侧用 two pointers 找另外两个数，并跳过重复的 value 组合。**

```text
nums[i] + nums[left] + nums[right] = 0

固定 nums[i] 后：
nums[left] + nums[right] = -nums[i]
```

### 正确写法

```java
class Solution {
    public List<List<Integer>> threeSum(int[] nums) {
        Arrays.sort(nums);
        List<List<Integer>> ans = new ArrayList<>();

        for (int i = 0; i < nums.length - 2; i++) {
            if (nums[i] > 0) {
                break;
            }

            if (i > 0 && nums[i] == nums[i - 1]) {
                continue;
            }

            int left = i + 1;
            int right = nums.length - 1;

            while (left < right) {
                int sum = nums[i] + nums[left] + nums[right];

                if (sum < 0) {
                    left++;
                } else if (sum > 0) {
                    right--;
                } else {
                    ans.add(Arrays.asList(
                        nums[i], nums[left], nums[right]
                    ));

                    left++;
                    while (left < right
                            && nums[left] == nums[left - 1]) {
                        left++;
                    }

                    right--;
                    while (left < right
                            && nums[right] == nums[right + 1]) {
                        right--;
                    }
                }
            }
        }

        return ans;
    }
}
```

### 三个 branches 怎么推进

| Condition | 动作                 | 依据                                             |
| --------- | -------------------- | ------------------------------------------------ |
| sum < 0   | left++               | 当前 left 配最大的可用 value 仍不够，排除 left   |
| sum > 0   | right--              | 当前 right 配最小的可用 value 仍太大，排除 right |
| sum == 0  | 记录，两侧移动并去重 | 当前两个 values 的配对已经记录                   |

**各自推进后，回到下一轮重新计算 sum。不要在 branches 外再无条件移动两侧。**

### 为什么找到答案后可以两侧都移动

例如固定 -3，找到：

```text
-3 + 1 + 2 = 0
```

- 保留 1，只能再配 2；相同 value 来自其他 index，仍是重复答案。
- 保留 2，只能再配 1；同样不会产生新答案。

因此当前两个 values 都可以跳过，继续寻找新的组合。

### 为什么在找到答案后去重

**Sum 不为 0 时也可以跳过重复 values，但不是必须。**

例如固定 -5、right 是 3，left 连续遇到三个 1，每次 sum 都为 -1。不专门去重，也会通过下一轮的 left++ 逐个走过去，不会加入错误答案。

| 情况              | 去重的作用                       |
| ----------------- | -------------------------------- |
| sum < 0 / sum > 0 | 减少重复计算，不影响答案是否重复 |
| sum == 0          | 避免再次加入同一个 triplet       |

本写法在找到答案后统一去重。并不是“去重只能写在这里”，而是“两侧都推进”的动作只能在对应条件下执行。

### Boundary 与 break / continue

- `i < nums.length - 2`：右侧至少留下两个位置。
- `left = i + 1`：不重复使用 i。
- `left < right`：另外两个 indices 也不同。

```java
if (nums[i] > 0) break;
```

Array 已 sorted，后面的数也大于 0，剩余部分全部不可能有答案。break 跳出外层 for，随后执行 return ans。

不能写成 `>= 0`，因为 `[0,0,0]` 是合法答案。

```java
if (i > 0 && nums[i] == nums[i - 1]) continue;
```

当前固定值已处理过，但后面不同的 values 仍可能有答案，所以只跳过当前 iteration。

### Duplicate triplets 怎么定义

**按 values 判断，不按 indices 判断；顺序不同也算重复。**

```text
[-1,0,1] 和 [-1,1,0] → 同一个 triplet
```

例如：

```text
nums = [-1,-1,0,1]

indices (0,2,3) → [-1,0,1]
indices (1,2,3) → [-1,0,1]
```

只能返回一次。

一个 triplet 内可以包含相同 values：

```text
[-1,-1,2] // 合法，两个 -1 来自不同 indices
```

因此不能先把 input 全部去重，否则会丢掉这种答案。

### 为什么外层用 continue，内层用 ++ / --

外层 for 的 update statement 是 i++。执行 continue 后，仍会执行它，再进入下一轮。

内层 while 不会自动移动 pointer，必须显式执行 left++ / right--。如果只写 continue，condition 不变，就会 infinite loop。

**Continue 只跳过本轮剩余代码，不负责改变 pointer。**

### 为什么比较 left - 1 和 right + 1

找到答案后先移动 pointer：

- left++ 后，left - 1 指向刚用过的 value。
- right-- 后，right + 1 指向刚用过的 value。

再比较相邻 values，跳过重复。连续跳过时，相邻的重复值仍相等。

### Arrays.asList()

```java
ans.add(Arrays.asList(nums[i], nums[left], nums[right]));
```

把三个 values 组成一个 List<Integer>，再加入外层 ans。

```text
as List = 组成 List
```

内层 List 是 fixed-size，可以 set，不能 add / remove 改变 size。外层 ans 是 ArrayList，可以继续加入 triplets。

### 复杂度分析

设 n = nums.length，k = 返回的 triplets 数量。

**Time: O(n²)**：

- Sorting 为 O(n log n)。
- 每换一个 i，left / right 都重新初始化，再扫描右侧。
- 各轮最多移动的次数合计：

```text
(n−2) + (n−3) + … + 1 = O(n²)
```

因此：

```text
O(n log n) + O(n²) = O(n²)
```

去重和提前 break 不改变最坏复杂度。

**Extra space**：

- Two pointers 搜索本身：O(1)，不含 sorting 和返回结果。
- Sorting 的额外开销取决于 Java Arrays.sort 的具体实现。
- 返回结果：O(k)，最坏 O(n²)。

### 沉淀

- **三个数拆成固定一个，再找两个。**
- **每个 branch 负责自己的 pointer update。** 不要在外面再统一推进。
- **区分重复计算与重复答案。** 前者可以不优化，后者必须避免。
- **Break 排除剩余全部可能，continue 只跳过当前轮。**
- **相同 values 可以出现在一个答案中，相同 triplet 不能重复返回。**

### Interview pitch

> "First, I sort the array. Then I fix one number and use two pointers to find two numbers to its right whose sum equals the negative of the fixed number.
>
> If the total is too small, I move left forward. If it is too large, I move right backward. When I find a triplet, I record it, move both pointers inward, and skip duplicate values.
>
> I also skip duplicate values for the fixed number, so each unique triplet is returned once. The overall time complexity is O(n²)."
