**真正的坎**：缺的不是「想到 greedy」，是它的两条正确性依据（有解的判据 + 为什么整段候选能一次跳过）。**看题解觉得容易 = recognition，和能重建出来是两回事**——证据是读完后的自述有两处和代码对不上：

**①②是一对**：都是「这个量此刻代表什么 / 边界落在哪一格」。

### 三刷 (8/21/2026) ❌ 三处错，思路在但没落地

```java
for (int i = 0; i < gas.length - 1; i++) {   // ❌③ 上界少一格，最后一站被跳过
    cur = gas[i] - cost[i];                  // ❌❌① 应为 cur += ，覆盖掉了累计
    total += gas[i] - cost[i];               //     ✅ total 这行是对的
    if (cur < 0) {
        start++;                             // ❌② 应为 start = i + 1
        cur = 0;
    }
}
```

**①（核心）**：`cur` 模拟的是**油箱**，油箱本来就有存量，必须累加。写成 `=` 之后 `cur` 只反映单站盈亏，于是 `cur < 0` 判的变成「这一站自己亏」而不是「从 start 走到这撑不住了」——**判断的含义整个变了**，`start` 的更新也就失去了依据。单站盈亏根本不是判据：`gas=[1,2,3,4,5], cost=[3,4,5,1,2]` 里自身不亏的是 3 和 4 两站，正确起点却只有 3。

**②（我自己定位的）**：把数组理解成一个区间——**前面这一段累加的油箱为负了，start 要从 `i+1` 开始算，不能 `++`**。`start++` 是把「第几格」当成「失败了几次」在数，而且丢掉了整段跳过这条剪枝，退化成 O(n²)。

**③**：绕圈问题每一站都要算，没有「最后一站不用管」。`total` 少加一项、`cur` 少走一段。

**①②是连着的**：`cur` 一退化成单站值，重置逻辑就没了依据，`start++` 顺理成章地被写出来。

### 四刷 (8/24/2026) ⚠️卡推导 代码一次 AC，`total ≥ 0` 与「start 就是解」没分开

代码一次写对，三刷三个错全未再犯（`cur +=`、`start = i + 1`、上界 `gas.length`）。

**自测点**：一趟从左到右的线性 scan 为什么等价于绕圈？`start` 之后那段从没验证过能不能绕回开头，凭什么直接 return `start`？

**答成**「算了 total，`total > 0` 就走得过去」——只答到「**存在**某个起点可行」，没接上「那个起点就是 `start`」。收窄到「用 `total` 和 A 段余量把 B 段中途余量表示出来」后答不出 → 因果链没建立，非手生。

**这就是二刷那两条依据里的第一条**，三轮未补上：二刷是复述时把 `totalSum` 的角色说错，本轮是说不出它保证了什么。

> **自检信号**：一个量能回答「有没有解」，不代表它能回答「解在哪」。看到某个判据被拿来支撑结论时，问一句「它管的是存在性还是构造」。

### 核心思路（一句话）

**`totalSum >= 0` 决定「有没有解」，`curSum` 转负的位置决定「解在哪」——一趟 scan 同时算这两件事。**

### 代码

```java
public int canCompleteCircuit(int[] gas, int[] cost) {
    int curSum = 0;      // 从 start 到 i 这一段的净油量（有存量，必须累加）
    int totalSum = 0;    // 全程净油量，判可行性，全程不清零
    int start = 0;
    for (int i = 0; i < gas.length; i++) {
        curSum += gas[i] - cost[i];
        totalSum += gas[i] - cost[i];
        if (curSum < 0) {
            start = i + 1;   // [start, i] 整段作废，i+1 尚未检验
            curSum = 0;      // 只清 curSum
        }
    }
    if (totalSum < 0) return -1;   // == 0 有解，不能写 <= 0
    return start;
}
```

### 推导一：为什么整段 `[start, i]` 可以一次跳过

设 `curSum` 在 `i` 处首次转负，取段内任意 `j`：

从 start 出发能走到 j（是走到 i 才断的），说明**开到 j 时油箱里还有富余**。那从 j 自己出发呢？它起步是 0，比「从 start 开过来的那个自己」**少了那份富余**。带着富余的版本走到 i 都断了，油更少的版本只会**更早断**。

所以段内每一格做起点都必定失败 → 整段一次排除，`start` 直接跳到 `i+1`。这就是 O(n²) 压成 O(n) 的地方。

### 推导二：为什么不用验证 `start` 之后能绕回开头（四刷卡在这）

按 `start` 把整圈切两段：**A = start → 末尾**，余量 `cur`（循环结束时手上那个）；**B = 开头 → start-1**，余量 `rest`。于是 `totalSum = cur + rest`。

从 `start` 出发实际是先走 A 再走 B：

1. **A 段安全**：全程 `curSum` 没再转负（否则 start 早被挪走），走完手上有 `cur ≥ 0`。
2. **B 段填得平**：进 B 段时已有 `cur` 打底，`totalSum ≥ 0` 即 `cur + rest ≥ 0`，A 段富余够填 B 段亏空。
3. **中途也不会断**：走到 B 段任意 j，手上是 `cur + (开头到 j 的余量)`。而「开头到 j 的余量」`≥ rest`——j 之后到 `start-1` 那截正是被判负、挪掉起点的部分，只会让余量更低。所以中途 `≥ cur + rest = totalSum ≥ 0`。

> 直觉：**富余是先拿到的，亏空是后遇到的**。`totalSum ≥ 0` 说明富余够填亏空，顺序又保证填在亏之前，所以中途不会断油。

`totalSum` 已经替你验证了 B 段——这就是一趟 scan 等价于绕圈的全部理由。

### 复杂度分析

**Time: O(n)**：单趟 scan，`start` 单调右移不回退。
**Space: O(1)**：三个 int。

对比 brute force O(n²)（枚举每个起点各模拟一圈）：省在「一整段候选一次排除」，不是逐个起点重试。

### 沉淀

- **`=` 还是 `+=`，先问「这个量有没有存量」**。凡是「前缀和跌破 0 就重开」的形态（134、53），那个变量都在模拟一个会攒的东西，必然累加。三刷栽在这。
- **一个量管存在性、另一个管构造，别互相顶替**：`totalSum` 答「有没有」、`curSum` 答「在哪」，只有后者随起点重置。全局量出现在重置语句里就是坏味道；拿全局量去论证局部结论（四刷）同样是坏味道。
- **`start` 是「第几格」不是「第几次」**：它该被赋值成一个位置（`i + 1`），不该被 `++`。同族：189 的 `n-k`、45 的 `i == count`、367 的 `left`/`left²`。
- **可行性判据的等号方向单独想一遍**：`totalSum == 0` 是「恰好开完」不是「差一点」。凡「总量够不够」型判断，先问 0 归哪边。
- **greedy 跳跃型的通用形态**：证明「区间内每点都不优于端点」→ 整段跳过 → O(n²) 压成 O(n)。134 和 45 共用这个骨架。

### Interview pitch (练口述)

> "Brute force would try every station as a start and simulate a full loop — O(n²). The key insight is that two separate questions can be answered in one pass. First, feasibility: if total gas minus total cost is negative, no start works, since any full loop consumes that same total — and exactly zero is still feasible. Second, locating the start: I track a running sum from the current candidate. The moment it goes negative at index i, no station in that whole segment can work — any later station j in it starts without the surplus it would have had arriving from start, so it'd reach i with even less gas. I jump start to i plus one and reset only the running sum, never the total. And I don't need to verify the wrap-around: the segment from start to the end ends with a non-negative surplus, the remaining prefix is covered because total is non-negative, and the surplus is collected before the deficit is hit. One pass, O(n) time, O(1) space."
