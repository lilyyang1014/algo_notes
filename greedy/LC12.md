### 一刷 (8/31/2026) ❌ 没思路：把 13 的解法搬了过来，两题不是镜像

**卡在哪**：先把 `3749` 拆成 `[3,7,4,9]`，然后不知道拿这个数组干什么。

**真正的坎**：**digits 一拆开就丢了位权，查不了表**——那个 3 代表的是 3000，而罗马数字里根本没有「3」这个符号。13 里每个字符的值是固定的（`X` 在哪儿都是 10），拆开逐位处理成立；12 里每一位的值取决于它站在哪一位，拆开就死了。

**要看清的一句话**：那十三个值（1000/900/500/400/100/90/50/40/10/9/5/4/1）就是罗马数字的**全部合法零件**，任何罗马数字都是它们从大到小拼起来的。看清这句，题目就变成「用给定面额凑金额」——找零钱问题。

**与 13 的共同卡点（同一天两道）**：胜负都在「表里放什么」，不在循环怎么写。13 是表建对了没用上（key 类型不匹配），12 是表根本没建对。

**其余的错**（编译期两处 + 与 13 同形两处）：

```java
ans = map.get(i+1) - cur;   // ❌① String 减 int，编译不过

                            //    步长不固定该用 while —— 今天第二次
return s;                   // ❌⑤ 返回了输入不是 ans
```

**③④比单个 bug 值钱**：和 LC13 那次「三套方案各写一半」是同一个动作——**两套写法拼在一起，每一半单独看都对**。

### 二刷 (9/1/2026) ❌ 表建反了，循环只开一层，最后看了题解

**一刷那个坎过了**：这次没再去拆 digits，直接就去建表。卡的位置往后挪了一格，这是进展。

**错一：表从小到大建。** 数组里没有「建表顺序」和「取用顺序」两套东西——**写下的顺序就是取用顺序**。从小到大就意味着每步先拿最小面额，`num = 1000` 会被 1 减一千次，吐出一千个 I。表必须降序，这不是排版，是贪心本身。

**错二：只开了一层循环。**

```java
while (num >= 0) {   // ❌ 条件也错：num 减到 0 时 0 >= 0 仍为 true，死循环
    // 然后就懵了：减哪个面额？
}
```

「里面怎么减」写不出来，不是想不出来，是**结构里没有那个信息**。循环里只有 `num` 一个状态变量，它答不了「我现在站在表的哪一格」，那减哪个面额就无从谈起。

这道题每一步要回答两个问题，而这两件事各自独立变化：

- 现在用哪一格面额？→ **外层 for**，只往下走、不回头
- 这一格还能再用一次吗？→ **内层 while**，榨干为止

两个职责压进一个 while，缺的那一层就是「懵」的来源。

**和当天上午 LC135 同一形态**：那次是一个 for 同时要「遍历」+「挑该处理的位置」，if 没写出来；这次是一个 while 同时要「换面额」+「连用同一面额」，减法写不出来。

**笔记也有责任**：上一版的正确写法只注释了「while 不是 if：同一面额可连用」，**从没说过外层 for 是干嘛的**。留下的印象就成了「内层用 while」，外层那一层根本没进脑子。这版已经把两层分工写进注释。

**「按顺序遍历就别用 Map」这条 8/31 讲过，今天又滑了**，所以它算真实信号不算笔误——见沉淀。

**自测点**：原来那条（3749 那个）9/1 讲穿作废——当天问 `decimal place value` 是什么意思，而这个词的定义本身就是答案。新的一条在排期备注页，复习时问。

### 核心思路（一句话）

**十三个值就是全部面额，从大到小每次减到不能再减，减一次追加一个符号。**

### 正确写法

```java
int[] values     = {1000, 900, 500, 400, 100, 90, 50, 40, 10, 9, 5, 4, 1};  // 必须降序
String[] symbols = {"M", "CM", "D", "CD", "C", "XC", "L", "XL", "X", "IX", "V", "IV", "I"};

StringBuilder sb = new StringBuilder();
for (int i = 0; i < values.length; i++) {   // 外层：换面额，只往下走、不回头
    while (num >= values[i]) {              // 内层：这一格用几次，榨干为止（MMM、CC）
        sb.append(symbols[i]);
        num -= values[i];
    }
}
return sb.toString();                       // sb 不是 String，别忘了转
```

**两层各管一件事**：外层决定「站在哪一格」，内层决定「这一格用几次」。少哪一层都写不下去。

**用两个数组不用 Map**：这题要**按降序遍历**，HashMap 不保证顺序。数组下标顺序天然就是贪心顺序，两个数组靠同一个 `i` 对齐。

### 为什么贪心是对的（这一层要能讲出来）

贪心通常有翻车风险——面额 `{1,3,4}` 凑 6，贪心得 4+1+1，最优是 3+3。

12 不会翻车，因为**六个减法形式（900/400/90/40/9/4）已经被当成独立面额放进表里了**。若表里只有 M/D/C/L/X/V/I 七个，凑 9 会得到 `VIIII`——贪心走进死胡同，因为它不知道 `IX` 这条路。把 IX 也列成面额之后，9 这一格直接有解，不需要回头。

**贪心之所以成立，不是它聪明，是表被设计成让它不会犯错。**

### 复杂度分析

**Time O(1)**：num ≤ 3999，外层 13 档、内层最多减 3 次，与输入规模无关。
**Space O(1)**：两张表是常数大小。

### 沉淀

- **拆数位之前先问一句：拆完之后每一位还认得出自己是多少吗？** 12 拆完就死了，位权丢了。（9/1 这条过了）
- **写循环之前先数一下：这段逻辑里有几样东西在独立变化？** 有几样就得有几层结构（或几个状态变量）。少一层，就会出现「知道要干嘛但写不出来」的那种懵。本题两样：换面额（外层 for）、同一面额连用几次（内层 while）。
- **要按顺序遍历就别用 Map**，用两个平行数组靠同一个 `i` 对齐。「这个容器给不给我顺序」是选容器的第一问。**8/31 写过、9/1 又滑，说明还没接到手上。**
- **表的顺序就是取用顺序**，降序建表不是排版是算法本身。
- **步长不固定就别用 for**：for 的 update statement 写死了，手动改 `i` 会和它叠加（8/31 两次）。
- **`ans =` 和 `ans +=` 是两件事**：覆盖不是修正（8/31 两次，另一次在 LC13）。
- **贪心正确性的通用问法**：什么情况下「拿最大的」会让后面无解？答不上就是没想清楚，不是「感觉对」。

### 引申：什么时候用 StringBuilder

**判据只有一条：拼接动作在不在循环体里。** 在 → StringBuilder；不在 → String 直接 `+` 就行。

**为什么**：String 不可变，`s += c` 不是「往里加」，而是新建一个 String + 复制全部已有字符。单次是 O(当前长度)，放进循环就是 1+2+…+n = **O(n²)**。StringBuilder 内部是可变 `char[]`，append 就是往末尾写一格、满了扩容——**与 ArrayList 完全同构**，摊还 O(1)。

> **一句话记法**：ArrayList 的代价来自「下标必须连续」，**String 的代价来自「不可变」**——任何修改都得复制全体。

**循环外不必纠结**：`"Hello, " + name + "!"` 编译器会自动优化成 StringBuilder。但**这个优化不跨循环边界**，循环里每一轮 `+=` 都是独立的一次拼接，编译器帮不了你。所以分界不是「拼几次」，是「在不在循环里」。

**常见触发场景**：构造答案串（12、38、6、43）；`sb.reverse()` 反转 / 判回文；回溯的路径（`append` → 递归 → `deleteCharAt(sb.length()-1)` 回退）。

| 调用                 | 返回                   | 备注                                            |
| -------------------- | ---------------------- | ----------------------------------------------- |
| `sb.append(x)`       | **StringBuilder 自己** | 所以能链式 `sb.append(a).append(b)`             |
| `sb.toString()`      | String                 | 最后调一次，这才产生不可变对象                  |
| `sb.reverse()`       | 自己                   | 原地                                            |
| `sb.deleteCharAt(i)` | 自己                   | 回溯标配 `deleteCharAt(sb.length()-1)`          |
| `sb.length()`        | int                    | **不是 `.size()`**，跟 String 一样用 `length()` |
| `sb.setCharAt(i, c)` | void                   | String 没有的能力                               |

`append` 返回自己、`list.add` 返回 boolean、`map.put` 返回旧 value——三个不同的答案，都是「它还给我什么」那一轴。`StringBuffer` 是线程安全版，单线程一律用 StringBuilder。
