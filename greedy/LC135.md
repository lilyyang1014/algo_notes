### 二刷 (8/24/2026) ❌ 看出要扫两趟，代码没写出来，直接看的答案

**卡在哪**：知道要扫两趟，但每趟干什么、两趟怎么拼起来，写不出来，去看了答案，看懂很快。

**真正的坎**：左右两条规则打架。每个人要同时满足「比左邻分高就比左邻糖多」和「比右邻分高就比右邻糖多」，方向相反，一趟只能兑现一条。

**第二趟要两样东西，缺一不可**：

- `if (ratings[i] > ratings[i+1])`——判断这条约束**存不存在**
- `Math.max(...)`——约束存在时，加进去而**不推翻第一趟**

（这两条的分工是四刷才吃透的，见下。）

**代码里那处错（抄写手误）**：

```java
for(int i = n - 2; n >= 0; i--){   // ❌ condition 写的是 n，应为 i
```

`n` 是长度、恒不变 → condition 永真 → loop 停不下来，`i` 减到 -1 时 `ratings[-1]` 当场 AIOOBE。

> **自检信号**：for 头写完横着读一遍，三段主语必须是同一个 variable。**有没有 break，决定同一个手误是静默还是显性**——这次没 break 所以直接崩；loop 里有 break 的话，它会替错误的 condition 兜底，部分 case 蒙对，反而更难发现。

### 四刷 (9/1/2026) ❌ 右扫整块 if 没写，只剩 `Math.max`

思路口述完整（两条约束方向相反、一趟只能卡一边、取 max 是为了不丢第一趟），坎不在理解层。

```java
for(int j = ratings.length - 2; j >= 0; j--){
    ans[j] = Math.max(ans[j], ans[j+1]+1);   // ❌ 缺 if (ratings[j] > ratings[j+1])
}
```

**后果**：等于对**每个** j 都断言「必须比右邻多一颗」→ `ans` 被推成从右往左严格递增，恒有 `ans[j] ≥ n-j`，总和虚高。`[1,2,3]`：左扫得 `[1,2,3]`，右扫 j=1 → `max(2,4)=4`、j=0 → `max(1,5)=5`，返回 12，应为 6。不崩，静默。

**为什么 max 顶不了 if**：`Math.max(ans[j], ans[j+1]+1)` 说的是「至少 `ans[j+1]+1`」，它表达不了「不动」。而约束不存在时，正确动作恰恰是不动。

**第一趟为什么没暴露这个**：三元的 `: 1` 已经替你处理了「约束不存在时怎么办」——回落到下界 1。第二趟没有下界可回落，所以那件事只能由 if 单独扛。**「回落到某个下界」和「保持不动」不是一回事**，只有前者塞得进表达式里。

**笔记自身的问题（已改）**：这份笔记原来把 `Math.max` 加粗强调了三次，还写过「`Math.max` 是两条约束能共存的唯一原因」，而 if 那一行从没被单独提过。复习完留下的印象就是「第二趟 = 取 max」。**被反复加粗的那一行，会挤掉旁边没加粗但同样必要的行。**

### 核心思路（一句话）

**两条方向相反的约束，各扫一趟；每趟都要先用 ratings 判断约束在不在，第二趟再用 `Math.max` 把新约束叠上去而不推翻旧的。**

### 正确写法

```java
public int candy(int[] ratings) {
    int n = ratings.length;
    int[] ans = new int[n];

    // 第一趟：左 → 右，只管「比左邻分高就比左邻多」
    ans[0] = 1;
    for (int i = 1; i < n; i++) {
        ans[i] = (ratings[i] > ratings[i - 1]) ? ans[i - 1] + 1 : 1;  // 约束不在就回落到 1
    }

    // 第二趟：右 → 左，兑现「比右邻分高就比右邻多」；从 n-2 起手，最后一个没有右邻
    for (int i = n - 2; i >= 0; i--) {          // condition 是 i 不是 n
        if (ratings[i] > ratings[i + 1]) {      // 先判约束在不在——约束不在就不动
            ans[i] = Math.max(ans[i], ans[i + 1] + 1);   // 写 ans 不写 ratings；取 max 不直接赋值
        }
    }

    int answer = 0;
    for (int num : ans) answer += num;
    return answer;
}
```

`ans[i]` 的含义：**满足到目前为止所有约束时，i 需要的最少糖果数**。是绝对量，不是「比邻居多几颗」。

### 复杂度分析

**Time: O(n)**：三趟线性扫描。
**Space: O(n)**：`ans` 数组。

对比 brute force（反复扫全表调整、直到没人需要改）：省在把两条约束按方向拆开，各扫一趟就都满足了，不用迭代到收敛。

### 沉淀

- **写循环之前先答一句：这一趟要不要挑位置？** 要挑，循环体第一行就得是 if；不用挑，才轮到想赋什么值。for 只负责走遍，一个位置都不会替你挡掉。第一趟的挑选被三元的 `: 1` 吸收了，第二趟没有东西能吸收它——四刷就栽在这个不对称上。
- **一行赋值里出现两个数组、共用一个下标时，写完把左边那个格子单独指一遍**，问「我要算的量存在这儿吗」。右边一眼看得出，左边看不出。和 LC238 二刷（`temp *= ans[j+1]` 该写 `nums[j+1]`）同族，那次错在读、三刷这次错在写，**写侧更隐蔽：读错是数算错，写错是整个 loop 静默失效**。
- **别原地改写还要继续读的输入数组**。`ratings` 是 condition 的依据，被写过之后，后面每一轮判断都建在污染的数据上。
- **`ans[i]` 是绝对量，不是差值也不是「数量」**。这个词已经滑过两次（8/25、9/1）。本题两者在 `ans[i-1]+1` 那步同步增长，说串了不出错；LC42 里把绝对高度和相对高度塞进同一个 `Math.min` 就直接错。
