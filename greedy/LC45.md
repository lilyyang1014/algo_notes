### 二刷 (8/5/2026) ❌ 没思路

**卡在哪**：知道「到达某个节点就要起跳」，但分不清 `curDistance` 和 `nextDistance` 该怎么配合。一度以为只有 `curDistance >= n-1` 才是对的 break 条件，觉得用 `nextDistance` 判断像是提前用了一个还没生效的值。

**真正的坎**：没建立「分层」模型。这题本质是 BFS——`curDistance` 是当前层右边界，`nextDistance` 是扫描当前层时顺手算出的下一层右边界。`i == curDistance` 触发的不是「起跳」这个动作，而是「这一层扫完了，可以决定跳」。

> **自检信号**：纠结「这一步该维护几个 variable」时，先问「这是第几层」——分层想清楚了，variable 该放哪就明确了。

### 四刷 (8/10/2026) ❌ 把「跳数」当成「层边界」去比

```java
class Solution {
    public int jump(int[] nums) {
        int cur = nums[0];      // ❌② 初值宣称"第一跳已跳过"，但 count=0 说的是"一次没跳"
        int next = 0;
        int count = 0;
        if(nums.length == 1) return 0;
        for(int i = 0; i < nums.length; i++){
            next = Math.max(next, i + nums[i]);   // ✅ 三刷的骨架还在，无条件更新
            if(i == count){
                // ❌❌① 核心错误：应为 i == cur。count 是"跳了几次"，
                //      cur 是"当前层右边界"，两个完全不同的量
                count++;
                cur = next;
                if(next >= nums.length - 1) break;
            }
        }
        return count;
    }
}
```

**①的根因**：`count` 和 `cur` 都从 0 附近增长，前几个 test case 蒙对了。真正的信号是——**`cur` 只被写、从不被读**（`cur = next` 之后无人使用）。**写进去没人用，说明它本该承担的角色被别的东西顶替了**——顺着 `cur` 找就能找到出错那一行。与 LC274「声明了却从未被读取」是镜像。

**加特判是信号不是修复**：补 `nums.length == 1` 后 test case 从 39 涨到 44，多过的全是长度 1 的 case，真 bug 一个没动。**特判能提高通过率，通常说明主逻辑有洞**（同 LC55 三刷 ❌③）。

**②**：`cur` 初值应为 `0`。一步没跳时你站在下标 0，右边界就是 0；`nums[0]` 是跳完第一次之后的边界 → 第一跳不被计数，最终少 1。

> **初值必须讲同一个故事**（LC80 二刷、LC55 三刷同族）。**自检**：写完初始化那几行，问「如果 loop 一轮都不跑，这些值合起来描述的是什么状态？」答案应该是「什么都没发生」。

> **退化的反例**（`next` 若挪进 if）：`[2,3,1,1,4]`——正确解 i=0,1 都参与 max → next = max(2, 4) = 4 → 2 跳；退化解只看 i=2 那格 → cur = 3 → 3 跳。**「最远的那一格」≠「跳得最远的那一格」**，greedy 挑的位置往往在层的中间。

### 核心思路（一句话）

**把数组按「跳几次能到」分层：`curDistance` 是当前层右边界，`i` 扫到边界说明这层扫完了，用扫描中攒下的 `nextDistance` 决定要不要再跳一次。**

### 两版对照（只用这两版之一）

**A. 上界 `n-1`（标准版，最干净）**

```java
class Solution {
    public int jump(int[] nums) {
        int curDistance = 0;       // 当前跳数覆盖到的最远下标（这一层的右边界）
        int nextDistance = 0;      // 扫这一层时顺手算出的下一层右边界
        int count = 0;
        for (int i = 0; i < nums.length - 1; i++) {   // ★ 最后一格不用再决定起跳
            nextDistance = Math.max(nextDistance, i + nums[i]);   // 每格都要参与 ← 关键
            if (i == curDistance) {                    // 这一层扫完了 → 决定跳 ← 关键
                count++;
                curDistance = nextDistance;
            }
        }
        return count;
    }
}
```

**B. 上界 `n`（则 break 和特判都变成必需）**

```java
class Solution {
    public int jump(int[] nums) {
        int curDistance = 0;
        int nextDistance = 0;
        int count = 0;
        if (nums.length == 1) return 0;                // ★ 必需
        for (int i = 0; i < nums.length; i++) {
            nextDistance = Math.max(nextDistance, i + nums[i]);
            if (i == curDistance) {
                count++;
                curDistance = nextDistance;
                if (curDistance >= nums.length - 1) break;   // ★ 必需
            }
        }
        return count;
    }
}
```

**三个 ★ 是同一件事的三种拦法。** 要拦的是**「踩到最后一格 `i = n-1`，且那一刻恰好 `i == curDistance`」时多加的那次 `count++`**（`[1,1,1,1]` 的 i=3）：

|       | 上界  | break | 特判 | 怎么拦                                                                                                            |
| ----- | ----- | ----- | ---- | ----------------------------------------------------------------------------------------------------------------- |
| **A** | `n-1` | 不要  | 不要 | **源头**：循环根本走不到最后一格                                                                                  |
| **B** | `n`   | 必需  | 必需 | break 在够到终点时**提前退出**；特判兜 `[0]` 这类长度 1 的（break 判断在 `count++` 之后，拦不住已经加上去的那次） |

**A 为什么不用特判**：`[0]` 时 `n-1 = 0` → 循环条件 `i < 0` → 一轮不进 → 返回 0。长度为 1 的数组整个循环体不执行，特判想拦的事没机会发生。

**两版的两个 `← 关键` 完全相同**：`next` 在 if 外（否则退化成从层右端起跳）、比的是 `curDistance` 而非 `count`（四刷栽在这里）。**差别只在收尾，核心逻辑一个字不差。**

### 复杂度分析

**Time: O(n)**：每个下标只参与一次 `nextDistance` 更新，一次遍历。
**Space: O(1)**：三个 variable。

对比 brute force O(n²)（从每个可达位置枚举/DFS 试跳取最小）：greedy 把「选最优跳点」压缩成扫描时顺手维护的一个 max，不必真的枚举每种跳法。

### 沉淀

- **`count++` 是「决定跳」，不是「正在跳」**：不需要知道从这一层哪个点起跳，只要这层扫完、知道下一层能到哪，答案就定了——代码里从不记录「从哪跳」。说岔成「正在跳」就会觉得终点那格也该算一跳 → 多算。这也是 `break` 必须在 `count++` **之后**的原因。
- **BFS 分层视角**：`curDistance` = 当前层右边界，`nextDistance` = 下一层右边界，`count` = 层数。想不清 loop 在干嘛时，回到「这是第几层」。
- **变量角色混淆是本题最贵的错**（四刷）：症状是**某个变量只被写、不被读**——固定自检项。
- **初值必须讲同一个故事**（LC80 二刷、LC55 三刷同族）：`curDistance` 和 `count` 都在说「已经跳了几次」，对不上就差一跳。
- **收尾只有 A、B 两版，别临场发明第三种**（六刷）：三个 ★ 拦的是同一件事，`n-1` 从源头解决。写之前先答「多算那次归谁拦」。

### 引申：跟 LC55 的对照

- 55 只答「能不能到」，一个 `coverRange` 就够，覆盖到终点直接 `return true`。
- 45 要答「最少几步」，必须多一个 `nextDistance` 把「当前层」和「下一层」分开，否则不知道该在哪个时间点给 `count` 加一。
- **上界那一行责任不同**：55 的 `i <= coverRange` 是可达性的唯一检测器，循环正常结束 = `return false`，上界**承担语义**；45 题目保证必达，上界只防多算。**先分清上界在承担语义还是只防越界，再决定写什么。**

### Interview pitch (练口述)

> "I treat this as layered BFS: curDistance is the rightmost index reachable with the current number of jumps, and while scanning that layer I track nextDistance, the farthest index reachable with one more jump. When i reaches curDistance, that layer is fully scanned, so I commit to another jump — count++ — and move the boundary to nextDistance. I stop the loop at n-2 since there's no need to decide a jump from the last index. O(n) time, O(1) space, versus brute-force DFS trying every jump sequence."
