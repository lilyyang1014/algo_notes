### 二刷 (8/3/2026) ❌ 循环条件换成 nums.length，可达性检查整个丢了

```java
for(int i = 0; i < nums.length; i++){
    //         ❌❌ 应为 i <= coverRange
    //            「循环访问到 i」≠「实际能跳到 i」
    coverRange = Math.max(coverRange, i+nums[i]);
    if(coverRange >= nums.length - 1) return true;
}
```

**根因**：`i <= coverRange` 不是普通边界，它把可达性编码进了语法。换成 `nums.length` 后，循环会拿一个根本到不了的 `i` 去刷新覆盖范围。`[3,2,1,0,4]`：i=3 时卡死在 coverRange=3，但循环继续走到 i=4，`4+4=8 >= 4` → 误判 true。

**自测点**：不看答案说出 ① `i <= coverRange` 替代了什么检查 ② `[3,2,1,0,4]` 在哪一步被挡住

### 正确写法

```java
class Solution {
    public boolean canJump(int[] nums) {
        int coverRange = 0;                       // 目前能到达的最远下标
        for (int i = 0; i <= coverRange; i++) {   // 只在可达范围内前进 ← 关键
            coverRange = Math.max(coverRange, i + nums[i]);
            if (coverRange >= nums.length - 1) return true;
        }
        return false;                             // i 超出 coverRange = 卡死
    }
}
```

Time O(n) / Space O(1)。`nums.length == 1` 不用特判。

### 沉淀

- **循环变量的推进 ≠ 状态的可达**。for 会无条件推进 `i`，可达性是算法自己的约束，必须显式守住
- **动态循环边界**：条件里的变量在体内被修改 → 这个 loop 的语义是「在可达范围内遍历」，不是「遍历整个数组」
