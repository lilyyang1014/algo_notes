## 55. Jump Game

Tags: greedy, array

### 二刷 (8/3/2026) ❌ 循环条件换成 nums.length，可达性检查整个丢了

```java
for(int i = 0; i < nums.length; i++){
    //         ❌❌ 应为 i <= coverRange
    //            「循环访问到 i」≠「实际能跳到 i」
    coverRange = Math.max(coverRange, i+nums[i]);
    if(coverRange >= nums.length - 1) return true;
}
```

**根因**：`i <= coverRange` 不是普通边界，它把可达性编码进了语法。换成 `nums.length` 后，循环会拿一个根本到不了的 `i` 去刷新覆盖范围。`[3,2,1,0,4]`：i=3 时卡死在 coverRange=3，但循环继续走到 i=4，`4+4=8 >= 4` → 误判 true。

**自测点**：不看答案说出 ① `i <= coverRange` 替代了什么检查 ② `[3,2,1,0,4]` 在哪一步被挡住

### 三刷 (8/5/2026) ❌ 覆盖范围用赋值而非取最大 —— coverRange 会缩水

178 个 test case 过了 124 个。**二刷的错没再犯**（循环条件这次记得用 coverRange 了），但换了个位置出新错：

```java
class Solution {
    public boolean canJump(int[] nums) {
        int coverRange = nums[0];
        for(int i = 1; i < coverRange; i++ ){
            //           ❌② 应为 i <= coverRange：coverRange 本身可达，必须被访问
            coverRange = i + nums[i];
            // ❌❌① 核心错误：直接赋值 → 覆盖范围可能变小
            //      语义是「目前能到的最远处」，只能增不能减，必须 Math.max
            if(coverRange >= nums.length - 1) return true;
        }
        return false;   // ❌③ nums[0] 直接覆盖终点时循环可能一次没进 → 漏判
    }
}
```

**①的根因**：coverRange 的语义是**单调不减的最优值**，任何「目前最好的」类型的变量，更新方式只能是 max（或 min），赋值等于把历史最优扔了。反例 `[3,0,0,0]`：i=1 时 `coverRange = 1 + 0 = 1`，从 3 掉到 1，循环立刻结束返回 false；实际从 index 0 一步就能到终点。

**②**：coverRange 是能到达的**最远下标**，它本身可达，`i <` 把边界那一格排除了。

**③**：判断只写在循环体内，循环没进（或没走到）就没人判。`[5,1,1,1]`、长度为 1 的数组都会漏。

**初值的一致性问题**（顺带发现，本次无害但值得记）：`coverRange = nums[0]` 宣称「index 0 已处理」，`i = 0` 起步却宣称「还没处理」——两个初值讲的不是同一个故事，这是 **LC80 二刷那条规则**的又一次露头。这次因为 `Math.max` 幂等，矛盾被吸收了，只留下一轮空转；80 那次同样的矛盾直接导致 return 少 1。**无害的那次更容易漏掉**。

统一从 `coverRange = 0` + `i = 0` 起步就没有这个问题：loop 第一轮自然处理 index 0，判断也在同一处发生，不用给长度 1 和「nums[0] 直接到终点」各打一个补丁。

**自测点**：不看答案说出 ① coverRange 为什么只能用 max 更新，写成赋值会怎样（举一个反例） ② `i <= coverRange` 里的 `=` 去掉会漏掉什么 ③ 为什么 `coverRange=0, i=0` 的组合比 `coverRange=nums[0], i=1` 少两个补丁

### 四刷 (8/10/2026) ⚠️手生 代码一次写对，口答第一遍答成了结论复述

```java
class Solution {
    public boolean canJump(int[] nums) {
        if(nums.length == 1) return true;   // 多余，主逻辑已兜住（见下）
        int cur = nums[0];
        for(int i = 0; i <= cur; i++ ){     // ✅ 二刷的错没再犯
            cur = Math.max(cur, i + nums[i]);   // ✅ 三刷的错没再犯
            if(cur >= nums.length - 1) return true;
        }
        return false;
    }
}
```

两个考点都守住了。`nums.length == 1` 误写 `return 0` 是编译期拦下的**纯手误，不进排期**。

**多余的特判**：n=1 时 `cur = nums[0]`，i=0 进循环，判断退化成 `cur >= 0` 恒成立 → 直接 true。写它是**没验证过的防御性假设**——担心循环处理不了 n=1，实际不用担心。三刷笔记里已经写过这句，这轮没接上。

**没意识到自己在依赖什么**：循环体访问 `nums[i]` 时 i ≤ cur，而 cur 一旦 ≥ n-1 就当场 return → 能进下一轮说明 `cur ≤ n-2`，于是 `i ≤ n-2 < n`，永不越界。**正确性隐式耦合在相隔几行的 return 上**——和 LC45 那次 `i < nums.length` 靠 break 兜底是同一个模式：对，但对得脆。

**自测点口答（两次追问才收敛）**：问「走到 `return false` 时发生了什么」，第一遍答「一直没进 return true 那行，所以到不了」——**这是结论的复述，不是因果链**。收窄成「循环是怎么结束的、i 停在哪一格」后答出：退出时 i 已走完 `[0, cur]` 每一格，cur 是这些格子能跳到的最远处的最大值，全取过还没够到 n-1 → **可达集已封闭**，后面的格子本身就进不去。

> **判 ⚠️手生非卡推导**：因果链是有的，只是从 invariant 翻译成话不够顺。但要留意「还没到」和「再也到不了」差着一个证明，`return false` 的依据是后者。

**口述里的 off-by-one**：她说「i 走到 cur 的位置，两个相等了」，严格说退出时 `i == cur + 1`（`i <= cur` 为 false 才退）。不影响推理成立，但这个「退出时变量停哪一格」的位置感问题，和 LC704 / LC34 反复出现的 left/right 是同一类。

**自测点**（下轮用）：`return false` 成立的依据是「可达集封闭」——说出退出时 i 和 cur 的**精确**关系，以及为什么 cur 就是可达范围的天花板而不是「还没算完」

### 正确写法

```java
class Solution {
    public boolean canJump(int[] nums) {
        int coverRange = 0;                       // 目前能到达的最远下标
        for (int i = 0; i <= coverRange; i++) {   // 只在可达范围内前进 ← 关键
            coverRange = Math.max(coverRange, i + nums[i]);   // 只增不减 ← 关键
            if (coverRange >= nums.length - 1) return true;
        }
        return false;                             // i 超出 coverRange = 可达集封闭
    }
}
```

Time O(n) / Space O(1)。`nums.length == 1` 不用特判（i=0 那轮就会判出 `0 >= 0`）。

**两个 `← 关键` 是这题仅有的两个考点，二刷和三刷各错一个，四刷两个都守住了。**

### 沉淀

- **循环变量的推进 ≠ 状态的可达**。for 会无条件推进 `i`，可达性是算法自己的约束，必须显式守住（二刷）
- **「目前最好的」类变量只能用 max/min 更新**。写成赋值 = 丢掉历史最优，症状是这个值会莫名其妙变小（三刷）
- **动态循环边界**：条件里的变量在体内被修改 → 这个 loop 的语义是「在可达范围内遍历」，不是「遍历整个数组」
- **初值必须讲同一个故事**（与 LC80 二刷同一条）：`coverRange` 的初值在说「处理到哪了」，`i` 的初值也在说同一件事，两者对不上就得打补丁
- **写特判前先验证主逻辑兜不兜得住**（四刷）。防御性的一行不花成本，但它标记着一个没验证过的假设，下次改动时没人知道能不能删
- **「循环正常结束」的语义要能证明，不能复述**（四刷）：`return false` 靠的是「可达集封闭」，不是「还没到」
