### 核心思路（一句话）

**交易次数不限 ⇒ 任何跨天收益都能拆成逐日差值之和 ⇒ 把所有正的日差值收走即可。**

---

### 解法一：贪心

```java
class Solution {
    public int maxProfit(int[] prices) {
        int profit = 0;
        for (int i = 1; i < prices.length; i++) {
            if (prices[i] - prices[i-1] > 0) {
                profit += prices[i] - prices[i-1];
            }
        }
        return profit;
    }
}
```

**Time O(n) / Space O(1)。** `prices.length == 1` 时循环不进，返回 0 ✓

**为什么成立（telescoping，一步推导）**：

```
prices[j] - prices[i] = (prices[i+1] - prices[i]) + (prices[i+2] - prices[i+1]) + ... + (prices[j] - prices[j-1])
```

中间项全部抵消。所以「低买高卖一整段上坡」与「这段里每天买卖一次」的**总收益完全相等**。既然次数不限，就把所有正差值收走，负的跳过（那些天不持股）。

**关键澄清**：代码里每个正差值看起来像「当天买当天卖」，但**它不对应真实交易序列**——实际最优操作是谷底买、峰顶卖。两者数值相同，贪心算的是拆解后的等价形式。**面试里这句要主动说**，否则会被追问「你这是每天都在交易吗」。

**121 为什么不能用这招**：121 只允许交易一次，一旦拆成日差值就变成多次交易了。**能不能 telescoping，前提是交易次数不限**——所以 121 走的是另一条贪心（维护历史最低价）。

### 解法二：DP 五步法

**1. dp 含义**（本题约定：0 = 不持有，1 = 持有）

- `dp[i][0]`：第 i 天**不持有**股票时的最大现金
- `dp[i][1]`：第 i 天**持有**股票时的最大现金

**2. 转移方程**

```java
dp[i][0] = Math.max(dp[i-1][0], dp[i-1][1] + prices[i]);  // 保持不持有 / 今天卖出
dp[i][1] = Math.max(dp[i-1][1], dp[i-1][0] - prices[i]);  // 保持持有 / 今天买入
```

**`dp[i-1][0] - prices[i]` 是 121 与 122 的唯一差别**，其余一字不动：

- **121（一次）**：买入起点固定为 `0` → `-prices[i]`。因为只交易一次，买入前不可能有过卖出，账上必然是 0
- **122（无限次）**：买入起点是「昨天不持有」的最大现金 `dp[i-1][0]` → 允许卖了再买

**3. 初始化**

```java
dp[0][0] = 0;            // 第 0 天不持有 = 没动过
dp[0][1] = -prices[0];   // 第 0 天持有 = 只能是当天买的 ← 负号
```

**不留白**（`new int[n][2]` 而非 `[n+1][2]`）：下标 i 的语义是「**第** i 天」，第 0 天是真实决策点，所以下标 0 直接用、必须手工赋值。（若语义是「**前** i 个」才留白，如背包、LCS。）

**4. 遍历顺序**：`i` 从 1 到 n-1，因为 `dp[i]` 依赖 `dp[i-1]`。

**5. 返回**：`dp[n-1][0]`。最后一天**不持有**才是利润最大化——手里还攥着股票等于钱没落袋。

```java
class Solution {
    public int maxProfit(int[] prices) {
        int n = prices.length;
        int[][] dp = new int[n][2];
        dp[0][0] = 0;
        dp[0][1] = -prices[0];
        for (int i = 1; i < n; i++) {
            dp[i][0] = Math.max(dp[i-1][0], dp[i-1][1] + prices[i]);
            dp[i][1] = Math.max(dp[i-1][1], dp[i-1][0] - prices[i]);
        }
        return dp[n-1][0];
    }
}
```

**Time O(n) / Space O(n)。** 滚动数组可压到 O(1)——面试里先写二维版拿正确性，被追问 space 时口述「`dp[i]` 只依赖 `dp[i-1]`，两个变量就能滚掉」即可，不必默写。

### 复杂度对比

| 解法    | Time | Space |
| ------- | ---- | ----- |
| 贪心    | O(n) | O(1)  |
| DP 二维 | O(n) | O(n)  |
| DP 滚动 | O(n) | O(1)  |

### 沉淀

- **能不能 telescoping（一串差值相加，中间全消，只剩两头），看操作次数有没有上限**。次数不限 → 跨段收益可拆成逐日增量，贪心成立；次数受限（121 的一次、123 的两次）→ 拆解会伪造出额外交易，只能上 DP
- **贪心的形式未必对应真实操作序列**，只保证数值相等。这一点面试要主动澄清
- **贪心 = DP 状态塌缩后的形态**。推不出贪心时退回 DP 定义状态，几乎总能推出来；反过来，122 的 DP 滚动版展开就是贪心版
- **状态定义的 0/1 约定要全系列统一**，否则 123/188 加维度时看串

### Interview pitch (练口述)

> "Since there's no limit on the number of transactions, any multi-day gain telescopes into a sum of consecutive daily differences — buying at a valley and selling at a peak yields exactly the same total as trading on every single day of that rise. So I just collect every positive daily difference and skip the negative ones. That's O(n) time, O(1) space. To be clear, the code isn't literally trading every day; the actual optimal plan buys at valleys and sells at peaks, but the totals are identical. I can also frame it as DP with a holding and a not-holding state, where buying transitions from the previous not-holding cash rather than from zero — that single change from the one-transaction version is what allows repeated trades, and the DP collapses to the same answer as the greedy."
