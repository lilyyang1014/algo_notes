### 核心思路（一句话）

**交易次数不限 ⇒ 任何跨天收益都能拆成逐日差值之和 ⇒ 把所有正的日差值收走即可。**

---

### 解法一：贪心

```java
class Solution {
    public int maxProfit(int[] prices) {
        int profit = 0;
        for (int i = 1; i < prices.length; i++) {
            if (prices[i] - prices[i-1] > 0) {
                profit += prices[i] - prices[i-1];
            }
        }
        return profit;
    }
}
```

**Time O(n) / Space O(1)。** `prices.length == 1` 时循环不进，返回 0 ✓

**为什么成立，两步，缺一不可**：

**第一步（纯代数，无前提）**——telescoping：

```
prices[j] - prices[i] = (prices[i+1] - prices[i]) + (prices[i+2] - prices[i+1]) + ... + (prices[j] - prices[j-1])
```

中间项全部抵消，等式恒成立。

**第二步（挂在题目条件上）**——这个拆法**可执行**，不只是算式相等。因为不限次数、且当天卖了可以立刻再买，「持有 i 到 j」与「每天收盘卖掉、隔天买回」是**收益完全相同的两个操作序列**。所以任何解都能改写成只做单日交易的形式，而单日差值互相独立 → 逐个取最优即全局最优：正的全收，负的全躲。

**第二步是要害。** 面试官问「凭什么」，答的是这两步，不是「感觉这样最优」。

**关键澄清**：代码里每个正差值看起来像「当天买当天卖」，但**它不对应真实交易序列**——实际最优操作是谷底买、峰顶卖。两者数值相同，贪心算的是拆解后的等价形式。**面试里这句要主动说**。

**121 为什么不能用这招**：只允许交易一次，一拆就变成多次交易了。**能不能 telescoping，前提是次数不限**——所以 121 走的是另一条贪心（维护历史最低价）。

### 解法二：DP 五步法

**1. dp 含义**（本篇约定：0 = 不持有，1 = 持有）

- `dp[i][0]`：第 i 天**不持有**股票时的最大现金
- `dp[i][1]`：第 i 天**持有**股票时的最大现金

**2. 转移方程**

```java
dp[i][0] = Math.max(dp[i-1][0], dp[i-1][1] + prices[i]);  // 保持不持有 / 今天卖出
dp[i][1] = Math.max(dp[i-1][1], dp[i-1][0] - prices[i]);  // 保持持有 / 今天买入
```

**`dp[i-1][0] - prices[i]` 是 121 与 122 的唯一差别**，其余一字不动：

- **121（一次）**：买入起点固定为 `0` → `-prices[i]`。只交易一次，买入前不可能有过卖出，账上必然是 0
- **122（无限次）**：买入起点是「昨天不持有」的最大现金 `dp[i-1][0]` → 允许卖了再买

**3. 初始化**

```java
dp[0][0] = 0;            // 第 0 天不持有 = 没动过
dp[0][1] = -prices[0];   // 第 0 天持有 = 只能是当天买的 ← 负号
```

**不留白**（`new int[n][2]` 而非 `[n+1][2]`）：下标 i 的语义是「**第** i 天」，第 0 天是真实决策点，所以下标 0 直接用、必须手工赋值。（若语义是「**前** i 个」才留白，如背包、LCS。）

**4. 遍历顺序**：`i` 从 1 到 n-1，因为 `dp[i]` 依赖 `dp[i-1]`。

**5. 返回**：`dp[n-1][0]`。最后一天**不持有**才是合法终局——`dp[n-1][1]` 是收盘还攥着股票、钱没落袋，不是「它比较小」（见二刷）。

```java
class Solution {
    public int maxProfit(int[] prices) {
        int n = prices.length;
        int[][] dp = new int[n][2];
        dp[0][0] = 0;
        dp[0][1] = -prices[0];
        for (int i = 1; i < n; i++) {
            dp[i][0] = Math.max(dp[i-1][0], dp[i-1][1] + prices[i]);
            dp[i][1] = Math.max(dp[i-1][1], dp[i-1][0] - prices[i]);
        }
        return dp[n-1][0];
    }
}
```

**Time O(n) / Space O(n)。**

### 解法三：DP 滚动（压缩到 O(1) space）

```java
class Solution {
    public int maxProfit(int[] prices) {
        int hold = -prices[0];   // 持股状态下手上的最大现金
        int free = 0;            // 不持股状态下手上的最大现金
        for (int i = 1; i < prices.length; i++) {
            free = Math.max(free, hold + prices[i]);
            hold = Math.max(hold, free - prices[i]);
        }
        return free;
    }
}
```

**能滚的判据只有一句**：`dp[i][*]` 只读 `dp[i-1][*]`，`dp[i-2]` 一次都没被读到。n 行里只有最新一行是活的，其余是死重 → 两个变量就够。

变量名直接从状态定义来（`hold` / `free`），比 `dp[i][1]` / `dp[i][0]` 更不容易在写转移时抓错哪一个，且**整层下标都不存在了**——二刷那种 off-by-one 在这一版里无从发生。

**这里有个坑，但本题恰好不咬人**：第二行读的 `free` 已经被第一行更新成「今天的 free」了，而二维版读的是 `dp[i-1][0]`（昨天的）。语义上这条多出来的路径是「今天卖掉、又拿今天的钱买回今天的股票」，算出来是 `hold + p - p = hold`，而 `hold` 本来就是候选之一 → **取 max 后没有任何变化**。根子在于本题不限次数、当天可来回，来回一趟净赚 0。

> **自检信号**：一维滚动数组里，如果转移读的是「同一轮已被更新过的变量」，先问一句——**这条多出来的路径在题目语义下是什么操作，它划算吗**。不划算 → max 自动吃掉，顺序随便；划算 → 必须存快照。

**309（冷冻期）上这条就会咬人**：那题 `hold` 要读的是**前天**的 free，卖完必须隔一天，当天来回不再免费。所以 122 上「顺序无所谓」是巧合，别当通用结论带走。

### 复杂度对比

| 解法    | Time | Space |
| ------- | ---- | ----- |
| 贪心    | O(n) | O(1)  |
| DP 二维 | O(n) | O(n)  |
| DP 滚动 | O(n) | O(1)  |

**O(n) time 是本题的下界**：任何没被读到的价格都可能改变答案。所以贪心并不比 dp 快——三者时间同级，贪心只赢在常数。**贪心和滚动 dp 在时空上完全打平，选择标准不是复杂度，是可扩展性**：加手续费、冷冻期、限制次数时，dp 改一行或加一个状态就行，贪心整条路会断。

**面试里的走法**：先讲两状态 dp 拿正确性（证明写在状态定义里，不用额外论证）→ 指出 `dp[i-2]` 从没被读到、可压到 O(1) → 再说这题因为不限次数且当天可来回，还能进一步坍缩成贪心。**展示的是解法之间的转换，不是背了一个结论。**

### 沉淀

- **能不能 telescoping，看操作次数有没有上限**。次数不限 → 跨段收益可拆成逐日增量，贪心成立；次数受限（121 一次、123 两次）→ 拆解会伪造出额外交易，只能上 DP
- **能不能滚动，看转移读到最远的是第几行**。只读 `i-1` → 两个变量；读到 `i-2` → 至少留三个
- **一维滚动里读到本轮已更新的变量时**，先问那条多出来的路径在语义下是什么操作、划不划算。不划算 max 会吃掉它，划算就必须存快照
- **贪心的形式未必对应真实操作序列**，只保证数值相等。面试要主动澄清
- **贪心 = DP 状态塌缩后的形态**。推不出贪心时退回 DP 定义状态，几乎总能推出来
- **返回哪个状态，靠「哪个是合法终局」而不是「哪个数大」**。比大小的理由依赖价格恒正，123/188/309 上会失效
- **状态定义的 0/1 约定要全系列统一**，否则 123/188 加维度时看串

### 引申：股票系列的分叉点

六题共用一个骨架，差别全在**买入的起点**和**状态维度**上：

| 题               | 差异                                      |
| ---------------- | ----------------------------------------- |
| 121（一次）      | 买入起点固定 `0`                          |
| 122（无限次）    | 买入起点浮动 `dp[i-1][不持有]` ← 本题     |
| 123（最多两次）  | 加维度：四状态，第二次持有 ← 第一次卖出后 |
| 188（最多 k 次） | 123 的一般化，状态数 2k+1                 |
| 309（冷冻期）    | 改「买入能从哪天的不持有状态转移」        |
| 714（手续费）    | 卖出那一行减去 fee                        |

- 309（滚动版必须存快照的反例，见解法三）

### Interview pitch (练口述)

> "Since there's no limit on the number of transactions, any multi-day gain telescopes into a sum of consecutive daily differences — and because we're allowed to sell and re-buy on the same day, that decomposition is actually executable, not just an algebraic identity. So I collect every positive daily difference and skip the negative ones: O(n) time, O(1) space. To be clear, the code isn't literally trading every day; the optimal plan buys at valleys and sells at peaks, but the totals are identical. I'd also frame it as DP with a holding and a not-holding state, where buying transitions from the previous not-holding cash rather than from zero — that single change from the one-transaction version is what allows repeated trades. Since each row only reads the previous row, the table rolls down to two variables, so the DP is O(1) space too. I'd return the not-holding state at the end, not because it's numerically larger but because still holding a share isn't a valid terminal state. In an interview I'd lead with the DP, since adding a fee, a cooldown, or a transaction cap only changes a line or a state, whereas the greedy argument breaks entirely."
