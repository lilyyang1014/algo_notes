### 四刷 (9/18/2026) ❌ DP 读错 state，买入时混入多次 transaction

```java
dp[i][0] = Math.max(dp[i-1][0], dp[i][1] + prices[i]);
// ❌① dp[i][1] 尚未计算，默认 0，相当于免费拿到 stock

dp[i][1] = Math.max(dp[i-1][1], dp[i][0] - prices[i]);
// ❌❌② 买入接上已有 profit，允许完成一笔 transaction 后再次买入
```

**①的根因**：今天卖出，要接昨天的持有 state `dp[i-1][1]`。例如 `[7,1]`，读默认 0 会算出 profit = 1，正确答案是 0。

**②的根因**：本题最多一笔 transaction，今天买入前不能已有交易 profit，因此买入分支只能是 `-prices[i]`，不是不持有 state 减价格。

当天重新说出了 greedy 思路：维护 prefix minimum。DP 与 greedy 都是 O(n) time，greedy 将 space 从 O(n) 降到 O(1)。

**自测点**：为什么买入分支不能用 `dp[i-1][0] - prices[i]`？用 `[1,5,2,8]` 说明它会多算哪笔 profit。

### 核心思路（一句话）

**固定卖出日，之前买得越便宜，profit 越大；扫描时维护最低买入价和最大 profit。**

### 正确写法①：Greedy

`minPrice` 记录截至今天的最低价，`maxProfit` 记录截至今天的最大 profit。

```java
class Solution {
    public int maxProfit(int[] prices) {
        int minPrice = prices[0];
        int maxProfit = 0;

        for (int i = 1; i < prices.length; i++) {
            minPrice = Math.min(minPrice, prices[i]);
            maxProfit = Math.max(maxProfit, prices[i] - minPrice);
        }

        return maxProfit;
    }
}
```

**为什么先更新最低价也可以？** 如果今天成为最低价，差值就是 0，不会产生正 profit；0 对应不交易。

在这份初始化下，两行交换也正确：先算 profit，就是只用今天之前的最低价。

### 正确写法②：DP

- `dp[i][0]`：第 i 天结束时，不持有 stock 的最大 profit。
- `dp[i][1]`：第 i 天结束时，持有 stock 的最大净收益，买入成本记为负数。

**持有不代表今天买入，也可能是之前买的、一直没卖。**

```java
class Solution {
    public int maxProfit(int[] prices) {
        int n = prices.length;
        int[][] dp = new int[n][2];

        dp[0][0] = 0;
        dp[0][1] = -prices[0];

        for (int i = 1; i < n; i++) {
            // 继续不持有，或把昨天持有的 stock 今天卖掉
            dp[i][0] = Math.max(dp[i-1][0],
                               dp[i-1][1] + prices[i]);

            // 继续持有，或今天首次买入
            dp[i][1] = Math.max(dp[i-1][1], -prices[i]);
        }

        return dp[n-1][0];
    }
}
```

**为什么买入只能用 `-prices[i]`？**

最多一笔 transaction → 买入前没有完成过其他 transaction → 可用的交易 profit 是 0 → 买入后为 `0 - prices[i]`。

如果改成 `dp[i-1][0] - prices[i]`，对于 `[1,5,2,8]`：

- 1 买、5 卖，先赚 4。
- 带着这 4 在价格 2 时再次买入，持有 state 变成 `4 - 2 = 2`。
- 价格 8 时卖出，结果为 `2 + 8 = 10`。

这算了两笔 transaction。本题正确答案是 `8 - 1 = 7`。

### 拓展：DP 压缩成两个 variable

只依赖前一天，不需要保存整张 DP table：

```java
int cash = 0;
int hold = -prices[0];

for (int i = 1; i < prices.length; i++) {
    cash = Math.max(cash, hold + prices[i]);
    hold = Math.max(hold, -prices[i]);
}

return cash;
```

先更新 `cash`，使用的仍是昨天的 `hold`；更新 `hold` 不依赖 `cash`。

它与 greedy 维护的信息相同：

- `hold = -minPrice`
- `cash = maxProfit`

**本题的 greedy 和压缩 DP 可以这样对应，不代表所有 greedy 都能从 DP 直接压缩得到。**

### 复杂度分析

| 做法                                  | Time  | Space |
| ------------------------------------- | ----- | ----- |
| Brute force：枚举买入日与之后的卖出日 | O(n²) | O(1)  |
| Greedy                                | O(n)  | O(1)  |
| 二维 DP                               | O(n)  | O(n)  |
| 压缩 DP                               | O(n)  | O(1)  |

O(n) time 已经最优：需要检查所有价格。压缩 DP 优化的是存储，不是扫描次数。

若还要返回买卖日期，greedy 可以额外记录最低价日期和最佳买卖日期，仍是 O(1) space。

### 沉淀

- **先看 transaction 次数，再写买入 transition。** LC121 首次买入从 0 出发；LC122 可以接之前的 profit。
- **读 DP state 前，确认它已经计算。** Java 默认 0 可能把“尚未计算”伪装成合法值。
- **初值要符合题意。** 本题允许不交易，所以最大 profit 从 0 开始，不必用 `Integer.MIN_VALUE`。
- **重复寻找 prefix minimum，可以改成增量维护。** 每来一个价格，用一次 `Math.min` 更新。
- **写完 for 头横着检查。** 初始化、condition、update statement 是否指向预期的 variable。

### 引申：DP table 是否需要多留一格

取决于 index 的定义，不由题型名称决定：

- `dp[i]` 表示「第 i 天」：本题使用 n 行，手动初始化第 0 天。
- `dp[i]` 表示「处理完前 i 天」：可以使用 n + 1 行，另行定义未处理任何天的初始 state。

两种定义都可以，关键是初始化和 transition 一致。本题若漏掉 `dp[0][1] = -prices[0]`，默认 0 就相当于免费拿到 stock。

### Interview pitch

> "For each selling day, the best buying price is the lowest price seen before it. I track that minimum and update the maximum profit in one pass. The answer starts at zero because making no transaction is allowed. This takes O(n) time and O(1) space."
