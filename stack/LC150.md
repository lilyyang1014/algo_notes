**① String 转 integer 的 API 不熟**

```java
int right = stack.pop().parseInt();
// ❌ parseInt 是 Integer 的 static method，不是 String 的 instance method
```

改用 `Deque<Integer>`，数字 token 入栈时转换：

```java
stack.push(Integer.parseInt(token));
```

**② 把“不是任何 operator”写成 OR**

```java
for (int token : tokens) { // ❌ tokens 是 String[]，应为 String token
    if (cur != "+" || cur != "-" || cur != "*" || cur != "/") {
        // ❌ cur / token 混用；String 内容比较应使用 equals
        // ❌ 多个“不等于”用 ||，operator 也会进入数字 branch
        stack.push(Integer.parseInt(token));
    }
}
```

**根因**：“是其中一个”用 OR；“一个都不是”要求每个排除条件同时成立，用 AND。

例如 token 为 `"+"`，虽然“不等于加号”为 false，但“不等于减号”为 true；用 OR 后整体仍为 true，错误进入数字 branch。

```text
是 operator：A || B || C || D
不是 operator：!A && !B && !C && !D
```

这是 De Morgan’s law：`!(A || B)` 等价于 `!A && !B`。

**③ 主体写出后，syntax 和最终返回值没补完**

```java
// ❌ 一个连接符写成了 &，本题统一使用 &&
!token.equals("-") & !token.equals("*")

else if (token.equals("-") { // ❌ 缺少一个 )
    num = left - right;
}
// "*"、"/" 的 branches 同样缺少 )

// ❌ 方法末尾漏了 return stack.pop();
```

Boolean `&` 在这里可以运算，但不会 short-circuit；它不是本次 compile error 的来源。缺少 `)` 和 return 才会阻止 compilation。

> **自检信号**：用一个 operator 和一个数字分别检查分类 condition；最后问自己“答案现在存在哪里，是否已经 return”。

**自测点**：不写代码，分别用 `"+"` 和 `"3"` 代入数字判断，解释为什么多个 `!equals` 之间必须用 AND。

### 题目

给定 String array `tokens`，表示合法的 Reverse Polish Notation expression，返回计算结果。

```text
["2", "1", "+", "3", "*"] → 9
对应：(2 + 1) * 3
```

- **operand**：参与运算的数。
- **operator**：`+、-、*、/`。
- 每次运算使用两个 operands，产生一个新结果。

### Clarify

先只读核心题面，主动确认会影响实现的条件：

| 问题                                                        | 原题保证                                                        |
| ----------------------------------------------------------- | --------------------------------------------------------------- |
| Expression 是否一定有效？                                   | 是；每次遇到 operator 时至少有两个 operands，最后恰好剩一个结果 |
| Operators 是否只有四则运算，其余 tokens 都是合法 integers？ | 是                                                              |
| 是否允许 negative integers？                                | 允许                                                            |
| Division 是否可能遇到零除数？                               | 不会                                                            |
| Division 如何处理 negative result？                         | 向零截断，例如 `-7 / 2 = -3`                                    |
| 中间结果是否可能 overflow？                                 | 都在 32-bit integer 范围内                                      |

`left / right` 中，left 是被除数，right 是除数。需要排除的是 **right 为 0**；`0 / 3` 没问题。

原题保证有效，不代表 stack 始终有两个数，而是**遇到 binary operator 时至少有两个可用 operands**。

### 核心思路（一句话）

**Stack 保存尚未消耗的 operands 和中间结果；遇到 operator，取出最近两个结果运算，再 push 回去。**

### 正确写法

```java
import java.util.ArrayDeque;
import java.util.Deque;

class Solution {
    public int evalRPN(String[] tokens) {
        Deque<Integer> stack = new ArrayDeque<>();

        for (String token : tokens) {
            if (!token.equals("+")
                    && !token.equals("-")
                    && !token.equals("*")
                    && !token.equals("/")) {
                stack.push(Integer.parseInt(token));
            } else {
                int right = stack.pop();
                int left = stack.pop();
                int result = 0;

                if (token.equals("+")) {
                    result = left + right;
                } else if (token.equals("-")) {
                    result = left - right;
                } else if (token.equals("*")) {
                    result = left * right;
                } else if (token.equals("/")) {
                    result = left / right;
                }

                stack.push(result);
            }
        }

        return stack.pop();
    }
}
```

若多个否定条件容易写反，可以改成正向判断：

```java
boolean isOperator = token.equals("+")
        || token.equals("-")
        || token.equals("*")
        || token.equals("/");
```

### 为什么先 pop right

较晚出现的 operand 在 stack 顶，先弹出的必须放在 operator 右侧：

```text
["5", "2", "-"]

right = 2
left = 5
result = 5 - 2 = 3
```

Addition / multiplication 可能掩盖顺序错误，因此 dry run 要包含 subtraction 或 division。

### 为什么最后只剩一个结果

下面按 stack 底 → 顶表示：

```text
读 2：[2]
读 1：[2, 1]
读 +：[3]
读 3：[3, 3]
读 *：[9]
```

每个 binary operator 消耗两个 operands，再放回一个结果。合法完整 expression 最终恰好留下一个结果，直接 pop 返回。

### 复杂度分析

设 n 为 tokens 数量，按原题每个 token 长度有界分析：

**Time: O(n)**：每个 token 处理一次，parse、比较和 stack 操作均为 O(1)。  
**Extra space: O(n)**：可能先读入很多 operands，之后才遇到 operators。最终剩一个结果，不代表过程中只用了 O(1) space。

若 token 长度不受限，还需计入扫描和解析其 characters 的成本。

### Follow-up：不再保证 input 有效

本轮能主动想到检查 token 和 pop 前的数量；“恰好两个也足够”经纠正后理解，最终剩余数量检查在提示后补上。

先与 interviewer 约定 invalid input 如何报告；以下假设抛 exception。

| 检查位置      | 检查内容                         | 反例                              |
| ------------- | -------------------------------- | --------------------------------- |
| 入口          | null / empty input               | `[]`                              |
| 解析 token    | 必须是支持的 operator 或合法 int | `["2", "abc"]`、`["2", "3", "^"]` |
| pop 之前      | `stack.size() >= 2`，不是 `> 2`  | `["2", "+"]`                      |
| Division 之前 | `right != 0`                     | `["2", "0", "/"]`                 |
| 运算后        | 若不再保证范围，检查 overflow    | `["2147483647", "1", "+"]`        |
| 全部读完      | `stack.size() == 1`              | `["2", "3"]`                      |

数字可尝试用 `Integer.parseInt(token)` 解析；失败会抛 `NumberFormatException`，超出 int 范围也会失败。

先识别 operator，再尝试解析其余 token。成功 push 数字后使用 continue 没问题；没有处理就 continue，才会漏掉它。

若需检查 arithmetic overflow，应先转 long 再运算，不能等 int 已经 overflow 后才检查。

### 沉淀

- **Stack 中保存的是仍可参与后续运算的结果。** 不只是原始数字。
- **先 pop right，再 pop left。** Subtraction / division 必须保持顺序。
- **“一个都不是”需要 AND。** 不确定时先写正向的 isOperator。
- **Validity 分两层检查。** 每个 token 合法，不代表整个 expression 合法。
- **完成运算还要返回答案。** 最终结果保存在 stack 中。
