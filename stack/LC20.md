### 一刷 (9/19/2026) ❌ 知道用 stack 配对，但没分清什么时候 push / pop

```java
stack.append(s.charAt(0)); // ❌① Deque 没有 append，用 push

for (int i = 1; i < s.length(); i++) {
    char cur = s.charAt(i);
    char pop = stack.pop();
    // ❌② 每轮直接 pop：读到左括号也会移除旧值，empty 时抛 exception
}
```

**根因**：stack 保存尚未配对的左括号。左括号来了要 push；只有右括号来了，才检查能否与 top 配对。

例如 `"([])"`，读到 `[` 时应保留 `(` 并 push `[`；直接 pop 会提前丢掉 `(`。

看解后重写，逻辑正确，只剩一处 mechanical error：

```java
if (cur == '(' || cur = '[' || cur == '{') {
    // ❌③ = 应为 ==，导致 compile error
}
```

> **自检信号**：多个 conditions 用 || / && 连接时，逐项检查比较符号。

**自测点（当时）**：为什么右括号只能与 top 配对，不能去 stack 更深处找同类型的左括号？

### 二刷 (10/10/2026) ❌ 左括号入栈后仍执行配对，分支范围没有划清

记得左括号 push、匹配后 pop，但初稿配对 condition 的括号未配平；查空放在 peek 之后；不匹配时也没有返回 false。

```java
if (是左括号) {
    stack.push(c);
}

// ❌① 左括号也会执行配对，刚入栈就与自己比较
if (匹配 stack.peek() 与 c) {
    if (!stack.isEmpty()) stack.pop();
    // ❌② 查空太晚：上面已经调用 peek 并与 char 比较
}
// ❌③ 不匹配时没有 return false，会忽略非法右括号
```

例如 `"(])"`，如果忽略不匹配的 `]`，后面的 `)` 会弹出 `(`，最后错误返回 true。

修改后仍把配对代码留在 if / else 外：

```java
if (c == '(' || c == '[' || c == '{') {
    stack.push(c);
} else {
    if (stack.isEmpty()) return false;
}

char top = stack.peek(); // ❌ 仍然每轮都会执行

if (匹配 top 与 c) {
    stack.pop();
} else {
    return false;
}
```

**根因**：if / else 不会自动跳到下一轮。输入 `"()"` 时，`(` 入栈后继续执行外面的配对代码，拿 `(` 与自己比较，立即返回 false。

> **自检信号**：用一个左括号走完整轮 for，检查 push 后是否还会执行配对；右括号的查空、peek、匹配与 pop 应在同一个 branch。

讲解后能复述正确的 branch 划分，也理解了 if / else 后的代码仍会继续执行。当天尚未展示修正后的独立代码。

**自测点（当时）**：如果不用 else，左括号 push 后需要加什么，才能保证本轮不再执行后面的配对代码？

### 三刷 (10/12/2026) — 匹配判断有误，自行修正后代码正确

写前能说出左括号 push、右括号配对；经提醒补全 empty stack 与最终剩余检查，并确认 Deque 应使用 push / pop。

**本轮卡点**：初稿没有在不匹配时立即返回 false，可能忽略非法右括号，让后续匹配把 stack 清空后误返回 true。与二刷“不匹配时未拒绝”是同一个问题，本轮自行发现并修正。

最终把失败条件写清：

```java
if ((c == ')' && deque.peek() != '(')
        || (c == ']' && deque.peek() != '[')
        || (c == '}' && deque.peek() != '{')) {
    return false;
}
deque.pop();
```

**根因**：不是“非法右括号没有入栈”，而是没有拒绝已经发生的错误。Stack 本来只保存左括号；类型或顺序不匹配时，后面的 character 无法补救。

> **自检信号**：用 `"(])"` 检查失败路径：遇到 `]` 的当轮是否立即返回 false，而不是继续读后面的 `)`。

最终代码正确；本轮有自行修正和写前提示，不记一次 AC。先 peek 再 pop 更清楚，但不是唯一正确写法：先 pop 再比较也可以，前提是先查空、不匹配立即返回 false。

### 核心思路（一句话）

**Stack 保存尚未配对的左括号；每个右括号必须与最近的一个左括号配对。**

### 正确写法

以下按 s 非 null、只包含六种括号的 input contract 编写；empty string 返回 true。

```java
import java.util.ArrayDeque;
import java.util.Deque;

class Solution {
    public boolean isValid(String s) {
        Deque<Character> stack = new ArrayDeque<>();

        for (int i = 0; i < s.length(); i++) {
            char c = s.charAt(i);

            if (c == '(' || c == '[' || c == '{') {
                stack.push(c);
            } else {
                if (stack.isEmpty()) return false;

                char top = stack.peek();

                if ((c == ')' && top != '(')
                        || (c == ']' && top != '[')
                        || (c == '}' && top != '{')) {
                    return false;
                }

                stack.pop();
            }
        }

        return stack.isEmpty();
    }
}
```

### Branch 与操作顺序

```text
左括号 → push
右括号 → 查空 → 检查类型 → 匹配才 pop
结束后 → 检查 stack 是否为空
```

配对代码属于右括号 branch。If / else 之后的代码仍会执行；若不使用 else，需要在左括号 push 后 continue，避免继续配对。

右括号只能匹配 top：最晚出现、尚未闭合的左括号必须先闭合。`"([)]"` 中遇到 `)` 时，不能跳过 top 的 `[` 去找更深处的 `(`。

### 三种失败情况

| 情况                   | 例子             | 检查位置                     |
| ---------------------- | ---------------- | ---------------------------- |
| 右括号没有对应的左括号 | `")"`            | 右括号 branch 中，stack 为空 |
| 类型或嵌套顺序不匹配   | `"(]"`、`"([)]"` | 当前右括号与 top 不匹配      |
| 左括号没有闭合         | `"(()"`          | traversal 结束，stack 非空   |

### Deque API

本题把 Deque 当 stack 使用：

```java
stack.push(c); // 从队头加入
stack.peek();  // 查看队头，不移除
stack.pop();   // 从队头移除并返回
```

`offer()` 默认从队尾加入，与 `pop()` 配对会变成 FIFO；本题需要 LIFO，使用 push / pop。

ArrayDeque 为空时：

- `peek()` 返回 null；赋给 char 或与 char 比较时，unboxing 会导致 NPE。
- `pop()` 抛出 NoSuchElementException。

因此必须先查空，再 peek / pop。

### Interview clarification

只问题面尚未明确、会影响实现的条件：

- **Character 范围**：只包含 `()[]{}` 吗？若有 letters / digits，是忽略还是直接判 invalid？
- **Empty / null**：允许 empty string 吗，是否视为 valid？能否假设 input 非 null？
- **Input size**：最大 length 是多少？
- **匹配规则**：若题面含糊，确认必须按类型正确嵌套，例如 `"([)]"` 应返回 false。

当前代码依赖“只有六种括号”：else 才能直接视为右括号。若允许其他 characters，需要按约定另行处理。

### 复杂度分析

**Time: O(n)**：每个 character 扫描一次，每个左括号最多 push / pop 各一次。  
**Extra space: O(n)**：全是左括号时，stack 保存全部 characters。

### 沉淀

- **最晚出现的左括号，必须最先配对。** 这是使用 stack 的原因。
- **Branch 范围要和职责对应。** 左括号只 push，右括号才查空、配对和 pop。
- **不匹配必须立即拒绝。** 不能忽略非法右括号，等最后 stack 为空再判断。
- **先排除失败，最后检查剩余。** 最终 `return stack.isEmpty()` 检查未闭合的左括号。
- **从 i = 0 统一处理。** 不需要提前 push 第一个 character，也不需要单独判断 length == 1。
