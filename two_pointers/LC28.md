### 一刷 (9/29/2026) ❌ 思路有了，候选起点与匹配进度混在一起

想用 ans 记录候选起点，完整匹配 needle 后返回，但没有写完：

```java
int ans = 0;
for (int i = 0; i < needle.length(); i++) {
    char c = needle.charAt(i);
    while (i < haystack.length && c != haystack.charAt(i)) {
        // ❌① i 同时表示两个 String 的 index，无法独立变化
        // ❌② String 长度应为 length()
        ans++;
        i++;
        // ❌③ 没有固定候选起点，也没有检查后续字符是否连续匹配
    }
}
```

**根因**：需要独立表达「从哪里开始试」和「已经匹配了几个字符」。ans 没有固定住起点，i 又同时承担两边的绝对 index，匹配过程无法展开。

**讲解后重写成功**：start 固定候选起点，j 表示匹配进度，也是相对起点的 offset：

```text
start = 2

j=0：haystack[2] 对 needle[0]
j=1：haystack[3] 对 needle[1]
j=2：haystack[4] 对 needle[2]
```

两个 String 共享的是 offset，不是绝对 index。本轮先掌握 brute force，KMP 暂不要求独立实现。

> **自检信号**：写比较前，分别指出候选起点和 offset；内层只推进 offset，失败后才换起点并重置 offset。

**自测点**：某个起点匹配了几个字符后失败，能不能直接从失败位置重新尝试，跳过中间的候选起点？举例说明。

### 二刷 (9/30/2026) ❌ guard 漏保护 needle；未匹配时返回 0

start 与 j 的分工、外层范围和匹配成功判断都写对了，剩下两处：

```java
int ans = 0; // ❌② 未匹配时仍返回 0，应初始化为 -1
...
while (j + start < haystack.length()
        && haystack.charAt(start + j) == needle.charAt(j)) {
    // ❌① 只保护 haystack；j == m 后仍可能访问 needle.charAt(m)
    j++;
}
...
return ans;
```

**根因**：① 同一行访问两个 String，却只检查 haystack 的 index；`"ab"` / `"a"` 匹配完后 j=1，继续访问 needle 时越界。② ans 的初值也是「没有匹配」路径的返回值；`"abc"` / `"d"` 会错误返回 0。

> **自检信号**：逐个核对每次访问由哪个 condition 保护，再用「完全匹配」和「完全不匹配」各走一遍返回路径。

**自测点**：某个 start 匹配失败时，能否立刻 return -1？给一个具体例子说明。

### 核心思路

**从左到右尝试每个候选起点，固定 start，用 j 连续比较；第一次完整匹配时返回 start。**

### 正确写法

```java
class Solution {
    public int strStr(String haystack, String needle) {
        int n = haystack.length();
        int m = needle.length();

        for (int start = 0; start <= n - m; start++) {
            int j = 0;

            while (j < m
                    && haystack.charAt(start + j) == needle.charAt(j)) {
                j++;
            }

            if (j == m) return start;
        }

        return -1; // 所有候选起点都失败，才判定不存在
    }
}
```

- **`start <= n - m`**：从 start 到末尾至少剩 m 个字符；等号对应刚好剩 m 个字符。
- **`j < m`**：保护 needle；配合外层的 `start <= n - m`，也能保证 `start + j < n`。
- **`j == m`**：完整匹配，返回 start；否则尝试下一个 start，j 从 0 重新开始。

起点从小到大尝试，因此第一次成功就是最早出现的位置。若 m>n，外层 loop 不执行，直接返回 -1。

保留 `ans + break` 的写法也可以，但 ans 必须初始化为 -1。

### 复杂度分析

**Time: O((n-m+1) × m)**（n≥m）：最多尝试 n-m+1 个起点，每次最多比较 m 个字符，通常简写为 O(nm)。
**Space: O(1)**：只维护固定数量的 variable。

### 沉淀

- **起点 + offset = 当前 index。** start 表示候选起点，j 表示匹配进度；两段序列起点不同，也能共享 offset 来对齐。
- **连续匹配不能跳过不匹配字符。** 遇到不同字符就结束本次尝试，否则检查的不是 substring。
- **每次访问都要有边界依据。** 一个 guard 不一定保护同一行的所有访问；本题 haystack 的安全依赖内外两层 condition 配合。
- **默认返回值要对应失败路径。** 使用 ans 暂存结果时，先确认「一次都没更新」应该返回什么。
