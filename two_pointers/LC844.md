### 二刷 (7/24/2026) ❌ 没思路：方向对了，翻译不成代码

**卡在哪**：知道倒序两个 pointer、遇 `#` 要「跳过」，但写不出「跳过」的代码结构。

**真正的坎**：「跳过 #」不是一个 if，是一笔**会累积的删除债**——`#` 自己不算字符、还要吞掉左边下一个幸存字符，且能连续堆叠（`"ab##"` 欠两笔）。需要的是**记账 + 清账的小状态机**：skip counter 记债，内层 loop 边左移边清账，直到停在幸存字符上或出界。

**当天重写的两个错**：①「单边出界 → false」写成了字符比较 if 的 `else if`（挂错宿主）→ 退化成「字符相等就 return false」，`"a"/"a"` 现形。②`else` 分支里重写 `!= '#'`（冗余 condition），和 LC80 二刷同族。

### 三刷 (7/29/2026) ❌ 结构记住了，三处推进/边界责任掉线

框架一次到位，bug 全在落地那一步：

```java
while(i >= 0){
    if(s.charAt(i) == '#'){
        countS++;
        // ❌❌① 漏 i--：'#' 自己也要跳过。i 不动 → 下一轮读到同一个 '#'
        //      → countS 无限累加 → 遇到任何 # 都 infinite loop
    }else{
        if(countS > 0){ countS--; i--; }
        else break;
    }
}
...
    if(s.charAt(i) != t.charAt(j)) return false;
    // ❌③ charAt 前未查越界：外层是 || ，完全可能 i = -1 而 j >= 0
    i--;
    j--;
    return true;   // ❌② 写在 while 体内 → 只比第一对就返回
}
```

**①的根因**：`while` 里**每一条不 break 的分支都必须推进 loop variable**，`'#'` 那支只记债没走人。

**②③的根因**：**把某一层的前提当成了另一层的前提**——`return true` 是外层的终局却写进体内；外层的 `||` 保证「至少一边还有」，不是「两边都有」。补越界检查时一度想写裸 `else { return false; }`，那会把「两边都耗尽」（true）和「单边耗尽」（false）压成一支，`s="a#", t="b#"` 现形。

> **自检信号 A**：if 条件含 `&&` / `||` 时取反不止一种情况（`!(A && B)` = A假 / B假 / 都假），裸 `else` 会把它们压成一支。「互补分支用裸 else」的前提是**真互补**，复合条件通常不满足。

```java

    if(s.charAt(i) == '#'){countS++; i--;}
    else if(countS >= 0) {countS--; i--;}   // ❌❌ 应为 countS > 0
    else break;
}
```

**根因**：`countS` 的语义是「还欠几个删除」，`> 0` 才表示「有欠账 → 这个字符要被吞」。`>= 0` 把 **countS == 0（无欠账 = 这是幸存字符）** 也划进了删除分支，本该 break 出来参与比较的字符被 `i--` 悄悄跳过。

**静默且局部**：countS 变 -1 后 `-1 >= 0` 为 false、下轮就 break，所以每个 string 只有**第一个幸存字符**被吃掉，极难一眼看出。反例 `s="ab", t="ac"`：`'b'` 和 `'c'` 全被吃，只比了 `'a'=='a'` → return true（期望 false）。

**归族**：和 LC34 8/4 的 `<=` vs `<` 同族——**等号该不该带**，都是「语义在脑子里是对的，没接到 condition 那一行上」。

**关键观察**：**有提示的情况下这个错依然发生** → 提示能帮你搭骨架，帮不到 condition 那一格，两层是独立的。

> **自检信号 B**：写 counter 的 condition 时，把 `count == 0` 单独代进去问一句「这一刻该删还是该留」。counter 类 condition 的错几乎全在 0 那一格上。

**自测点**：① `return true` 为什么必须在外层 while 之后 ② 外层 `||` 保证了什么、没保证什么

### 核心思路（一句话）

**倒序 two pointers，各自用 skip counter 清完「删除债」、停在幸存字符上再比较；`#` 只影响左侧，所以唯有倒序扫不需要额外空间。**

### Brute force 版（推导链起点 + string API 练手）

正序重建两个最终 string 再比较，stack 语义（正序添加 → 「最近的」=「末尾的」→ `#` 就是 pop 末位）：

```java
class Solution {
    public boolean backspaceCompare(String s, String t) {
        return getString(s).equals(getString(t));
        // ⚠️ String 内容比较必须 equals；== 比的是引用（C++ 转 Java 头号坑）
    }
    private String getString(String str) {
        StringBuilder sb = new StringBuilder();      // String immutable，凡「边走边改」必须 StringBuilder（或 char[]）
        for (int i = 0; i < str.length(); i++) {     // length() 带括号是方法；array 的 length 不带括号
            if (str.charAt(i) != '#') {
                sb.append(str.charAt(i));            // 尾部追加 = push
            } else if (sb.length() > 0) {            // guard：债多于人（"##a" 前两个 # 时 sb 为空），空则忽略——没它就越界
                sb.deleteCharAt(sb.length() - 1);    // 删末位 = pop（Java 无 pop_back，这么拼）
            }
        }
        return sb.toString();                        // 用完转回 String
    }
}
```

O(n+m) time / O(n+m) space。

**过手的 string API**：`equals` / `charAt` / `length()` / StringBuilder 的 `append` / `deleteCharAt` / `toString`。

- `deleteCharAt(末位)` 是 O(1)，删中间才是 O(n)（后面元素要整体前移）
- `toCharArray()` 是 String 专属，StringBuilder 没有，需 `sb.toString().toCharArray()` 过桥
- 转数组是 O(n) 复制不是取引用；只读一位用 `charAt` 就够

### 代码（倒序 two pointers，O(1) space）

```java
class Solution {
    public boolean backspaceCompare(String s, String t) {
        int i = s.length() - 1, j = t.length() - 1;
        int skipS = 0, skipT = 0;
        while (i >= 0 || j >= 0) {
            while (i >= 0) {
                if (s.charAt(i) == '#') { skipS++; i--; }   // 记债
                else if (skipS > 0)     { skipS--; i--; }   // 清账：字符被吞
                else break;                                 // 幸存字符，停（不动 i）
            }
            while (j >= 0) {
                if (t.charAt(j) == '#') { skipT++; j--; }
                else if (skipT > 0)     { skipT--; j--; }
                else break;
            }
            if (i >= 0 && j >= 0) {                 // 都停住 → 比字符
                if (s.charAt(i) != t.charAt(j)) return false;
            } else if (i >= 0 || j >= 0) {          // 单边出界 → 长度不等
                return false;                       // （与上面的 if 并列，勿嵌入）
            }
            i--; j--;
        }
        return true;                                // 双双出界 → 全部通过
    }
}
```

### 复杂度分析

**Time: O(n+m)**：i、j 各自单调左移不回头，每个字符至多访问一次。
**Space: O(1)**：两个 pointer + 两个 counter。

对比 brute force 的 O(n+m) space：时间同阶，倒序版的全部价值是把空间压到 O(1)——面试 follow-up「能不能 O(1) space」要的就是它。

### 沉淀

- **每条不 break 的分支都要推进 loop variable**（三刷 ①）。反过来，**`break` 那支不能推进**：内层 while 只负责「停到幸存字符上」，推进的责任归外层比较之后那两行——定位与推进分层，谁都别抢（五刷）
- **counter 的 condition 卡在 0 那一格**（四刷）
- **别把某一层的前提当成另一层的**：`return true` 属外层终局；`||` 只保证「至少一边还有」（三刷 ②③）
- **「债多于人」这个 edge case 的两种归宿**：brute force 版靠显式 guard `sb.length() > 0`；倒序版里它表现为扫完 skip 仍 > 0，被 `i >= 0` 天然吸收，多余的债自动作废。口述时能追踪它的去向 = 真懂了

### 引申：从 brute force 到 O(1) 的两次追问

1. **正序重建**（见上，stack 语义）。O(n+m) time / O(n+m) space
2. 追问一「倒过来扫会怎样」→ 先见 `#` 后见字符，没东西可 pop → **被迫改记账**：skip counter 记债清账。仍 O(n+m) space（串照建，且 build 出的是反串——用于比较无妨，要输出需 reverse）
3. 追问二「既然只是比较，何必存串」→ 丢掉 StringBuilder，双 pointer 当场比 → **O(1) space**

可迁移判断：**当操作只影响单侧（`#` 只删左边）时，从另一侧扫常能省掉辅助结构**（同族：LC88 从后往前填）。面试按 1→2→3 口述，两个追问自己说出来比直接甩最优解加分。
