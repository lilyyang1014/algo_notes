### 一刷 (7/28/2026) ❌ loop variable 声明了但 body 里从没用 + 暴力解撞 TLE

自己想出「右移 k 位 = 右移 1 位做 k 次」的分解，实现骨架也对，但 loop body 里把 pointer 写死了。我的代码：

```java
class Solution {
    public void rotate(int[] nums, int k) {
        while(k > 0){
            int temp = nums[nums.length - 1];        // ✅ 存住末位，这步对
            for(int right = nums.length-1; right >= 1; right--){
                nums[nums.length-1] = nums[nums.length-2];
                // ❌❌① 核心错误：right 有初值、有 condition、有 update statement，
                //    唯独 body 里不提它 → 这个 loop 不是「搬 n-1 次」，
                //    而是把同一句幂等赋值重复 n-1 次，第 2 轮起完全无效果
            }
            nums[0] = temp;
            k--;
        }
    }
}   // ❌② 整体 O(n·k)，n、k 都到 1e5 → 1e10，改对①之后仍 TLE（39/41）
```

**①的根因**：写 loop body 时脑子里想的是「末位那一格」这个**具体位置**，没切换到「第 right 格」这个**通用位置**。loop 的意义全在 loop variable 参与 body，不参与就等于把一句话说了 n 遍。

Dry run（`nums = [1,2,3,4,5], k = 1`）：

```
temp = nums[4] = 5
第 1 轮: nums[4] = nums[3] = 4   →  [1,2,3,4,4]
第 2~4 轮: 同一句，无变化
nums[0] = temp                   →  [5,2,3,4,4]
```

期望 `[5,1,2,3,4]`。3 被 4 覆盖、2 原地不动——不崩不越界的静默错误。

**②**：改成 `nums[right] = nums[right-1]` 后逻辑完全正确，41 个 case 过 39 个。**只挂最后一两个 = 复杂度不够，不是逻辑不对**；前几个就挂才是逻辑或边界问题。看挂在哪一段比看挂了几个有用。

**自测点**：①③ 已讲穿作废；② `k %= n` 在两种解法里的地位差别（承接到二刷）。

**自测点①答错（这是本轮的核心问题）**。问：改成左移 k 位，三次反转版怎么改？我答：

```java
reverse(nums, 0, n-1);
reverse(nums, 0, k);          // ❌❌ 第一段长度成了 k+1
reverse(nums, k+1, n-1);
```

**根因**：分割点落在 `k` 之后，第一段长度是 **k+1**，实际实现的是「右移 k+1 位」= 左移 **n−k−1** 位。只有当 `n−k−1 == k`，即 **n = 2k+1** 时才碰巧等于左移 k 位。我举的例子是 n=7, k=3——正好撞上这个退化情形。

**反例 `n=5, k=1`**（左移 1 位，期望 `[2,3,4,5,1]`）：

```
[1,2,3,4,5] → 整体反转 → [5,4,3,2,1]
reverse(0,1) → [4,5,3,2,1]
reverse(2,4) → [4,5,1,2,3]   ❌
```

**正确改法：分割点在 `n−k`。**

```java
reverse(nums, 0, n-1);
reverse(nums, 0, n-k-1);
reverse(nums, n-k, n-1);
```

### 核心思路（一句话）

**右移 k 位就是把 `[A|B]` 变成 `[B|A]`（B = 最后 k 个）——整体反转一次就把两块的位置换对了，只是各自内部倒了，再分别反转回来即可。**

整体反转顺手办了两件事：一件是要的（B 整段搬到前面），一件是不要的（每段内部倒序）。后两次反转专门撤销后者。所以是三次——1 次成事 + 2 次善后。

### 左移 k 位 = 右移 n−k 位（三刷的坎）

三条推法，任选一条能当场说出来即可：

1. **环**：n 个位置首尾相接，旋转就是在环上走。往左 k 步和往右 n−k 步落点相同，因为绕一圈是 n 步。
2. **下标算术**（最严格）：右移把 `i` 送到 `(i+k) mod n`，左移送到 `(i−k) mod n`。模 n 下 `−k ≡ n−k`，两个映射对每个下标都相同 → 同一个操作。
3. **逆运算**（最短）：记左移 k 为 `L(k)`、右移 k 为 `R(k)`。`L(k)` 后接 `L(n−k)` 走满一圈不变；`L(k)` 后接 `R(k)` 也不变。逆运算唯一 → `L(n−k) == R(k)`。

> **这一步的通用形态**：手上已有右移模板时，不要为左移重推一套，先问「能不能翻译成已有的那个」。和 34 的「最后一个 = target」翻译成 `L(target+1) − 1` 是同一个动作——**重推一套要重踩一遍边界，翻译只需验证一次转换关系。**

### 代码

**解法一：额外数组** —— O(n) time / O(n) space，几乎写不错，面试里先拿下正确性。

```java
class Solution {
    public void rotate(int[] nums, int k) {
        int n = nums.length;
        k %= n;                                 // 此版可省，(i+k)%n 已自带取余
        int[] newArr = new int[n];
        for (int i = 0; i < n; i++) {
            newArr[(i + k) % n] = nums[i];      // 在 i → 去 i+k；越界绕回开头
        }
        for (int i = 0; i < n; i++) {
            nums[i] = newArr[i];                // 必须逐格写回，见「沉淀」
        }
    }
}
```

`newArr[(i + k) % n] = nums[i]` 的三步推导：① 右移 k 位 = 位置 `i` → 位置 `i + k`（题面直译）② `i + k` 会越界 ③ rotate 语义要求绕回开头 = 取余。

**解法二：三次反转** —— O(n) time / O(1) space，follow-up 要的就是这个。

```java
class Solution {
    public void rotate(int[] nums, int k) {
        int n = nums.length;
        k %= n;                          // 正确性必需：k=7,n=5 时 reverse(0,6) 越界
        reverse(nums, 0, n - 1);         // [A|B] → [Bᴿ|Aᴿ]，位置已对，各自倒着
        reverse(nums, 0, k - 1);         // Bᴿ → B
        reverse(nums, k, n - 1);         // Aᴿ → A
    }
    private void reverse(int[] nums, int left, int right) {
        while (left < right) {           // 对撞 pointers，与 704 同骨架
            int temp = nums[left];
            nums[left] = nums[right];
            nums[right] = temp;
            left++;
            right--;
        }
    }
}
```

**三次之间的依赖关系**：后两次**顺序可换**——`[0, k-1]` 与 `[k, n-1]` 不相交，无数据依赖，先复位哪块都行；区间一旦重叠，顺序立刻变成关键。**第一次不能动**——后两次依赖「已整体翻转」这个前提。`k = 0` 时 `reverse(0, -1)` 安全，`left < right` 当场 false。

**第三种（知道即可）**：环状替换 cyclic replacement，同样 O(1) space，但要跑 `gcd(n, k)` 个环、数着搬运总数才知道停，极易死循环或漏元素。面试里主动说出「知道它存在、不选它因为实现风险高」比硬写一个带 bug 的版本得分高。

### 复杂度分析

**额外数组** —— Time: O(n)：两个独立 loop 各 n 轮。Space: O(n)：newArr。
**三次反转** —— Time: O(n)：三次 reverse 共搬约 n 格，**与 k 无关**。Space: O(1)：只有 left/right/temp。

对比暴力 O(n·k)（右移 1 位重复 k 次）：暴力把一个 O(n) 问题拆成 k 个 O(n) 子问题，分解本身没错，是**代价累加**。

### 沉淀

- **单个例子只能证伪，不能证明**（三刷的教训）：验证一个通用公式时，一个例子过了什么也说明不了——尤其当它是退化情形（n=2k+1、k=0、n=1）。要么给出推导，要么至少代两组**结构不同**的值。
- **dead loop variable 自检信号**：写完 loop 扫一眼 **body 里有没有出现 loop variable**。没有就问「那这个 loop 为什么要转 n 次」。合法例外只有 body 每轮结果不同但不依赖计数（读输入、pop 栈）。**数组题里 body 不提 loop variable，基本必错。**
- **不确定的那一行当场标 `??`，写完回头 dry run 结清**：不打断主线思路，又保证那一行不会蒙混过关。34 的 `<=`、844 的 `countS >= 0` 都是「语义在脑子里对、没接到 condition 那一行上」——`??` 就是在那一行上留个必须回头的记号。
- **写代码前把 constraint 代进复杂度**：n ≤ 1e5 时 O(n²) 和 O(n·k) 都是 1e10，出局；能过的是 O(n) / O(n log n)。**constraint 的量级是在告诉你答案的复杂度。**
- **`k %= n` 什么时候是必需**：判据是 **k 有没有被当成下标直接用**。被当下标用（三次反转的 `reverse(0, k-1)`）→ 必须先夹进 `[0, n)`，否则越界；只出现在 `(...) % n` 内部（额外数组版）→ 取余已兜底，写它只是卫生习惯。
- **Java 数组传参传的是引用**：`nums[i] = ...` 改元素调用方看得到；`nums = newArr` 只改局部引用指向，调用方**纹丝不动**。返回 void 的 in-place 题，结果留在临时数组里 = 什么都没做。测出来「数组没变化」不代表方案错了，先查有没有写回。
- **方向判据**：`newArr[(i+k)%n] = nums[i]` 是右移，`newArr[i] = nums[(i+k)%n]` 是左移。两行长得几乎一样，**问「+k 在描述去向还是来源」**，或拿第一个元素代一遍，五秒定方向。
- **看 TLE 提示里的参数**：如果超时信息带着某个参数的具体值（如 `k = 56846`），先问「我的解法耗时含不含这个参数」。不含 → 超时的一定不是这份代码。

### 引申：「重复 k 次同一个操作」怎么消掉 k

看到这类解法先问一句：**k 能不能被消掉？** 三条常见出路——找恒等式（189 的 `reverse(A+B) = reverse(B)+reverse(A)` 展开）、找周期性（旋转 n 次回原点，所以 `k %= n`）、换数据结构。重复 k 次是最朴素的分解，往往不是终点。

### Interview pitch (练口述)

> "The brute force is to rotate by one position k times, which is O(n·k). With n and k up to 1e5 that's 1e10 operations, so it won't pass. A simple linear solution uses an extra array: the element at index i moves to index (i + k) mod n, so I fill a new array in one pass and copy it back — O(n) time, O(n) space. Since the follow-up asks for O(1) extra space, I'd use the three-reversal trick. Rotating right by k means turning [A|B] into [B|A], where B is the last k elements. If I reverse the whole array I get B-reversed followed by A-reversed — the two blocks are already in the right place, just internally backwards — so reversing each block restores them. That's O(n) time, O(1) space. One thing to watch: k can exceed n, and here k is used directly as an index, so I have to take k mod n first or the reverse call goes out of bounds. If the problem asked for a left rotation instead, I'd reuse the same routine — rotating left by k is the same as rotating right by n minus k — and only the split point changes. There's also a cyclic-replacement solution with the same complexity, but it requires handling gcd(n, k) separate cycles and is much easier to get wrong."
