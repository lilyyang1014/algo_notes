### 一刷（日期待补）

当时用两个先后执行的 while loops 写对，但对「为什么只处理 nums2 的剩余部分」半懂不懂。

### 二刷 (9/22/2026) ❌ 忘记 backward merge，重写时混淆访问条件与结束条件

**卡在哪**：先想到插入，但插入会反复搬动 nums1 的有效 elements；提示「最大值」后，才想到利用末尾空位，从后往前填。

**真正的坎**：知道要检查 pointer，却没分清「这一侧还能不能取」和「整个合并能不能结束」。

#### ① 复制 + sorting：初始化和移动没对应起来

```java
if (nums2.length = null) return; // ❌ length 是 int；= 是 assignment
for (int i = m - 1; i < nums1.length; i++) { // ❌ 第一个空位是 m
    int j = 0; // ❌ 每轮重置，无法接着上轮继续复制
    while (j <= nums2.length - 1) {
        nums[i] = nums[j]; // ❌ nums 未定义，应为 nums1[i] = nums2[j]
        j++; // ❌ i 不动，反复覆盖同一格
    }
}
Arrays.sort(nums1);
```

改掉内层 while 后，仍把 `int j = 0` 留在 loop 内 → 每轮都复制 nums2[0]。

**根因**：跨 iteration 累积的 pointer 要在 loop 外初始化；**每复制一个 element，读取和写入位置都要推进。**

#### ② 从后往前填：pointer 变了，提前取出的值不会跟着变

```java
int l = m - 1, r = nums2.length - 1;
int a = nums1[l]; // ❌ m=0 时越界；l-- 后 a 也不会更新
int b = nums2[r]; // ❌ n=0 时越界；r-- 后 b 也不会更新

for (int i = nums1.length; i >= 0; i--) { // ❌ 最后一个 index 是 length-1
    if (a > b) {
        nums1[i] = a;
        l--;
    } else if (b >= a) { // 冗余：这里直接 else 即可
        nums1[i] = b;
        r--;
    }
}
```

**根因**：`a = nums1[l]` 保存的是当时的 int 值，不是与 l 的绑定。**每轮先确认 pointer 有效，再按当前 pointer 取值。**

例如 `[1,4,0,0]` 与 `[2,3]`：修正写入起点后，第一次取走 4，l 已移到 1，但 a 仍是 4 → 下一轮又填 4。

#### ③ 改写时又套了 while：i-- 执行得太晚

```java
for (int i = nums1.length - 1; i >= 0; i--) {
    while (r >= 0) {
        if (nums1[l] > nums2[r]) { // ❌ 没保护可能已为 -1 的 l
            nums1[i] = nums1[l];
            l--;
        } else {
            nums1[i] = nums2[r];
            r--;
        }
    } // ❌ 内层结束后才执行 i--，期间一直覆盖同一格
}
```

**根因**：每轮填一格，就要移动一次写入 pointer；**先后执行两个 loops 可以，嵌套后移动时机就变了。**

#### ④ ❌❌ 核心错误：防止越界，不等于完成合并

后来把整个 loop 的 condition 改成：

```java
r >= 0 && l >= 0 // ❌❌ 如果后面没有补写 nums2，会提前结束
```

反例 dry run：`nums1 = [4,0], m = 1; nums2 = [2], n = 1`

- 初始：l=0，r=0，i=1。
- 取 4 → nums1=[4,4]，l=-1，r=0，i=0。
- 两边都有效的 condition 不成立 → 退出，2 没写进去。

**这是静默错误：没有越界，但结果错了。**

**根因**：nums1 用完，只代表之后改取 nums2；nums2 用完，才代表可以结束。**loop condition 管「是否继续」，branch condition 管「这一轮取谁」。**

**自测点**：面试官问：nums1 和 nums2 都可能先用完，为什么两种情况的后续处理不同？

---

### 正确写法

从后往前取较大的 element，利用末尾空位，避免覆盖尚未处理的数据。

```java
class Solution {
    public void merge(int[] nums1, int m, int[] nums2, int n) {
        int l = m - 1, r = n - 1;

        for (int i = m + n - 1; r >= 0; i--) {
            // 先检查 l，&& short-circuit 保证不会读取 nums1[-1]
            if (l >= 0 && nums1[l] > nums2[r]) {
                nums1[i] = nums1[l];
                l--;
            } else {
                // 包括 nums1 已用完的情况
                nums1[i] = nums2[r];
                r--;
            }
        }
    }
}
```

**为什么 nums2 用完就能停？**

始终有 `i = l + r + 1`：每轮 i 减一，l 或 r 也恰好有一个减一。
当 r=-1 时，i=l → nums1 剩余部分就在正确位置，无需再搬。

旧版两个 while 也正确：先在两边都有效时比较，再单独复制 nums2 的剩余部分。

### 复杂度分析

**Time: O(m+n)**：每轮放好一个 element，最多处理 m+n 个。
**Space: O(1)**：只用三个 pointers，in-place。

对比复制后 sorting 的 O((m+n) log(m+n))：利用已有顺序，省去重新 sorting。

### 沉淀

- **初始化一次、每轮取值、每轮移动是三件事**：pointer 不该每轮重置，当前候选值却需要每轮重新读取。
- **for 的 condition 不必使用初始化的 variable**：i 管写到哪里，r 管是否继续，职责可以分开。
- **边界失效后，要判断是结束还是切换处理方式**，不能只靠加 condition 防越界。

> **自检信号**：写下 array[p]，先找保证 p 合法的 condition；看到 p--，再检查下一次读取是否仍被保护。最后 dry run：空 array、单个 element、两侧分别先用完。
