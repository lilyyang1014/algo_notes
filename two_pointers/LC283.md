### 一刷 (7/23/2026) ❌ condition 依赖 slow 位置，导致 slow 无法越过开头的非零段

```java
int slow = 0;
for (int fast = 1; fast < nums.length; fast++) {
    // ❌③ 在这个错误版本中，跳过 fast=0 恰好无影响，因为该轮 condition 恒 false；
    // 改成只判断 nums[fast] != 0 后，本版初始化要求 fast 从 0 起
    if (nums[slow] == 0 && nums[fast] != 0) {
        // ❌❌① 核心错误：只有 slow 停在 0 上才处理，
        // 没有逻辑让它越过开头的非零段 → [1,0,2] 全程空转
        int temp = nums[fast]; // ❌② 当前 assignment 顺序下，应保存 nums[slow]
        nums[slow] = nums[fast];
        nums[fast] = temp;     // ❌ 写回自身，0 消失、非零被复制
        slow++;
    }
}
```

**①的根因**：这个版本把 slow 的推进限制在「nums[slow] 是 0」时，却没有处理 slow 指向非零的情况。修正版本按 nums[fast] 是否非零决定保留，每保留一个就推进 slow。和 LC27 二刷同族：应推进的 pointer 没有推进，导致静默错误。

**②的根因**：执行 `nums[slow] = nums[fast]` 前，要先保存即将被覆盖的 nums[slow]，才能完成 swap。

### 两条 invariant

每轮开始时：

1. `[0, slow)`：已落位的非零 elements，顺序与原 array 一致。
2. `[slow, fast)`：已扫描但未放入非零前缀的部分，**全是 0**。

第二条解释了 swap 为什么安全：

- `slow < fast`：nums[slow] 必然是 0，swap 把这个 0 换到 fast 的位置。
- `slow == fast`：中间区间为空，只是自己和自己交换。

处理非零 element 后 slow++；处理 0 时 slow 不动。fast 每轮推进，所以这两个区间的含义始终保持。

### 正确写法

```java
class Solution {
    public void moveZeroes(int[] nums) {
        int slow = 0;

        for (int fast = 0; fast < nums.length; fast++) {
            if (nums[fast] != 0) {
                int temp = nums[slow];
                nums[slow] = nums[fast];
                nums[fast] = temp;
                slow++;
            }
        }
    }
}
```

开头是非零段时，slow == fast，swap 是自交换 no-op，两个 pointers 同步推进。本版 slow=0 的初始化要求 fast 从 0 开始，否则会漏掉第一个非零 element 对 slow 的推进。

可以用 `if (slow != fast)` 跳过自交换，但 slow++ 仍需执行。

### 复杂度分析

**Time: O(n)**：fast 扫描 n 个 elements，每轮 O(1)。
**Space: O(1)**：in-place swap，只使用固定数量的额外 variables。

对比把非零 elements 复制到新 array 再补 0 的做法，省掉 O(n) 额外空间。

### 引申：为什么非零 elements 保序

**fast 按原顺序发现非零 elements，slow 按相同顺序把它们依次写入前缀。**

swap 换回 fast 位置的是 0，或发生自交换，不会把其他非零 element 移到未扫描区，因此不会打乱后续读取顺序。

反向变体中，两个 pointers 都从 n−1 开始，先遇到的右侧非零先放到右侧，仍然保序，只是 0 聚到前端。

不能仅凭「扫描和写入方向相同」判断所有 in-place 算法都保序，还要确认写入不会破坏尚未读取的数据。

### 沉淀

- **本版 condition 看 fast，写入用 slow**：每发现一个非零 element 就保留并推进 slow，不能让 slow 因当前值非零而卡住。
- **swap 前保存将被覆盖的值**：当前 assignment 顺序下，temp 保存 nums[slow]。
- **写入与推进成对**：保留一个非零 element 后推进 slow；即使是自交换，也不能漏 slow++。
- **检查中间区间的含义**：本题 `[slow, fast)` 全是 0，这是 swap 安全的依据。
- **swap 不是唯一解法**：也可以先依次覆盖写入非零 elements，再把剩余位置统一填 0；只覆盖、不补零不完整。

> **自检信号**：分别用「开头非零」和「开头为零」的例子，检查 slow 是否正确推进；每次 swap 前，确认被换回 fast 的是什么。

### 关联

- LC27：同族历史错误——应推进的 pointer 在某个 branch 中没有推进，导致卡住或空转。
- LC26 / LC80：同一套扫描与写入分工，但保留 condition 不同。
- LC26 / LC27：只要求有效前缀；LC283 还要求尾部全是 0，因此必须通过 swap 或补零维护完整结果。
