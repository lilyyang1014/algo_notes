### 一刷 (7/23/2026) ❌ 分支判断依赖了 slow 位置的中间状态，而不是 fast 读到的原始数据

```java
int slow = 0;
for (int fast = 1; fast < nums.length; fast++) {
    //   ❌③ 本版恰好无害（fast=0 轮 condition 恒 false），但标准写法必须从 0 起
    if (nums[slow] == 0 && nums[fast] != 0) {
        // ❌❌① 核心错误：condition 看了 nums[slow] → slow 只能停在 0 上才干活，
        //       没人推它越过开头的非零段 → [1,0,2] 全程空转，原样输出（静默错误）
        int temp = nums[fast];   // ❌② swap 手误：temp 该存将被覆盖的 nums[slow]
        nums[slow] = nums[fast];
        nums[fast] = temp;       //    → nums[fast] 写回自己，0 消失、非零被复制
        slow++;
    }
}
```

**①的根因**：分工是 fast 读、slow 写，`nums[0..slow)` 是算法自己维护的输出区。**分支判断只能依赖 fast 读到的原始数据**，拿输出区当输入 = 让算法依赖自己的中间产物。和 27 二刷同族（那次是 fast 没人推进），现象都是 pointer 卡死 + 静默错误。

**②**：swap 三行的经典手误，temp 的唯一使命是保住那个即将被覆盖的值。

### 两条 invariant（283 的实质）

1. `[0, slow-1]`：已落位的非零，顺序与原数组一致
2. `[slow, fast-1]`：**全是 0**（每个非零都被换到 slow 并推进 slow，中间夹的只可能是 0）

第 2 条是 swap 安全的前提：`nums[slow]` 里装的必然是 0（或 `slow == fast` 时是它自己），换过去等于把一个 0 送到后面，不会毁数据。**26/27 只需第 1 条，283 需要两条**——这是它在族里的实质差异。

### 正确写法

```java
public void moveZeroes(int[] nums) {
    int slow = 0;
    for (int fast = 0; fast < nums.length; fast++) {  // 从 0 起
        if (nums[fast] != 0) {          // 只看 fast 读到的原始值
            int temp = nums[slow];      // temp 存将被覆盖的 nums[slow]
            nums[slow] = nums[fast];
            nums[fast] = temp;          // 0 被换到 fast 的位置
            slow++;
        }
    }
}
```

开头是非零段时 `slow == fast`，swap 是自交换 no-op，两个 pointer 同步推进——这就是 fast 必须从 0 起的原因。加 `if (slow != fast)` 可省掉这些空操作，但多一层嵌套，留着当面试里「还能优化吗」的现成答案。

### 复杂度分析

**Time: O(n)**：fast 每轮必进一格，恰好 n 轮，每轮 O(1)。
**Space: O(1)**：in-place swap，只有 slow / fast / temp。

对比额外数组做法（非零抄进新数组再补 0）：省掉 O(n) space，且同样天然保序。

### 引申：这类 in-place 重排为什么保序

**扫描方向与写入方向一致 → 保序。** 正向版里先遇到的（更靠左的）非零先写在更左边；反向变体（两个 pointer 都从 `n-1` 起）里先遇到的（更靠右的）先写在更右边，同样保序，只是 0 聚到了前端。**两个方向不一致时**（如 fast 左→右扫、slow 右→左写）非零整体倒序。判断这类快慢 pointer 是否 stable，看这一条就够。

### 沉淀

- **slow/fast 铁律：判断看 fast，写入用 slow**——拿输出区当分支依据，invariant 直接崩
- **swap 的 temp 存「将被覆盖的值」**：三行写完 dry run 两个 element 验一遍
- **写 + 推进必须成对**：swap/覆盖之后紧跟 `slow++`，漏一个等于没处理这个 element
- **快慢 pointer 类题目，唯一要盯的是「两个 pointer 夹出的中间段装什么」**——26/27/80/283 各不相同，每题都得能一句话说出来
- **pointer 卡死一族的信号**：输出与输入一模一样（空转），或某段被复制（单侧推进）→ 先查每个分支里该动的 pointer 有没有人推

### 关联

- 27（同族核心错：某个 pointer 在分支里没人推进 → 卡死/空转）
- 26 / 80（同一套 slow/fast 骨架，只是 condition 不同；283 特殊在用 swap 而非覆盖，因为 0 要保留）
