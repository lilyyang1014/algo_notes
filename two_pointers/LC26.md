### 三刷 (7/23/2026) ❌ slow 表示最后确认位置，return 漏了 +1

和 LC27 同天连刷，loop body 正确，只错 return：

```java
int slow = 0;
for (int fast = 1; fast < nums.length; fast++) {
    if (nums[fast] != nums[slow]) {
        slow++;
        nums[slow] = nums[fast];
    }
}
return slow; // ❌ slow 是最后确认位置的 index，应返回 slow + 1
```

**根因**：这版 slow 从 0 开始、先加后写，表示最后一个已保留位置；却沿用了 LC27「slow 是 count」的 return。

当时改为 slow=1、写后加，统一成 next write position。**旧版算法本身可以成立，错的是 return 与 pointer 含义不一致。**

### 六刷 (9/23/2026) assignment 方向写反，思路与初始化正确

独立解释：nums[0] 已保留，fast、slow 都从 1 开始，分别表示待检查和待写入位置。

```java
int slow = 1;
for (int fast = 1; fast < nums.length; fast++) {
    if (nums[fast] != nums[slow - 1]) { // 正确：与最后一个已保留值比较
        nums[fast] = nums[slow];       // ❌ 方向反了，应 nums[slow] = nums[fast]
        slow++;
    }
}
return slow;
```

**反例 dry run**：`[1,1,2]`。到 fast=2、slow=1 时发现新值 2，却执行 `nums[2]=nums[1]` → array 变成 `[1,1,1]`；返回 2，但有效前缀错误。

**本轮判断**：去重 condition、初始化、slow 的含义和 return 都正确，是局部 assignment 失误；提示核对左右职责后自行识别，不作为核心思路退步。尚未回报修正版测试结果。

> **自检信号**：读 assignment 时按「左边是目的地，右边是来源」检查：slow 待写、fast 待读，所以 nums[slow] = nums[fast]。

### 正确写法

**slow 是下一个待写入位置，`[0, slow)` 是已去重的有效前缀。**

```java
class Solution {
    public int removeDuplicates(int[] nums) {
        int slow = 1; // 本题保证非空，nums[0] 已保留

        for (int fast = 1; fast < nums.length; fast++) {
            if (nums[fast] != nums[slow - 1]) {
                nums[slow] = nums[fast];
                slow++;
            }
        }
        return slow;
    }
}
```

### 为什么这样初始化和比较

- **slow=1**：第一个 element 已保留，已有 1 个有效值，下一格写在 index 1。
- **fast=1**：index 0 已处理，从下一格开始检查。
- **比较 nums[slow-1]**：它是最后一个已保留值；array 已 sorted，当前值与它不同才需要保留。
- **return slow**：有效区间是 `[0, slow)`，长度为 slow。

旧版 `nums[fast] != nums[fast-1]` 也正确，用来识别一个新值的开始。两种比较方式都能配合 next write position，**不必为了保持 slow 的含义而强制只用其中一种。**

### 复杂度分析

**Time: O(n)**：fast 扫一遍，每轮 O(1)。
**Space: O(1)**：只使用两个 pointers，in-place。

### 沉淀

- **先定义 pointer，再定 return**：next write position 对应 count；最后确认位置对应 index，不能混用。
- **读写方向固定**：fast 提供候选值，slow 接收写入；保留时写入并 slow++，否则只推进 fast。
- **比较已确认的数据**：当前版本最后一个保留值是 nums[slow-1]；nums[slow] 尚不属于有效前缀。
- **初始化也属于 invariant**：不能只凭「先写后加」判断 return，必须一起核对起点与有效区间。

### 关联

- LC27：同样是 fast 扫描、slow 待写；没有预先保留的 element，所以 slow 从 0 开始。
- LC80：同一套读写分工，但允许保留的重复次数不同；count 是一种实现方式，并非必需。
- LC69 / LC34：退出时 pointer 的含义决定返回什么，不能凭记忆猜 return。
