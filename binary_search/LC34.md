### 核心思路（一句话）

**只写 `L(x)` = 第一个 ≥ x 的下标，调用两次：** 左边界 = `L(target)`，右边界 = `L(target+1) - 1`。

### 右边界为什么是 `L(target+1) - 1`

手上只有「找第一个 ≥ x」这个工具，它只找区域的**左**边缘，所以把「最后一个 = target」翻译过去：

整数上 `> target` ⇔ `≥ target+1`，所以 `L(target+1)` = 第一个 > target 的位置，退一格 = 最后一个 ≤ target。

> 直觉：没法直接问「最后一个 8 在哪」，但可以问「第一个比 8 大的在哪」，然后退一格。
> **「最后一个 X」= 「第一个 > X 的位置」- 1**

`nums = [5,7,7,8,8,8,10]`, target=8：`L(8)` = 3 ✅，`L(9)` = 6 → `6-1 = 5` ✅

### 代码

```java
class Solution {
    public int[] searchRange(int[] nums, int target) {
        int start = find(nums, target);                  // first >= target
        // find 的值域是 [0, n]，n 不是合法下标 → 必须先挡住再访问；|| 短路，顺序不能反
        if (start == nums.length || nums[start] != target) {
            return new int[]{-1, -1};
        }
        int end = find(nums, target + 1) - 1;            // (first >= target+1) - 1 = last <= target
        return new int[]{start, end};
    }

    // 唯一的模板：第一个 >= target 的下标；不存在则返回 nums.length
    private int find(int[] nums, int target) {
        int left = 0, right = nums.length - 1;           // 闭区间 → while 用 <=
        while (left <= right) {
            int mid = left + (right - left) / 2;         // 防 overflow
            if (nums[mid] < target) {                    // = 归 right 这侧 → left 不跳过等于的
                left = mid + 1;
            } else {                                     // nums[mid] >= target
                right = mid - 1;
            }
        }
        return left;
    }
}
```

### 沉淀：边界映射速查（只用 L）

**`L(x)` = 第一个 ≥ x 的下标。值域 `[0, n]`——n 表示「没有 ≥ x 的」。**

| 要找      | 写法           |
| --------- | -------------- |
| first ≥ x | `L(x)`         |
| first > x | `L(x + 1)`     |
| last ≤ x  | `L(x + 1) - 1` |
| last < x  | `L(x) - 1`     |

**不用背，两条规则当场推：**

1. **看符号定 x**：`≥` / `<` 用 `x`；`>` / `≤` 用 `x + 1`（进一档，整数上 `> x` ⇔ `≥ x+1`）
2. **看 first/last 定尾巴**：`first` 不动，`last` 一律 `-1`——**last 只会 `-1`，绝不会 `+1`**

### 沉淀：`==` 归哪一侧就是 L/U 的开关

两分支穷尽了全部关系，`==` 没有独立位置，只能归队。**归哪边决定你拿到哪个 primitive：**

| `nums[mid] == target` 时                    | condition             | left 停在          |
| ------------------------------------------- | --------------------- | ------------------ |
| 归 right（`right = mid - 1`，继续往左收）   | `nums[mid] < target`  | 第一个 `≥` = **L** |
| 归 left（`left = mid + 1`，跳过所有等于的） | `nums[mid] <= target` | 第一个 `>` = **U** |

**换算 `U(x) = L(x + 1)`**——看题解遇到 U 版时按这条折算，不要跟着换底。

**取反动作的适用边界**：`predicate 对 index 单调`（真真真假假假）+ `left 只在 condition 为真时前进`，两条都满足才成立。旋转数组（33/153）的 `nums[mid] >= nums[left]` 不单调，取反出来没有指向——那类题的 left/right 只承载「答案在哪半边」。

### 沉淀：其他

- **拿返回值访问元素前永远先查越界**——值域 `[0, n]` 比合法下标多一格，**作为「位置」永远有效，作为「下标」不一定有效**。四刷栽在这里
- **假 guard 比没 guard 更危险**：guard 的位置必须早于它要防的那次访问
- **overflow**：L 版怕 `target = Integer.MAX_VALUE`（`x+1` 溢出）。本题 constraint `-10^9 ~ 10^9`，安全
- 一个 primitive 打通这一类：704（查存在）、35（`L(target)` 直接就是答案）、34（本题）
- Time: O(log n) / Space: O(1)

### Interview pitch

> "I use a single helper — a lower bound that returns the first index where nums[i] is at least x. The left boundary is that helper called on target directly. For the right boundary I reuse the same helper by shifting the argument: on integers, greater-than-target is the same as at-least-target-plus-one, so the first index past the target range is lowerBound of target plus one, and stepping back one gives the last occurrence. One template instead of two. Before indexing with the result I guard it — the return value ranges over zero to n inclusive, so n itself isn't a valid index, and if the value there isn't the target then the target doesn't exist. O(log n) time, O(1) space."
