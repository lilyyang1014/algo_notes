**思路层面 ✅**：两次 lowerBound、`target+1` 再 -1、存在性检查——框架完全记住了，独立写出来的。我的代码（错误点标在旁边）：

```java
class Solution {
    public int[] searchRange(int[] nums, int target) {
        int left = lowerBound(nums, target);
        if (left == nums.length || nums[left] != target) return int[]{-1,-1};  // ❌ 缺 new
        int right = lowerBound(nums, target + 1) - 1;
        return int[]{left, right};   // ❌ 同上，缺 new
    }

    private int[] lowerBound(int nums, int target){
        //      ↑❌ 返回类型应是 int（返回的是下标，不是数组）
        //                    ↑❌ 参数应是 int[] nums
        int left = 0, right = nums.length - 1;
        while (left <= right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] < target) {
                left = mid + 1;
            } else if (nums[mid] > target) {
                rifht = mid - 1;      // ❌ 拼写：right
            } else {
                return mid;           // ❌❌ 核心错误：lowerBound 绝不能在相等时提前返回！
                                      //    它承诺的是「第一个 ≥ target」，提前返回只是「某一个 target」，
                                      //    不保证是第一个。把 704「找到就返回」的习惯带过来了。
            }
        }
        return left;
    }
}
```

**为什么 `return mid` 是错的 —— 反例 `nums = [8,8,8]`, target = 8**：

- left=0, right=2 → mid=1, `nums[1]==8` → 直接 return 1
- 但左边界应该是 **0**，返回了 1 ❌
- 更隐蔽的是：主函数 `nums[1]==8` 检查照样通过，不报错，最终返回 `[1,2]`，正确答案是 `[0,2]`——**静默错误，不会崩，只会答案错**

**正解**：相等时不返回，和 `>` 一起归到 `right = mid - 1`，继续往左压。这就是二刷笔记里那句「**`=` 归到 right 这侧 → left 不跳过等于的**」。

> **自检信号**：写 lowerBound 时如果出现了 `== target` 的分支，基本就写错了。它天然是**两个分支**，不是 704 那种三分支——因为 `=` 必须和 `>` 站一队，没有单独的位置。（这条对 U 版同样成立。）

**注**：存在性检查那行三刷是**对的**（只错在缺 `new`），边界检查本身完整。

### 核心思路（一句话）

**只写一个 `U(x)` = 第一个 > x 的下标，调用两次：** 左边界 = `U(target - 1)`，右边界 = `U(target) - 1`。

### 两个端点为什么这么写（推导）

手上只有「找第一个 **>** x」这一个工具。它天生只找区域的**右**边缘，那就把两个需求都翻译成它：

**左边界 = 第一个 ≥ target**
整数上 `≥ target` ⇔ `> target - 1`，所以退一档代入 → `U(target - 1)`。

**右边界 = 最后一个 ≤ target**
`U(target)` 是第一个 > target 的位置，往回退一格就是最后一个 ≤ target → `U(target) - 1`。

> 直觉：没法直接问「最后一个 8 在哪」，但可以问「第一个比 8 大的在哪」，然后退一格。
> **「最后一个 X」= 「第一个 > X 的位置」- 1**

例：`nums = [5,7,7,8,8,8,10]`, target = 8

- `U(7)` = 3（第一个 > 7）→ 左边界 ✅
- `U(8)` = 6（值 10 的下标）→ `6 - 1 = 5` → 右边界 ✅

### 代码

```java
class Solution {
    public int[] searchRange(int[] nums, int target) {
        int start = find(nums, target - 1);              // first > target-1 = first >= target
        // start 的值域是 [0, n]，n 不是合法下标 → 必须先挡住再访问；|| 短路，顺序不能反
        if (start == nums.length || nums[start] != target) {
            return new int[]{-1, -1};
        }
        int end = find(nums, target) - 1;                // (first > target) - 1 = last <= target
        return new int[]{start, end};
    }

    // 唯一的模板：返回第一个 > target 的下标；不存在则返回 nums.length
    private int find(int[] nums, int target) {
        int left = 0, right = nums.length - 1;           // [left, right] 闭区间 → while 用 <=
        while (left <= right) {
            int mid = left + (right - left) / 2;         // 防 overflow 的写法
            if (nums[mid] <= target) {                   // = 归到 left 这侧 → 跳过所有等于的
                left = mid + 1;
            } else {                                     // nums[mid] > target
                right = mid - 1;
            }
        }
        return left;   // index of first element > target; ranges over [0, n], n means "none exists"
    }
}
```

### 那行存在性检查为什么必须写、且顺序不能反

- `find` **一定会返回一个数**，它是「分界线」，合法范围 `[0, nums.length]`——右端比最大下标多一格。所以返回值**作为「位置」永远有效，作为「下标」不一定有效**
- `start == nums.length`：所有元素都 ≤ target-1，分界线落在数组末尾之外 → 直接 `nums[start]` 越界崩溃
- `nums[start] != target`：没越界，但指向的值 > target，说明 target 不存在，start 只是插入缝隙
- **顺序不能反**：`||` 短路，越界时直接返回、不会执行 `nums[start]`
- 这行还守住一个前提：**target 存在**时，「最后一个 ≤ target」才等于「最后一个 = target」

### 沉淀：边界映射速查（只用 U = upperBound）

**`U(x)` = 第一个 > x 的下标。值域 `[0, n]`——n 表示「不存在比 x 大的」。**

| 要找      | 写法           |
| --------- | -------------- |
| first > x | `U(x)`         |
| first ≥ x | `U(x - 1)`     |
| last ≤ x  | `U(x) - 1`     |
| last < x  | `U(x - 1) - 1` |

**不用背，两条规则当场推：**

1. **看符号定 x**：`>` / `≤` 用 `x`；`≥` / `<` 用 `x - 1`（退一档，因为整数上 `≥ x` ⇔ `> x-1`）
2. **看 first/last 定尾巴**：`first` 不动；`last` 一律 `-1`（最后一个满足 = 第一个不满足的前一格）
   → **last 只会 `-1`，绝不会 `+1`**

本题即：左边界 = first ≥ target = `U(target - 1)`；右边界 = last ≤ target = `U(target) - 1`。

**`=` 在 U 里归 left 这侧**——`nums[mid] <= target → left = mid + 1`，必须跳过所有等于的，才能停在第一个真正大于的位置。（与 L 相反：L 里 `=` 归 right，才不跳过等于的。）两分支，没有第三支——**出现 `== target` 分支基本就写错了**。

### 沉淀：两个 primitive 互为对偶

- `L(x)` = first ≥ x，`U(x)` = first > x
- 换算：`U(x) = L(x + 1)`，`L(x) = U(x - 1)`
- **选定一个作底，另一个全靠平移 ±1 得到，不需要第二套模板**
- 偏移方向随 primitive 反转：以 L 为底找 `>` 用 `x+1`；以 U 为底找 `≥` 用 `x-1`。**方向搞反是这类题最常见的翻车点**——判据是「往哪边跨一档才能让符号变成 primitive 自带的那个」
- **overflow 风险也镜像**：L 版怕 `target = Integer.MAX_VALUE`（`x+1` 溢出成 MIN_VALUE），U 版怕 `target = Integer.MIN_VALUE`（`x-1` 溢出成 MAX_VALUE）。本题 constraint 是 `-10^9 ~ 10^9`，安全；无 constraint 保证时要挡

### 沉淀：其他

- 一个 primitive 打通二分这一类：704（查存在）、35（插入位置 = `U(target-1)` 或 `L(target)`）、34（本题）
- **拿返回值访问元素前，永远先查越界**——值域 `[0, n]` 比合法下标多一格，**作为「位置」永远有效，作为「下标」不一定有效**。四刷栽在这里
- **假 guard 比没 guard 更危险**：`nums == null` 写在 `find` 调用之后永不生效。判据：**guard 的位置必须早于它要防的那次访问**
- Time: O(log n) / Space: O(1)

### Interview pitch (练口述)

> "I use a single helper that returns the first index where nums[i] is strictly greater than x — an upper bound. The right boundary is straightforward: the first index greater than target, minus one, gives the last index that's at most target. For the left boundary I reuse the same helper by shifting the argument: on integers, at-least-target is the same as greater-than-target-minus-one, so lowerBound is just upperBound of target minus one. That way I only maintain one search template instead of two. Before indexing with the result I have to guard it — the helper's return value ranges over zero to n inclusive, so n itself is not a valid index, and if the value there isn't the target then the target doesn't exist. O(log n) time, O(1) space."
