### 五刷 (8/4/2026) ❌❌ 调用处用 L 版、condition 用 U 版

四刷的越界检查已修复。错在 primitive 串线：

### 六刷 (8/6/2026) ❌❌ 存在性检查的连接词

**进步**：condition 写 `<`、注释写 first ≥ target、调用处按 L 版用——**三者第一次完全对上账**，四刷五刷的错都没再犯。


- **该拦的漏了**：`[5,7,7,8,8,10]`, target=6 → L(6)=1 未越界 → 整个条件 false → 算出 `[1, 0]` 这个左 > 右的垃圾区间。静默。

改 `||` 两个问题一起消失，**顺序不能反**——`||` 的短路正是「guard 必须早于它要防的那次访问」在这一行的形态；`||` 版还顺手兜住空数组（L 返回 0，`0 >= 0` 直接短路）。

**归族**：和同日 LC844 的 `countS >= 0` 同族——**语义对，翻译成布尔表达式时接错**。

**自测点：①对 ②错**。② 问 `findLast` return 谁，答 `return left`，理由「第一个 > target 等价于最后一个 ≤ target」——**概念叫对了，挂错了变量**，两者差一格，后者是 `left - 1` 即退出时的 `right`。

### 七刷 (8/11/2026) ⚠️ 代码全对，口答框架错

**代码一次写对，六刷五刷的错均未再犯**：condition 写 `<` 且注释对上账、存在性检查写 `||` 且顺序正确、`target+1` 技巧和 `return left` 都对。

**自测点：②对 ①错**。② 顺序为什么不能反——因果链完整（L 的值域含 `nums.length`，不是合法下标，所以越界检查必须先短路）。

**① 答成「`&&` 取反是 `||`」，两层都错**：

1. **德摩根律记漏了一半**：正确是 `!(A && B) == !A || !B`——连接符翻转的同时**两个操作数也各自取反**。
2. **更关键：这题根本不是取反问题。** `A && B` 与 `A || B` 是两个不同的判断，不是同一判断的正反面。

> **正确的提问不是「怎么取反」，是「这件事有几种独立成因，它们是并列还是叠加」。** 「不存在」有两种成因——越界一种、值不对一种，**各自单独成立即可**，所以是「或」。用 `&&` 会要求两条同时满足 → 漏判。
> **存在性检查几乎永远是 `||`**（出界要拦、值不对也要拦）。

**两个边界观察**（不算错）：① `nums == null` 未覆盖空数组，靠下游 `left == nums.length` 隐式兜住——**正确性隐式耦合在相隔几行的判断上**，同 LC45 / LC55 那族，已第三次 ② `target + 1` 在 `target == Integer.MAX_VALUE` 时 overflow，本题约束下安全，面试常见追问（规避方式是不走 `target+1`，直接写 U 版）。

> **⚠️「循环外的判断」第四次掉线**：7/30 LC704 口答说反 → 8/4 LC34 代码写反 → 8/6 LC34 口答说反 → 8/11 LC34 口答框架错。
> **新归因**：不是「知识在笔记里没接到决策上」，而是**习惯用形式规则（取反、模板）代替语义推导**。形式规则记错一个字就全错，语义推导错不了。
> **对策**：遇到边界 / 连接词的判断，先问「这在语义上是什么」，再落成符号。拿具体反例把每个操作数单独代进去验一遍。

### 核心思路（一句话）

**只写 `L(x)` = 第一个 ≥ x 的下标，调用两次：** 左边界 = `L(target)`，右边界 = `L(target+1) - 1`。

### 右边界为什么是 `L(target+1) - 1`

手上只有「找第一个 ≥ x」，它只找区域的**左**边缘，所以把「最后一个 = target」翻译过去：整数上 `> target` ⇔ `≥ target+1`，`L(target+1)` = 第一个 > target 的位置，退一格 = 最后一个 ≤ target。

> 直觉：没法直接问「最后一个 8 在哪」，但可以问「第一个比 8 大的在哪」，然后退一格。
> **「最后一个 X」= 「第一个 > X 的位置」- 1**

`nums = [5,7,7,8,8,8,10]`, target=8：`L(8)` = 3 ✅，`L(9)` = 6 → `6-1 = 5` ✅

### 代码

```java
class Solution {
    public int[] searchRange(int[] nums, int target) {
        int start = find(nums, target);                  // first >= target
        // find 值域是 [0, n]，n 不是合法下标 → 必须先挡住再访问；|| 短路，顺序不能反
        if (start == nums.length || nums[start] != target) {
            return new int[]{-1, -1};
        }
        int end = find(nums, target + 1) - 1;            // (first >= target+1) - 1 = last <= target
        return new int[]{start, end};
    }
    // 唯一的模板：第一个 >= target 的下标；不存在则返回 nums.length
    private int find(int[] nums, int target) {
        int left = 0, right = nums.length - 1;           // 闭区间 → while 用 <=
        while (left <= right) {
            int mid = left + (right - left) / 2;         // 防 overflow
            if (nums[mid] < target) {                    // = 归 right 这侧 → left 不跳过等于的
                left = mid + 1;
            } else {                                     // nums[mid] >= target
                right = mid - 1;
            }
        }
        return left;
    }
}
```

### 沉淀：边界映射速查（只用 L）

**`L(x)` = 第一个 ≥ x 的下标。值域 `[0, n]`——n 表示「没有 ≥ x 的」。**

| 要找      | 写法           |
| --------- | -------------- |
| first ≥ x | `L(x)`         |
| first > x | `L(x + 1)`     |
| last ≤ x  | `L(x + 1) - 1` |
| last < x  | `L(x) - 1`     |

**不用背，两条规则当场推：**

1. **看符号定 x**：`≥` / `<` 用 `x`；`>` / `≤` 用 `x + 1`（整数上 `> x` ⇔ `≥ x+1`）
2. **看 first/last 定尾巴**：`first` 不动，`last` 一律 `-1`——**last 只会 `-1`，绝不会 `+1`**

### 沉淀：`==` 归哪一侧就是 L/U 的开关

两分支穷尽了全部关系，`==` 没有独立位置，只能归队。**归哪边决定你拿到哪个 primitive：**

| `nums[mid] == target` 时      | condition             | left 停在          | right 停在（= left-1） |
| ----------------------------- | --------------------- | ------------------ | ---------------------- |
| 归 right（`right = mid - 1`） | `nums[mid] < target`  | 第一个 `≥` = **L** | 最后一个 `<`           |
| 归 left（`left = mid + 1`）   | `nums[mid] <= target` | 第一个 `>` = **U** | 最后一个 `≤`           |

**退出时恒有 `right = left - 1`**（闭区间 + `while (left <= right)` 的交错性质）。**要「第一个…」return `left`，要「最后一个…」return `right`**——六刷答错的就是这一格。

**换算 `U(x) = L(x + 1)`**——看题解遇到 U 版时按这条折算，不要跟着换底。

**取反动作的适用边界**：`predicate 对 index 单调` + `left 只在 condition 为真时前进`，两条都满足才成立。旋转数组（33/153）的 `nums[mid] >= nums[left]` 不单调，取反出来没有指向——那类题的 left/right 只承载「答案在哪半边」。

### 沉淀：其他

- **拿返回值访问元素前永远先查越界**——值域 `[0, n]` 比合法下标多一格，**作为「位置」永远有效，作为「下标」不一定有效**。四刷栽在这里，六刷栽在同一行的连接词上
- **假 guard 比没 guard 更危险**：guard 的位置必须早于它要防的那次访问；`||` 的短路就是这条在代码里的落实
- **overflow**：L 版怕 `target = Integer.MAX_VALUE`（`x+1` 溢出）。本题 constraint `-10^9 ~ 10^9`，安全
- 一个 primitive 打通这一类：704（查存在）、35（`L(target)` 直接就是答案）、34（本题）
- Time: O(log n) / Space: O(1)

### Interview pitch

> "I use a single helper — a lower bound that returns the first index where nums[i] is at least x. The left boundary is that helper called on target directly. For the right boundary I reuse the same helper by shifting the argument: on integers, greater-than-target is the same as at-least-target-plus-one, so the first index past the target range is lowerBound of target plus one, and stepping back one gives the last occurrence. One template instead of two. Before indexing with the result I guard it — the return value ranges over zero to n inclusive, so n itself isn't a valid index, and if the value there isn't the target then the target doesn't exist. O(log n) time, O(1) space."
