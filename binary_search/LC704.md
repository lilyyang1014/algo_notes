### 二刷 (7/21/2026) ❌ boundary update 未利用 mid + 缺 loop 外 return

```java
int mid = (right + left) / 2; // ❌③ 通用写法有 overflow 风险
if (nums[mid] > target) {
    right = right - 1;       // ❌① 应 mid - 1，只缩一格会退化成 O(n)
} else if (nums[mid] < target) {
    left = left + 1;         // ❌① 应 mid + 1
} else if (nums[mid] == target) {
    return mid;
} else {
    return -1;              // ❌④ dead code：前面已覆盖全部情况
}
// ❌② 缺 return -1：未找到时没有返回值，编译失败
```

**根因**：sorted array 允许一次排除 mid 及其一侧，boundary update 必须利用 mid，才能持续缩小约一半的搜索范围。

**根因**：`<=` 和 `mid ± 1` 使用闭区间 `[left, right]`，但 right 初值包含了非法 index n。

**反例 dry run**：`nums=[5]`, target=6。初始 `(left,right)=(0,1)` → mid=0 → left=1 → 再进入 loop，mid=1 → `nums[1]` 越界。

本轮另两处理解已纠正：

- state 主要是 left / right 表示的候选范围；mid 是每轮计算的检查位置。
- Time 是 O(log n)，不是 O(n log n)：每轮工作量为 O(1)，范围持续减半。

**自测点口答**：为什么 `left == right` 仍要进入 loop？答：「还剩一个位置，要进去看这个位置行不行。」已理解；该问题已讲穿，不再作为下次独立验收题。

### 正确写法

```java
class Solution {
    public int search(int[] nums, int target) {
        int left = 0, right = nums.length - 1;

        while (left <= right) {
            int mid = left + (right - left) / 2;

            if (nums[mid] == target) {
                return mid;
            } else if (nums[mid] < target) {
                left = mid + 1;
            } else {
                right = mid - 1;
            }
        }
        return -1;
    }
}
```

### 复杂度分析

**Time: O(log n)**：候选范围持续减半，每轮 O(1)。
**Space: O(1)**：只使用固定数量的 local variables。

对比 linear search O(n)：sorted array 允许一次排除一整段候选位置。

### 沉淀

- **闭区间是一整套约定**：right 从 n-1 开始，`left <= right` 表示还有候选；排除 mid 后用 `mid ± 1` 更新。
- **维护的是候选范围**：如果 target 存在，它必须仍在 `[left, right]` 内。
- **正常退出时 `left = right + 1`**：最后一次 update 跨过剩余的候选位置，区间变空；不是每轮只移动一格。
- **index 与 value 分开**：left 可能到 n，right 可能到 -1；访问 array 前先检查范围。
- **能否提前 return，取决于命中是否已确定答案**：704 可以；LC34 找 first / last 时还需继续搜索。LC35 的 array 无重复，命中时也可以直接返回 mid。

### Edge cases

- `[5]`, target=5 → 0：单个 element 命中。
- `[5]`, target=6 → -1：单个 element 不匹配。
- `[2,5]`, target=2 / 5 → 0 / 1：两个端点。
- `[2,5]`, target=3 → -1：范围内不存在。
- `[2,5]`, target=1 / 6 → -1：范围外不存在。

LC704 保证 array 非空。

### 关联

- LC34：查找 first / last，命中后仍需继续收缩。
- LC35：未命中时，插入位置是退出后的 left。
- LC69：取符合其搜索判据的最后一个合法候选 right。
- LC367：同样需要区分 index、value 与计算结果。
