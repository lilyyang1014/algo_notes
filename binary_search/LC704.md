## 704. Binary Search

Difficulty: Simple  
Tags: binary search

![binary search interval shrinking](assets/704.png)

### 二刷 (7/21/2026) ❌

我的代码：

```java
class Solution {
    public int search(int[] nums, int target) {
        int left = 0, right = nums.length - 1;

        while (left <= right) {
            int mid = (right + left) / 2;
            if (nums[mid] > target) {
                right = right - 1; // 应该 right = mid - 1。写成 right-1 每次只缩 1，退化成 O(n)，不再是 binary search
            } else if (nums[mid] < target) {
                left = left + 1; // 同理，应该 left = mid + 1。有序数组可以一次性排除 mid 及一侧
            } else if (nums[mid] == target) {
                return mid;
            } else {
                return -1; // dead code：>/</==已覆盖所有整数情况，这个分支永远走不到
            }
        }
        // ❌ 缺 return：循环正常退出(没找到)时没有返回值，方法签名是 int → 编译报 "missing return statement"
    }
}
```

### 三刷 (7/30/2026) ⚠️卡推导 5min 一次 AC，退出语义说反

二刷四个错全避（`mid ± 1`、防 overflow、无 dead code、循环后有 return）。

**口答两次说反 left 的语义**，先套用 34 U 版说成「第一个 >」，纠正后再问又反回去。写代码没问题，口述才暴露——写的时候是模式匹配，说的时候才需要这条规则。

> **自检信号**：**推 left 的条件取反，就是 left 停在哪。**
> `< target` 推 left → 取反 `>= target` → 停在第一个 **≥**（704）
> `<= target` 推 left → 取反 `> target` → 停在第一个 **>**（34 的 U 版）
> 直觉纠正：`=` 写进推进条件 = 「等于的也要跨过去」，所以 left **停不在**等于的位置。
> 拿不准就走 `nums=[1,3,5], target=3`：两版 left 分别停在 1 和 2。

**自测点**：① 推 left 的条件如何决定 left 停在 ≥ 还是 > ② 退出时 left 与 right 的关系、各自语义 ③ 704 为什么能写 `== target` 提前返回，bound 类不行 ④ 704 退出后的信息，34 和 69 各用了哪一半

### 四刷 (8/3/2026) ✅ 5min，未翻笔记

二刷四个错继续全避。三刷口答说反的退出语义，这次**带着前提写进了注释**——`cuz I return equal early, so left is on the first element larger than target`。补上「提前 return 截走等号」这个前提后，说法成立：命中即返回，能走到循环外说明 target 不存在，此时「第一个 ≥」与「第一个 >」同格。

**但这是 704 的特例解释，不是通用规则。** 通用规则仍是取反：`<` 推 left → 取反 `>=` → 停在第一个 **≥**。34 的 L 版没有提前 return，target 存在时 left 恰好停在 target 身上——若记成「`<` 推 left → 第一个 >」，34 的左边界会差一格。**①的真正检验点在 34，不在本题。**

措辞：left 是**下标**不是 element（34 四刷漏越界检查就是从这个词滑出去的）

---

### 沉淀：退出时的 left / right

`while (left <= right)` 退出即 `left > right`，每轮挪一格 → **必然 `left = right + 1`**，两个 pointer 交错在分界线两侧。704 的写法（`<` 推 left）下：

- `left` = 第一个 **≥** target 的位置，值域 `[0, n]`
- `right` = 最后一个 **<** target 的位置，值域 `[-1, n-1]`

**同一退出状态，各题取不同的一半**：704 两半都不要（命中已在循环内返回，走到外面就是没找到 → `-1`）；34 取 `left`；69 取 `right`。

`left` 可以是 `n`、`right` 可以是 `-1`，都不是合法下标——**拿它访问数组前必须查**（34 四刷栽在这里）。left/right 是**下标**不是元素。

### 关联

- 34（`=` 归哪侧决定 left 停 ≥ 还是 >；三刷 `return mid` 是把 704 习惯带过去，bound 类里是核心错误）
- 35（插入位置 = 退出时的 `left`）
- 69（取退出时的 `right`）

### 正确写法

```java
class Solution {
    public int search(int[] nums, int target) {
        int left = 0, right = nums.length - 1;   // closed interval [left, right]

        while (left <= right) {
            int mid = left + (right - left) / 2; // avoid overflow
            if (nums[mid] > target) {
                right = mid - 1;
            } else if (nums[mid] < target) {
                left = mid + 1;
            } else {
                return mid;
            }
        }
        return -1;   // not found
    }
}
```
