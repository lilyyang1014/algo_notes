## 367. Valid Perfect Square

Date: 一刷(随想录，日期待补), 7/22/2026, 8/12/2026
Difficulty: Easy
Tags: binary search

![two exits: hit mid² == num → true inside loop, interval exhausted → false outside](assets/367.png)

### 二刷 (7/22/2026) ❌ 4 处错

我的代码（错误点标在旁边）：

```java
class Solution {
    public boolean isPerfectSquare(int num) {
        int left = 0, right = num;

        while (left <= right) {
            int mid = left + (right - left) / 2;
            long a = (long) mid * mid;      // ✅ overflow 防住了，69 的坑没白踩
            if (a*a == num) {               // ❌① a 已经是 mid²，a*a 是 mid⁴ → 应该 a == num
                return true;
            } else if (a*a > num) {
                mid = right - 1;            // ❌② 赋值方向反：应该 right = mid - 1
            } else if (a*a < num) {         //    改 mid 没用（下一轮立刻被重算覆盖），
                mid = left + 1;             //    left/right 永远不动 → 死循环
            }
            return false;                   // ❌③ 位置错：在循环体内，第一轮没命中就 false
        }                                   //    「搜完整个区间才 false」→ 应移到循环外
    }                                       // ❌④ 循环外没 return → 编译错 missing return statement
}
```

**②的定性**：暂记笔误（三刷验证 → 8/12 未再犯，确认为笔误）。但注意它和 704 二刷的 `right = right - 1` 是同一族错——**边界更新那一行**，形态不同（704 退化 O(n)，这次死循环）。

**③④是一对**：和 704 的「循环外缺 return」是同一个位置感问题的两面——704 是循环外忘了写，这次是把它写进了循环内。

### 三刷 (8/12/2026) ⚠️卡推导 —— 代码全对，follow-up 口答错在「搜索的量 vs 比较的量」

代码一次写对，二刷四个错全未再犯，`(long) mid * mid` 防护在。

**follow-up**：删掉 `if (a == num) return true;` 这一支，循环外要补什么判断？

我答：left 停在第一个 `>= num` 的位置，所以 `left == num` 就 return true。**❌ 应为 `(long) left * left == num`。**

**根因**：本题 `left` 装的是**根**（mid 那一类的量），`num` 是**平方数**——两者量纲不同，`left == num` 只在 num=0、1 时碰巧成立。num=16 时 left 停在 4，`4 == 16` 为 false。

而错的源头不在那行代码，在我口答时说的那句话里：

> **停位判据说的永远是 condition 里比较的那个量，不是 mid 本身。**

condition 是 `square < num`，所以准确说法是「left 停在**第一个使 `mid² >= num` 成立的 mid**」——主语是 mid，谓语说的是 mid²。我把它压成了「第一个 `>= num` 的位置」，mid 和 mid² 被压成一个词，再顺着这句话翻译，必然写出 `left == num`。**不是翻译错了，是照着一句已经压扁的话老实翻译出来的。**

**自测点**：把 `right` 的初值从 `num` 改成 `num / 2`，哪些 num 会出错、为什么？

### 核心思路（一句话）

**367 = 69 的判定版，形态上更接近 704：查存在，不关心边界。**
满足 `mid² == num` 的位置唯一 → `==` 提前 return true 合法；循环外唯一出口 return false（搜完整个区间都没有）。连 return left/right 的纠结都没有。

### 代码

```java
class Solution {
    public boolean isPerfectSquare(int num) {
        int left = 0, right = num;
        while (left <= right) {
            int mid = left + (right - left) / 2;
            long a = (long) mid * mid;
            if (a == num)      return true;
            else if (a > num)  right = mid - 1;
            else               left = mid + 1;
        }
        return false;   // 搜完整个区间，不存在
    }
}
```

### 引申：搜索的量 ≠ 比较的量

本题 mid 是候选的根、`mid * mid` 才是拿去比的东西，中间**没有 `nums[]` 这层符号把两者隔开**——这是它比 704/35 容易说串的原因。那两题有下标和值的天然分工，语感上不会混。

三条连带结论：

- **描述停位**：只能用 condition 里比较的那个量说（第一个使 `mid² >= num` 的 mid），别省成「第一个 >= num 的位置」
- **写最终判断**：只能用 mid 那一类的量写（`left * left`），因为 left 装的就是根
- **只查 left 一个候选就够**：`mid²` 单调递增，left 左边的平方全部严格小于 num、右边的全部大于 num，只有 left 这一格可能命中

同族题：LC69（搜 mid、比 mid²）、LC875（搜速度 k、比「按 k 吃完要多少小时」）、LC1011。凡是「二分答案」类，搜索空间和比较对象必然分离，这条都要用。

### 引申：提前 return 删掉之后，判断没消失，只是挪了地方

| 版本                          | else 分支的条件 | 循环外的结论                        |
| ----------------------------- | --------------- | ----------------------------------- |
| 原代码（有 `== return true`） | `a > num`       | `left² > num` → `return false` 就够 |
| 删掉提前 return               | `a >= num`      | `left² >= num` → 必须再查一次 `==`  |

原来在 `a == num` 那一刻当场结清的事，现在攒到循环外由 `left * left == num` 统一结清。

（同一机制在 LC35 上是反过来用的：那题说「left 停在第一个 `> target`」成立，正因为提前 return 把 `==` 那格拿走了；删掉提前 return，else 分支变 `>=`，说法就得跟着变。）

### 沉淀

- **自检：更新分支写完，看一眼等号左边**——必须是 `left` 或 `right`，`mid` 永远只在等号右边（区间指针才是被更新的对象）
- **自检：说完「left 停在第一个 XXX」，回头问一句 XXX 是我搜索的量还是我比较的量**。两者不同时，停位判据只能用后者说、最终判断只能用前者写
- 引入中间变量后注意概念绑定：`a` 就是 mid²，比较时用 `a`，别再平方
- return 的位置感：循环内 return =「找到了」；循环外 return =「搜完了没找到」。两个 return 各守一个语义，不能混
- Time: O(log num) / Space: O(1)
