## 367. Valid Perfect Square

Difficulty: Easy
Tags: binary search

![two exits: hit mid² == num → true inside loop, interval exhausted → false outside](assets/367.png)

### 二刷 (7/22/2026) ❌ 4 处错

```java
public boolean isPerfectSquare(int num) {
    int left = 0, right = num;
    while (left <= right) {
        int mid = left + (right - left) / 2;
        long a = (long) mid * mid;      // ✅ overflow 防住了，69 的坑没白踩
        if (a*a == num) {               // ❌① a 已经是 mid²，a*a 是 mid⁴ → 应为 a == num
            return true;
        } else if (a*a > num) {
            mid = right - 1;            // ❌② 赋值方向反：应为 right = mid - 1
        } else if (a*a < num) {         //    改 mid 没用（下一轮立刻被重算覆盖），
            mid = left + 1;             //    left/right 永远不动 → 死循环
        }
        return false;                   // ❌③ 位置错：在循环体内，第一轮没命中就 false
    }                                   //    「搜完整个区间才 false」→ 应移到循环外
}                                       // ❌④ 循环外没 return → 编译错
```

**②是笔误**（后续未再犯），与 704 二刷的 `right = right - 1` 同族——都错在边界更新那一行。**③④是一对**：与 704 的「循环外缺 return」是同一个位置感问题的两面，704 是忘了写，这次是写进了循环里。

**follow-up**：删掉 `if (a == num) return true;`，循环外要补什么判断？我答 `left == num`，**应为 `(long) left * left == num`**。

错的源头在口答那句话里——「left 停在第一个 `>= num` 的位置」**把 mid 和 mid² 压成了一个词**。压扁之后再老实翻译，必然写出 `left == num`。不是翻译错了，是照着一句已经压扁的话翻译出来的。

### 四刷 (8/21/2026) ⚠️卡推导 —— 同一条缝，换了个位置

问题：`right` 初值从 `num` 改成 `num / 2`，哪些 num 会出错？

**最关键那一步列对了**：出错 ⟺ `x > num / 2`。卡在下一步——代入 `num = x²` 化简时把两边的 x 约没了，答成「x > 1/2」；以及卡在「x 和 num 到底谁是谁」。

**答案**：`x > x²/2` → `x < 2` → **只有 num = 1 会出错**（`right = 0`，跑一轮 mid=0 就退出，返回 false）。`x ≥ 2` 时 `x ≤ num/2`，答案永远落在新区间内。

**措辞拧紧**：我说「x 掉到另一半区间上去了」——`right = num/2` 之后**右边那半根本不存在了**，不是没搜到，是没覆盖。这个区别决定修法：前者引向「再搜一次另一半」，实际只能把上界放回去。（同 LC380 那次「找错保护对象」。）

### 五刷 (9/4/2026) 代码一次写对；改写版三处错，口答第三次压扁（脏站，不定档）

主体一次 AC，`(long) mid * mid` 转型收在乘法**之前**（写成 `(long)(mid * mid)` 就白转了，int 先溢出，long 只接了个残骸）。

被要求写「删掉提前 return」那一版时，我自己写的：

```java
while (left <= right) {
    int mid = left + (right - left) / 2;
    long target = (long) mid * mid;    // ❌② declare 在循环内 → 循环外不存在，
    if (target < num) {                //    每轮新建每轮销毁，出了花括号连符号都解析不了
        left = mid + 1;
    } else {
        right = mid - 1;
    }
}
return if (target == num);             // ❌① if 是 statement 不是 expression，不产生值，
                                       //    return 后面跟不了它 → 直接写 return target == num
                                       // ❌❌③ 核心错：赌「最后一个 mid 就是答案」
```

**②归「声明位置决定生命周期」族第四次**（LC80 的 `count`、LC380 一刷的 field、LC238 的 `suffix`）。前三次是「值丢了」，这次是「人也不见了」。**想在循环外用的东西，必须在循环外 declare。**

**③的根因**：`num = 25`，`[0, 25]`——

| 轮  | left, right | mid | mid²   | 动作              |
| --- | ----------- | --- | ------ | ----------------- |
| 1   | 0, 25       | 12  | 144    | ≥ 25 → right = 11 |
| 2   | 0, 11       | 5   | **25** | ≥ 25 → right = 4  |
| 3   | 0, 4        | 2   | 4      | < 25 → left = 3   |
| 4   | 3, 4        | 3   | 9      | < 25 → left = 4   |
| 5   | 4, 4        | 4   | 16     | < 25 → left = 5   |

第 2 轮踩中过 25，但退出时最后一个 mid 是 4 → 返回 false。**删掉提前 return 之后，踩中的那一轮不再有特权**，被 `else` 当成「太大了」继续往下缩。

> **自检信号**：二分一定会**访问**到答案，但答案不一定是**最后一个**被访问的。循环外只能信 `left` / `right` 这两个收敛下来的量，`mid`、`target` 这种每轮被覆盖的临时量在循环外没有意义。

**口答：压扁第三次。** 我答「left 停在第一个 >= num，right 停在最后一个 < num」——语义对，但**「第一个 >= num」的不是 `left` 是 `left²`**。三刷是 `left` 与 `left²` 压扁，四刷是 `x` 与 `num` 分不清，这次原样复发。

**脏站**：下半句（为什么 `right * right == num` 恒 false）是 Claude 给的答案不是我推的，本轮不定 ⚠️ 子档、不计入连卡计数。代码那一份是干净的。

**自测点**：原来那条（用 `right` 判）9/4 讲穿作废，新的一条在排期备注页。

### 核心思路（一句话）

**367 = 69 的判定版，形态上更接近 704：查存在，不关心边界。**

满足 `mid² == num` 的位置唯一 → `==` 提前 return true 合法；循环外唯一出口 return false。连 return left 还是 right 的纠结都没有。

### 代码

```java
public boolean isPerfectSquare(int num) {
    int left = 0, right = num;
    while (left <= right) {
        int mid = left + (right - left) / 2;
        long a = (long) mid * mid;
        if (a == num)      return true;
        else if (a > num)  right = mid - 1;
        else               left = mid + 1;
    }
    return false;   // 搜完整个区间，不存在
}
```

Time: O(log num) / Space: O(1)

### 引申一：left 停在哪，f 长什么样

**left 是第一个使 `f(x) >= target` 成立的位置。f 长什么样，看 if 里比较的表达式**——是 `mid * mid` 就 `left * left`，是 `nums[mid]` 就 `nums[left]`。

mid 是每轮拿来试的试探点，试完就扔；left 是最后落定的那个整数。所以「left 满足条件」要代入的是 **f 的定义**，不是 `mid = left + (right-left)/2` 那条公式（追下去会绕回自己）。

循环外写什么，再多问一句——**题目要的是 k 本身，还是 f(k) 那个值**：

- 要 k → 直接 `return left`（LC35 的插入下标、LC875 的最小速度，**绝大多数二分题在这支**）
- 要 f(k) → 拿 left 重算一次。367 要 `(long) left * left == num`。**三刷栽的就是漏了这一步重算，五刷口答又滑回同一句**

只查 left 一个候选就够：`mid²` 单调递增，left 左边的平方全部严格小于 num、右边全部大于。

同族题：69、875 / 1011。凡「二分答案」类，**搜索的量和比较的量必然分离**——这正是本题三次卡推导的同一条缝。

### 引申二：搜索区间改了，先问「答案还在里面吗」

**任何时候改动 binary search 的边界，把「答案」和「边界」写成同一个量再比一次。** 本题就是 `x` vs `num/2`：代入 `num = x²` 统一成 x，一个不等式就把出错的输入全找出来了，不用挨个试数字。

和引申一是一对：引申一管**循环内部**（f 长什么样），这条管**区间本身**（f 的定义域够不够）。

### 引申三：提前 return 删掉之后，判断没消失，只是挪了地方

| 版本                          | else 分支的条件 | 循环外的结论                        |
| ----------------------------- | --------------- | ----------------------------------- |
| 原代码（有 `== return true`） | `a > num`       | `left² > num` → `return false` 就够 |
| 删掉提前 return               | `a >= num`      | `left² >= num` → 必须再查一次 `==`  |

原来在 `a == num` 那一刻当场结清的事，现在攒到循环外统一结清。**`==` 那一格归谁，看 condition 的等号在哪边**：`a < num` 推 left → 等号那格留给 left，所以外面查 `left`；`a <= num` 推 left → 等号那格被越过、归 right（LC69 的 right 是「最后一个 ≤ x」）。

用 `right` 判为什么不行：`right` 的语义是「最后一个使 `mid² < num`」的 mid，**严格小于**，所以 `right * right == num` 恒 false。真要写得写 `(long)(right+1) * (right+1) == num`，而 `right + 1` 就是 `left`，绕回来了。

**循环外那次比较也要 `(long)`**：`left` 最大到 `num + 1`，num 上限 2³¹−1，int 相乘照样溢出。循环里转了、循环外忘转是这题最容易漏的一处。

### 沉淀

- **说完「left 停在第一个 XXX」，把 f 的定义显式念出来**，别省成「第一个 >= num」——三刷、四刷、五刷三次都栽在这一句上，是本题唯一的长期短板
- **卡住时先查身份**：手上这个符号是输入还是答案、是下标还是值、是根还是平方。四刷主动问「x 和 num 各充当什么角色」是对的动作，应该更早做
- **循环外只能信收敛量**：`left` / `right` 是每轮被更新推着走的，`mid` / `target` 每轮重生。想在外面用 → 必须在外面 declare，而且大概率说明思路错了（五刷 ❌❌）
- **改区间边界 → 立刻验一次「答案还在新区间里吗」**（引申二）
- **更新分支写完看一眼等号左边**：必须是 `left` 或 `right`，`mid` 永远只在等号右边
- **overflow 转型要收在乘法之前**，`(long) mid * mid` 不是 `(long)(mid * mid)`；循环内外都要转
- return 的位置感：循环内 return =「找到了」，循环外 return =「搜完了没找到」
