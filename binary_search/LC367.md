## 367. Valid Perfect Square

Date: 一刷(随想录，日期待补), 7/22/2026, 8/12/2026
Difficulty: Easy
Tags: binary search

![two exits: hit mid² == num → true inside loop, interval exhausted → false outside](assets/367.png)

### 二刷 (7/22/2026) ❌ 4 处错

我的代码（错误点标在旁边）：

```java
class Solution {
    public boolean isPerfectSquare(int num) {
        int left = 0, right = num;

        while (left <= right) {
            int mid = left + (right - left) / 2;
            long a = (long) mid * mid;      // ✅ overflow 防住了，69 的坑没白踩
            if (a*a == num) {               // ❌① a 已经是 mid²，a*a 是 mid⁴ → 应该 a == num
                return true;
            } else if (a*a > num) {
                mid = right - 1;            // ❌② 赋值方向反：应该 right = mid - 1
            } else if (a*a < num) {         //    改 mid 没用（下一轮立刻被重算覆盖），
                mid = left + 1;             //    left/right 永远不动 → 死循环
            }
            return false;                   // ❌③ 位置错：在循环体内，第一轮没命中就 false
        }                                   //    「搜完整个区间才 false」→ 应移到循环外
    }                                       // ❌④ 循环外没 return → 编译错 missing return statement
}
```

**②的定性**：笔误（8/12 三刷未再犯，已确认）。但它和 704 二刷的 `right = right - 1` 是同一族——**边界更新那一行**，形态不同（704 退化 O(n)，这次死循环）。

**③④是一对**：和 704 的「循环外缺 return」是同一个位置感问题的两面——704 是循环外忘了写，这次是把它写进了循环内。

### 三刷 (8/12/2026) ⚠️卡推导 —— 代码全对，follow-up 口答栽了

代码一次写对，二刷四个错全未再犯，`(long) mid * mid` 防护在。

我答：left 停在第一个 `>= num` 的位置，所以 `left == num` 就 return true。**❌ 应为 `(long) left * left == num`。**

错的源头不在那行代码，在我口答说的那句话里——「第一个 `>= num` 的位置」把 mid 和 mid² 压成了一个词。压扁之后再老实翻译，必然写出 `left == num`。**不是翻译错了，是照着一句已经压扁的话翻译出来的。**

（num=16 时 left 停在 4，`4 == 16` 为 false。left 装的是**根**，num 是**平方数**，本来就不该相等。）

**自测点**：把 `right` 的初值从 `num` 改成 `num / 2`，哪些 num 会出错、为什么？

### 核心思路（一句话）

**367 = 69 的判定版，形态上更接近 704：查存在，不关心边界。**
满足 `mid² == num` 的位置唯一 → `==` 提前 return true 合法；循环外唯一出口 return false。连 return left/right 的纠结都没有。

### 代码

```java
class Solution {
    public boolean isPerfectSquare(int num) {
        int left = 0, right = num;
        while (left <= right) {
            int mid = left + (right - left) / 2;
            long a = (long) mid * mid;
            if (a == num)      return true;
            else if (a > num)  right = mid - 1;
            else               left = mid + 1;
        }
        return false;   // 搜完整个区间，不存在
    }
}
```

### 引申：left 停在哪，f 长什么样

**我只要记住一句：left 是第一个使 `f(x) >= target` 成立的位置。至于 f 长什么样，看 if 里比较的表达式——是 `square` 就 `left * left`，是 `nums[mid]` 就 `nums[left]`。**

mid 只是每轮拿来试的试探点，试完就扔；left 是最后落定的那个整数。所以「left 满足条件」要代入的是 **f 的定义**，不是 mid 的计算公式（`mid = left + (right-left)/2` 那条链追下去是死路，会绕回自己）。

循环外写什么，再多看一句——**题目要的是 k 本身，还是 f(k) 那个值**：

- 要 k 本身 → 直接 `return left`。LC35 的插入下标、LC875 的最小速度都是这支，**绝大多数二分题都在这支**
- 要 f(k) 的值 → 拿 left 重算一次。367 问「平方数等不等于 num」，所以要 `left * left == num`。**这次栽的就是漏了这一步重算**

顺带：只查 left 一个候选就够——`mid²` 单调递增，left 左边的平方全部严格小于 num、右边的全部大于，只有 left 这一格可能命中。

同族题：69（搜 mid、比 mid²）、875 / 1011（搜速度，比「按这个速度要多久」）。凡是「二分答案」类，搜索空间和比较对象必然分离。

### 引申：提前 return 删掉之后，判断没消失，只是挪了地方

| 版本                          | else 分支的条件 | 循环外的结论                        |
| ----------------------------- | --------------- | ----------------------------------- |
| 原代码（有 `== return true`） | `a > num`       | `left² > num` → `return false` 就够 |
| 删掉提前 return               | `a >= num`      | `left² >= num` → 必须再查一次 `==`  |

原来在 `a == num` 那一刻当场结清的事，现在攒到循环外统一结清。

**推论：`==` 那一格归谁，看 condition 的等号在哪边。** `square <= x` 推 left → 等号那格被 left 越过、归 right 地盘（LC69 的 right 是「最后一个 ≤ x」）；`square < x` 推 left → 等号那格留给 left。LC35 说「left 停在第一个 `>`」成立，也是因为提前 return 把 `==` 那格拿走了。

### 沉淀

- **自检：更新分支写完，看一眼等号左边**——必须是 `left` 或 `right`，`mid` 永远只在等号右边
- **自检：说完「left 停在第一个 XXX」，把 f 的定义显式念出来**，别省成「第一个 >= num 的位置」
- 引入中间变量后注意概念绑定：`a` 就是 mid²，比较时用 `a`，别再平方
- return 的位置感：循环内 return =「找到了」；循环外 return =「搜完了没找到」，各守一个语义
- Time: O(log num) / Space: O(1)
