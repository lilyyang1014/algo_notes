## 797. All Paths From Source to Target

![DFS path updates and backtracking](assets/797.png)

### 一刷 (9/30/2026) ❌ 终点重复加入 + 回溯删除位置错误

理解思路后，合上笔记独立写，错了两处：

```java
if (node == graph.length - 1) {
    path.add(node); // ❌① 调用 dfs 前已经加入，导致终点重复
    ans.add(new ArrayList<>(path));
    return;
}

// ...

path.remove(graph.length - 1); // ❌② 用了图的节点数量，可能越界或删错位置
```

**①的根因**：调用 `dfs(graph, next)` 前已经执行 `path.add(next)`，所以进入 dfs 时，当前节点已经在 path 中。到终点直接复制保存，否则 `[0, 4]` 会变成 `[0, 4, 4]`。

**②的根因**：回溯要删除 path 的最后一个 element，应使用 `path.size() - 1`。`graph.length` 是整张图的节点数量，和当前路径长度不是一回事。

> **自检信号**：进入 dfs 时检查当前节点是否已经加入；检查每次 add 后，是否有对应的 remove 撤销这次加入。

**自测点**：到终点时，path 已经包含哪些节点？这次 dfs 返回后，应该删除哪个节点，为什么？

---

### 核心思路

**从 0 开始 DFS，遇到终点就复制保存 path；对当前节点的每个邻居，依次执行「加入 → 搜索 → 撤销」。**

- `graph[node]`：当前节点能一步到达的节点编号。
- `path`：当前搜索的这一条路径。
- `ans`：已经找到的所有完整路径。
- 题目规定起点是 `0`，终点是 `graph.length - 1`，这不是 DAG 的定义。
- DAG 保证无环，不需要 visited 防止绕圈；不同路径可以经过同一个节点。

### 正确写法

```java
class Solution {
    List<List<Integer>> ans = new ArrayList<>();
    List<Integer> path = new ArrayList<>();

    public List<List<Integer>> allPathsSourceTarget(int[][] graph) {
        path.add(0);
        dfs(graph, 0);
        return ans;
    }

    private void dfs(int[][] graph, int node) {
        // 进入 dfs 时，node 已经在 path 中
        if (node == graph.length - 1) {
            ans.add(new ArrayList<>(path));
            return;
        }

        for (int next : graph[node]) {
            path.add(next);
            dfs(graph, next);
            path.remove(path.size() - 1);
        }
    }
}
```

### 复杂度分析

设节点数为 n。

**Time: O(n × 2ⁿ)**：最坏情况下路径数量为指数级，每次保存还需复制最多 n 个节点。

**Space: O(n)**：不计答案，path 和递归调用栈最多占 O(n)；计入答案则最坏为 O(n × 2ⁿ)。

### 沉淀

- **加入和撤销要对应**：每次加入一个节点，搜索结束后删除这次加入的节点。
- **保存路径要复制**：`new ArrayList<>(path)` 创建独立列表，后续修改 path 不会改变已保存的答案。
- **return 只结束当前调用**：回到调用它的那一行之后，继续执行 remove，再尝试下一个邻居。
