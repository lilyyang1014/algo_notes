## 238. Product of Array Except Self

### 一刷 (8/11/2026) ❌ 没思路（**读解法，非独立解出**）

**卡在哪**：不能用除法 → 想到暴力对每个 i 重乘一遍有大量重复计算 → 推出用 prefix product 边走边维护。到这里停住，suffix product 想不出来。

**真正的坎**：想通 prefix product 之后被**单一遍历方向锁死**了——默认「我已经在从左往右走」，没问过「能不能再扫一遍、能不能反着扫」。suffix 和 prefix 是完全同构的递推，只是方向相反：

```
suffix[i] = suffix[i+1] * nums[i+1]     ← 和 prefix[i] = prefix[i-1] * nums[i-1] 一个形状
```

坎不在 suffix product 这个概念，在于没意识到**答案 = 左边一坨 × 右边一坨**这个式子写出来之后，右边那坨该用和左边一样的办法拿。

**自测点**：① 如果题目**允许**用除法（总积 ÷ 自身），这个解法什么时候会出错？数组里恰好有一个 0、有两个 0，分别该输出什么？ ② `answer[i] *= right` 和 `right *= nums[i]` 调换顺序后，`nums = [1,2,3,4]` 的 `answer[2]` 会算成几？（口答，不许跑代码）

### 核心思路（一句话）

**answer[i] = i 左边所有元素的积 × i 右边所有元素的积；两侧各用一次同构的递推扫出来，第二次扫的方向和 suffix 的递推方向一致，所以 suffix 不用存数组。**

### 代码

```java
class Solution {
    public int[] productExceptSelf(int[] nums) {
        int n = nums.length;
        int[] answer = new int[n];
        answer[0] = 1;                      // 空积 = 1：nums[0] 左边没有 element
        for (int i = 1; i < n; i++) {
            answer[i] = answer[i - 1] * nums[i - 1];   // prefix product 存进输出数组
        }

        int right = 1;                      // 空积 = 1：nums[n-1] 右边没有 element
        for (int i = n - 1; i >= 0; i--) {
            answer[i] *= right;             // 用：此刻 right 恰是 i 右边的积
            right *= nums[i];               // 更新：留给 i-1（顺序不可换）
        }
        return answer;
    }
}
```

**invariant**：执行 `answer[i] *= right` 的那一刻，`right` 里装的一定是 nums[i] **右边**所有 element 的积。`right = 1` 让它在入口成立，`right *= nums[i]` 让它在每轮出口继续成立。

**两行顺序不可换**：先更新则 `right` 含了 nums[i] 自己，违反「except self」。这是本题唯一的 edge case 级陷阱，且是静默错误。

**Java 特有的坑**：`new int[n]` 默认填 0，从 Python 的 `[1] * n` 翻译过来时必须补 `answer[0] = 1`，漏掉则整个数组归零。

### 复杂度分析

**Time: O(n)**：两次独立的单趟 loop，2n → O(n)
**Space: O(1)**：只有 `right` 和 `i`。输出数组按题目口径不计入 extra space

对比 brute force O(n²)（每个位置重新乘一遍全数组）：把「每个位置各算一遍左右积」摊成「全数组各扫一遍」，重复的中间积只算一次。

对比朴素双数组版（另开 `prefix[]` + `suffix[]`，O(n) extra space）：prefix 搬进本来就要开的 `answer`（白嫖），suffix 塌成一个 int（真省）——follow-up 问的就是这两步。

### 沉淀

- **生产顺序 == 消费顺序 → 数组可塌成标量**：suffix 在从右往左那一趟里算出来就立刻被用掉，不需要留档；prefix 在第一趟算出、第二趟才用，中间隔了一整趟，所以必须存。判断某个中间数组能不能省掉，看的是这个，不是「它占不占地方」。同一条判据在 DP 里就是滚动数组能否成立、以及 01 背包为什么必须倒序。
- **「位置 i 的答案依赖它两侧的全局信息」→ 双向扫描**：正扫存一遍、反扫合并。看到这个形态直接往这条上靠，不用现推。
- **想通一半就被遍历方向锁死**：本题真正的卡点。破解的提问是「能不能再扫一遍？能不能反着扫？」
- **两端初值都是 1，同源于「空积 = 1」**：`answer[0]` 和 `right` 是同一条规则在左右两端的镜像（对应求和场景就是「空和 = 0」）。不要当两个特例记。
- **extra space 的口径**：输入 + 输出题目逼着开的，不计；纯为中间计算开的脚手架，才计。「in-place 排序是 O(1) 空间」是同一套口径。

### 引申：一次 loop 的写法（知道即可，不主动写）

左右两个指针在同一个 loop 里对向推进，`answer[i] *= left` 与 `answer[n-1-i] *= right` 各打一次。时间空间都没变，只是行数少了，可读性明显更差、`n-1-i` 容易写错。面试不主动给，被问到再提。

### Interview pitch (练口述)

> "Division is off the table, so I split the answer for each index into two halves: the product of everything to its left and everything to its right. Both halves follow the same recurrence, just in opposite directions. I do a left-to-right pass writing prefix products straight into the output array, then a right-to-left pass where I carry the suffix product in a single variable and multiply it in. The suffix never needs its own array because it's consumed in the same order it's produced. That gives O(n) time and O(1) extra space, not counting the output. The one thing to be careful about is ordering inside the second loop — multiply into the answer before folding nums[i] into the running suffix, otherwise the element includes itself."
