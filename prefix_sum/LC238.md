## 238. Product of Array Except Self

### 一刷 (8/15/2026) ⚠️ 结构对了，合并那一行的下标滑掉

```java
int temp = 1;
for(int j = nums.length-2; j >= 0; j--){
    temp *= ans[j+1];                        // ❌① 应为 nums[j+1]
    ans[j] = ans[j+1] * temp;                // ❌② 应为 ans[j]
}
```

**①**：`temp` 攒的是右边**原始元素**的连乘，所以该乘 `nums[j+1]`。`ans[j+1]` 是加工过的 prefix product，不是元素。写的时候脑子里 `temp` 就是后缀积——量是对的，抓错了数组名。

**②**：答案 = j 左边的积 × j 右边的积，**两个都归 j**。写 `ans[j+1]` 拿的是右邻居的 prefix，它比 `ans[j]` 多乘了一个 `nums[j]`——正好把要排除的自己又乘回来了。

**②还有第二层**：这个 loop 是原地覆盖的，`ans[j+1]` 上一轮就被写成最终答案了，读它的时候它早就不是 prefix 了。

dry run `[1,2,3,4]`（①已修、②未修）：

| j   | temp | 写成 `ans[j+1]*temp`                | 正确 `ans[j]*temp`   |
| --- | ---- | ----------------------------------- | -------------------- |
| 2   | 4    | ans[3]=6 → **24** ❌                | ans[2]=2 → **8** ✅  |
| 1   | 12   | ans[2]=**24**（已覆盖）→ **288** ❌ | ans[1]=1 → **12** ✅ |
| 0   | 24   | ans[1]=**288** → **6912** ❌        | ans[0]=1 → **24** ✅ |

j=2 只差一格，到 j=1 读到的已经是上一轮写进去的答案，被乘法一路放大。

> **自检信号**：原地覆盖的 loop 里，凡是读邻居的那一行都停一下，问「这一格现在装的还是我以为的那个量吗」。只读自己最安全；要读邻居，就得说得出它此刻是覆盖前还是覆盖后。

**归族**：同一天 704 是 `left`（index）和 `nums[left]`（值）压成一个词，这次是 `nums[j+1]`（元素）和 `ans[j+1]`（prefix）压成一个词。**两个量共用一个下标，写那一行时只抓住了下标，没抓住它属于哪个数组。**（274、45、367、704 同族）

### 二刷 (8/23/2026) ❌ 累积量 declare 在 loop 里，`last` 从来没被更新过

```java
int last = 1;
for(int j = nums.length-2; j >= 0; j--){
    int suffix = last * nums[j+1];   // ❌ declare 在 loop 内 → 每轮重生，last 全程停在 1
    ans[j] = suffix * ans[j];        //    → 后缀积退化成单个元素 nums[j+1]
}
```

**根因**：「后缀积」这个角色被劈成了两个 variable，**谁都没承担跨 iteration 的累积**——`last` 有名字有初值但没人更新它，`suffix` 每轮算完就没了。左边改成 `last` 就通过。

**很像「只差一点」**：`[1,2,3,4]` 得 `[2,3,8,6]`。最右两格恒对（`ans[n-1]` 不进这个 loop，`ans[n-2]` 的后缀本来就只有一个元素），越往左错得越狠，头两个 case 容易看成小偏差。

**归族**：LC80 的 `count` 该外置却内置、LC380 三个 field 连着赋值写进 constructor，这是**第三次**。LC80 笔记里那条沉淀原样适用，三次都没接到决策上。

### 三刷 (8/25/2026) ⚠️卡推导 代码一次写对，但说不出 `ans[i]` 到底是什么

### 核心思路（一句话）

**每个位置的答案 = 它的前缀积 × 它的后缀积。** 正着一趟把 prefix 铺进 `ans`，反着一趟用一个 variable 攒 suffix、就地乘上去。

### 代码

```java
class Solution {
    public int[] productExceptSelf(int[] nums) {
        int[] ans = new int[nums.length];
        ans[0] = 1;                              // 0 左边没有元素，空积 = 1
        for (int i = 1; i < nums.length; i++) {
            ans[i] = ans[i-1] * nums[i-1];       // ans[i] = nums[0..i-1] 的积
        }
        int suffix = 1;                          // declare 在 loop 外：它要跨 iteration 活着
        for (int j = nums.length - 2; j >= 0; j--) {
            suffix *= nums[j+1];                 // 攒的是元素，而且是累乘不是重算
            ans[j] = ans[j] * suffix;            // 自己的 prefix × 自己的 suffix
        }
        return ans;
    }
}
```

`ans[n-1]` 不进第二个 loop：它的后缀积是 1，第一趟的结果就是答案。

**两个边界都是 1 不是 0**：乘法的单位元是 1，而 `new int[n]` 默认填 0，所以 `ans[0]` 必须手动置 1，否则整条 prefix 链全是 0。

### 复杂度分析

**Time: O(n)**：两趟。
**Space: O(1)**（不算输出数组）：只多一个 `suffix`。

对比开两个数组分别存前后缀再合并：思路更直白，但要 O(n) 额外空间。暴力对每个位置重乘一遍是 O(n²)。

### 引申一：如果允许用除法

`ans[i] = total / nums[i]`——**炸的是 divisor**，`nums[i] == 0` 时抛 `ArithmeticException: / by zero`。`total` 为 0 完全合法（`0 / 5` 就是 0），别把被除数和除数抓成一个词。

要写对得先数有几个 0：没有 0 就直接除；恰好一个 0 在 k，那 `ans[k]` = 其余元素之积、**其他位置全是 0**；两个及以上 0，整个 ans 全是 0。

### 引申二：`ans[i]` 的定义，决定它乘到哪一格为止

第一趟如果写成 `ans[i] = ans[i-1] * nums[i]`，**就是把自己也乘进去了**，下面就要跟着改——得除以 `nums[i]`。但除数不能是 0，会抛异常；而且这题本来就禁除法。所以**这条路是死的，唯一的办法还是乘 `nums[i-1]`**。

第二趟也补不了这个账：`suffix` 攒的是 j 右边的元素，跟 j 自己无关，两边各管各的一侧。

真正要记的不是「除法不行」，是**改的那一行改掉的是 `ans[i]` 的定义**。定义、初值 `ans[0] = 1`、递推式是一套三件——动一个，另外两个必须回头核一遍。

**这条会迁移**：所有 prefix 型的题都有同一个岔路口——`prefix[i]` 到底含不含 `i` 自己。前缀和里它决定区间查询写 `prefix[r+1] - prefix[l]` 还是 `prefix[r] - prefix[l-1]`，是同一件事的加法版，**而那边没有「禁除法」这道门挡着**。先钉死定义，再写递推。

### 沉淀

- **前后缀分解**：「除自己以外的全部聚合」这类题，标准拆法都是「左边的聚合 ⊕ 右边的聚合」，两趟扫描。乘法如此，加法、最大值同理。
- **跨 iteration 的累积量 declare 在 loop 外**：声明位置决定生命周期。写在里面的症状是「累积值永远停在初值」或「靠它的 condition 永不触发」——和 LC80 的 `count`、LC380 的 field 同一条。
- **两个因子必须归同一个下标**：`ans[j]` 配 `suffix`，都是 j 自己的。合并那一行读到 `j+1` 就该警觉。
- **动了递推式就是动了定义**（见引申二）：改完先重念定义，再核初值和下游。
- **原地覆盖时，邻居已经不是原来那个量了**（见一刷的自检信号）。
- **边界值取的是运算的单位元**：乘法 1、加法 0。默认值 0 对乘法是毒药。

### Interview pitch (练口述)

> "Each answer is the product of everything to the left times everything to the right, so I compute it in two passes. The first pass fills the output array with prefix products — ans[i] is the product of nums[0..i-1], with ans[0] set to 1 since nothing is to its left. The second pass walks backwards with a single running suffix variable, multiplying it into each slot in place. That's O(n) time and O(1) extra space beyond the output. Two details matter: the suffix variable lives outside the loop because it has to accumulate across iterations, and both factors have to belong to the same index — the prefix already sitting in ans[j], and the suffix I've accumulated for j."
