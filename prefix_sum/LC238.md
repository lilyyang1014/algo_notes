## 238. Product of Array Except Self

Date: 8/15/2026
Difficulty: Medium
Tags: array, prefix product, 前后缀

### 一刷 (8/15/2026) ⚠️卡推导 结构建对，合并那一行下标归属滑掉

```java
int[] ans = new int[nums.length];
ans[0] = 1;                                  // ✅ 理由写对了：下标 0 左边没有元素，前缀积为 1
for(int i = 1; i < ans.length; i++){
    ans[i] = ans[i-1] * nums[i-1];           // ✅ 前缀积正确
}
int temp = 1;
for(int j = nums.length-2; j >= 0; j--){
    temp *= ans[j+1];                        // ❌① 应为 nums[j+1]
    ans[j] = ans[j+1] * temp;                // ❌② 应为 ans[j]
}
```

**整体结构是对的**：前缀积正向铺进 `ans`、后缀积用单变量反向累乘、原地合并、`ans[n-1]` 不动（它的前缀积已是全部元素、右边没东西，本身就是答案）。**两个错都在合并那一行。**

**❌①（手误）**：`temp` 攒的是**右边原始元素**的连乘，该乘 `nums[j+1]`。`ans[j+1]` 是已被加工过的前缀积，不是元素。口答确认「写的时候脑子里 `temp` 就是后缀积」——量的定义立住了，抓错了数组名。

**❌②（真正卡住的地方）**：答案公式是

```
ans[j] = (j 左边所有元素的积) × (j 右边所有元素的积)
```

两个因子**都归 j**：`ans[j]` 是 j 自己的前缀积，`temp` 是 j 自己的后缀积 → `ans[j] * temp`。写 `ans[j+1]` 取的是**右邻居的**前缀积，它比 `ans[j]` 多乘了一个 `nums[j]`——恰好把「除自身以外」要排除掉的那个自己又乘了回来。

**❌② 还有第二层**：这个 loop 是**原地覆盖**的。`ans[j+1]` 在上一轮就已经被写成最终答案了，读它的时候它早就不是前缀积。**一旦开始原地写，右边的邻居就不再是你以为的那个量。**

**dry run** `[1,2,3,4]`，前缀积 `[1,1,2,6]`，答案 `[24,12,8,6]`（①已修、②未修的版本）：

| j   | temp            | `ans[j+1] * temp`                     | 正确 `ans[j] * temp` |
| --- | --------------- | ------------------------------------- | -------------------- |
| 2   | ×nums[3]=4 → 4  | ans[3]=6 → **24** ❌                  | ans[2]=2 → **8** ✅  |
| 1   | ×nums[2]=3 → 12 | ans[2]=**24**（已被覆盖）→ **288** ❌ | ans[1]=1 → **12** ✅ |
| 0   | ×nums[1]=2 → 24 | ans[1]=**288** → **6912** ❌          | ans[0]=1 → **24** ✅ |

j=2 那轮只差一格；到 j=1，读到的 `ans[2]` 已是上一轮写进去的答案，错误被乘法一路放大。

> **自检信号**：**原地覆盖的循环里，凡是读邻居的那一行都要停一下**——问「这一格现在存的还是我以为的那个量吗？」。安全的写法是只读自己（`ans[j]`），要读邻居就说得出它此刻处于覆盖前还是覆盖后。

**归族**：同日第二次。早上 704 是 `left`（下标）与 `nums[left]`（值）被压成一个词，这次是 `nums[j+1]`（元素）与 `ans[j+1]`（前缀积）被压成一个词。**同一道缝：两个量共用一个下标位置，写那一行时只抓住了下标，没抓住它属于哪个数组、代表哪个量。**（274 ①③、45 四刷、367、704 同族）

**自测点**：为什么后缀积必须用 `temp` 这个单变量、而不能开第二个数组存后缀积再合并？（能，但代价是什么；以及若真开了第二个数组，`ans[j+1]` 这个写法会不会就变对了）

### 核心思路（一句话）

**每个位置的答案 = 它的前缀积 × 它的后缀积。** 先正向一趟把前缀积铺进 `ans`，再反向一趟用单变量攒后缀积、就地乘上去——两趟 O(n)，除输出外不占额外空间。

### 代码

```java
class Solution {
    public int[] productExceptSelf(int[] nums) {
        int[] ans = new int[nums.length];

        ans[0] = 1;                              // 下标 0 左边没有元素，前缀积 = 1
        for (int i = 1; i < nums.length; i++) {
            ans[i] = ans[i-1] * nums[i-1];       // ans[i] = nums[0..i-1] 的积
        }

        int suffix = 1;                          // 下标 n-1 右边没有元素，后缀积 = 1
        for (int j = nums.length - 2; j >= 0; j--) {
            suffix *= nums[j+1];                 // 攒的是元素
            ans[j] = ans[j] * suffix;            // 自己的前缀 × 自己的后缀
        }
        return ans;
    }
}
```

`ans[n-1]` 不进第二个 loop：它的后缀积是 1，第一趟的结果已经是答案。

**两个边界值都是 1，不是 0**：乘法的单位元是 1。`new int[n]` 默认填 0，所以 `ans[0]` 必须手动置 1，否则整个前缀积链全是 0。

### 复杂度分析

**Time: O(n)**：两趟遍历。
**Space: O(1)**（不计输出数组）：只多一个 `suffix`。

对比：开两个数组分别存前缀积和后缀积再合并，思路更直白但要 O(n) 额外空间；朴素做法对每个位置重新乘一遍其余元素是 O(n²)。题目通常要求不用除法——即便允许，除法遇到 0 会崩（数组含一个 0 时只有那一格非零，含两个 0 时全为 0），得单独统计零的个数，反而更麻烦。

### 沉淀

- **前后缀分解**：形如「除自己以外的全部聚合」的题，标准拆法都是 `左边的聚合 ⊕ 右边的聚合`，两趟扫描。乘法如此，加法、最大值同理。
- **两个因子必须归同一个下标**：`ans[j]` 配 `suffix`，都是 j 自己的。合并那一行读到 `j+1` 就该警觉。
- **原地覆盖时，邻居不再是原来的量**（见上方自检信号）。想避开这个坑，就把后缀积存成第二个数组——代价是 O(n) 空间。
- **边界值取的是运算的单位元**：乘法 1、加法 0。默认值 0 对乘法是毒药。

### Interview pitch (练口述)

> "Each answer is the product of everything to the left times everything to the right, so I compute it in two passes. The first pass fills the output array with prefix products — ans[i] is the product of nums[0..i-1], with ans[0] set to 1 since nothing is to its left. The second pass walks backwards with a single running suffix variable, multiplying it into each slot in place. That's O(n) time and O(1) extra space beyond the output. The key detail is that both factors have to belong to the same index — the prefix already sitting in ans[j], and the suffix I've accumulated for j — and since I'm overwriting in place, I can only read ans[j] itself, never a neighbour."
